## §2 E-2 · 节点返回值（三形态）

| 形态 | 语法 | 归一结果 | 失败信号（形态非法时） |
|---|---|---|---|
| **部分状态** | `dict` | 待写入 = 该 dict 的 items | 非 `dict` ⇒ `TypeError`（B7F1 **V-4** 同族） |
| **单条命令** | `Command` | 待写入 = `command.update`（若非 `None`）；跳转目标 = `command.goto` | `update` 既非 `dict` 又非 **2-tuples** ⇒ `TypeError`（⚠️ **2026-11-12 上游对齐 P3**：**2-tuples 是上游同款** · 上游 `types.py:836-840`） |
| **命令列表** | `list[Command \| dict]` | 待写入 = **按列表顺序**把各元素归入同一份；跳转目标 = 各条命令的 `goto` 的**并集**（各自成边） | 元素非 `Command` / `dict` ⇒ `TypeError`；⚠️ **空列表 ⇒ 失败**（**上游同款** · 2026-11-12 P3） |
| **无写入** | `None` | **零写入** | **合法**（⚠️ **上游同款** · 2026-11-12 P3 · 上游 `state.py:1459-1460`） |

**归一后的统一形状**（内部中间产物 · **不进公开面**）：

```text
NormalizedResult = {
    "writes": dict[str, tuple[Any, ...]],   # 待写入（每 key 一个**值序列** · 键序 = 归一顺序）
    "gotos": tuple[str, ...],               # 跳转目标（去重后保序）
}
```

⚠️ **`writes` MUST 是「每 key 一个**值序列**」**（**不是** `dict[str, Any]`）——
**理由（2026-11-11 分析轮 · 发起者拍板 · Q1）**：命令列表里**两条命令写同一个 key** 时，
`dict[str, Any]` 会让**后者覆盖前者** ⇒ 与 FR-004 / 裁定 15 的「**MUST NOT** 让后一条命令覆盖前一条」
「按**列表顺序**逐条归约 ⇒ 与上游 `updates.extend(...)` 顺序**逐字一致**」**直接冲突**
⇒ **SC-021① 不可实现**。
⇒ 改为**值序列**后：① 列表内同 key 的多个值**按列表顺序**依次入列 ⇒ 归约型通道按该顺序归约
（与上游**逐字一致**）；② **与 B7F1 的 `node_writes`（节点 → 通道 key → **值序列**）天然同构**
⇒ 可**直接**交给既有的 `_collect_writes` / `_merge_writes` ⇒ **合并路径零改动**、**FR / SC 零变动**。
⇒ 单命令 / 单 `dict` 形态 ⇒ 每 key 一个**单元素**序列（与 B7F1 的单值写入**同形**）。

⚠️ **归一是唯一的新增概念**：三种形态在**归一之后**只有一种内部表示 ⇒
「未知 key 报错」「归约器语义」「批量合并」「原子性」**全部复用 B7F1 的同一条路径**（裁定 4）。

## §3 E-5 / E-6 · 动态边表（落在调度状态上）

### 3.1 字段（**名字由本 plan 冻结** · 登记项 **R-3**）

| 项 | 值 | 理由 |
|---|---|---|
| 宿主 | `SchedulerState`（B7F1 已冻结 · **构造签名 `SchedulerState()` 逐字不变**） | 裁定 12 · 发起者拍板（澄清轮第 2 次 Q5） |
| 字段名 | **`dynamic_edges`** | 与既有字段风格一致（`versions_seen` / `step` / `channel_versions` / `node_versions` 皆为「名词 + 限定」）；⚠️ **它不是跨 feature 的公开契约**（L2 内部状态）⇒ 名字可由 plan 冻结，不进兼容矩阵 |
| 类型 | `dict[str, tuple[str, ...]]` | 源节点名 → 跳转目标序列（**保序** · 去重） |
| 缺省 | **工厂语义**（`field(default_factory=dict)`） | ⚠️ **MUST NOT** 用字面可变默认值（dataclass 会抛 `ValueError: mutable default` · B7F1 裁定 36 的同款实测） |
| 可变性 | **可变**（`SchedulerState` 本身就是可变 dataclass） | 运行期状态 |

### 3.2 生命周期（**MUST** 的状态机）

```text
节点 X 执行
   │
   ├─ 归一返回值 → 待写入 + 跳转目标集 G
   │
   └─ 动态边表[X] := G          ← ★ 每次执行**整体替换**（不是并集！）
        │
        └─ 下一轮的触发判定：目标 Y 的触发源集合加入 ("e", X)
             （仅当 dynamic_edges[X] 含 Y 时）
```

| 规则 | 内容 | 落点 |
|---|---|---|
| **整体替换** | X 每执行一次 ⇒ `dynamic_edges[X]` **被整体替换**为本次的跳转目标集（含**空集**）⇒ X 再次执行且**不**给 `goto` ⇒ 旧目标**被清空** | FR-009 · 裁定 2 |
| **只影响下一轮** | 动态边在**本轮触发判定之后**才产生 ⇒ 本轮**不**产生新的触发 ⇒ 目标**下一轮**才被触发 | FR-002 · 裁定 1 |
| **边的同款待遇** | 目标节点**无「有值」门槛**（边触发源只比版本号）⇒ 即使它订阅的通道都没值也**照跑** | FR-002 · 裁定 17 · research **D-09** |
| **静态边并行** | 动态边与静态边**叠加**（目标**都**被触发） | FR-008 · 裁定 3 · research **D-02** |
| **两个空间分离** | 动态边产生的触发源标识 = `("e", X)`（**边空间**）⇒ 与通道触发源 `("c", key)` **不混淆**（B7F1 裁定 3） | FR-002 · 裁定 1 |

## §4 状态机（一个 super-step 内 `Command` 的位置）

```text
① 触发判定  ──► ② 任务准备 ──► ③ 任务执行 ──► ④ 写入收集 ──► ⑤ 写入合并
   (B7F1)        (B7F1)         ★ B9F1 插入      ★ B9F1 插入      (B7F1 · 不变)
                                   │                │
                                   │ 节点返回值 ──► 归一（E-2 → 内部形状）
                                   │                │  ├─ 待写入（归 E-3 · 归源节点）
                                   │                │  └─ 跳转目标（归 E-5）
                                   │                │
                                   │                └─ dynamic_edges[X] := 跳转目标集
                                   │
                                   └─ 执行版本 +1（不变 · B7F1 的边触发源版本）
```

⚠️ **B7F1 的五个阶段顺序**与**四阶段产物**（`SuperStepResult` 的四个字段）**一字不改**
⇒ 本 feature 只在 ③④ 之间**插入**一个「归一」子步骤 ⇒ **阶段划分不变**（FR-001 的五阶段形态保持）。

## §5 E-3 · 待写入的归属与合并

| 规则 | 内容 | 落点 |
|---|---|---|
| **归属 = 源节点** | `Command.update`（及命令列表里每条命令）的写入归到**返回该命令的那个节点**名下 | 裁定 16 · SC-022 |
| **一条合并路径** | 归一后的待写入交给**同一个**合并实现 ⇒ 未知 key 校验 / 批量归约 / 覆盖型冲突 / 原子性 **全部复用** | 裁定 4 · FR-004 |
| **列表顺序 = 合并顺序** | 命令列表的写入按**列表顺序**归入同一份 ⇒ 归约型通道按该顺序归约（与上游 `_get_updates` 的 `updates.extend(...)` 顺序**逐字一致**） | 裁定 15 · research **D-08** |
| **未知 key** | 与普通返回值**同款** ⇒ `InvalidUpdateError`（L1 已冻结 · `invalid_keys` 列**全部**未知 key） | FR-004 · SC-004 |
| **原子性** | `Command.update` 引发的错误（未知 key · 覆盖型多写 · 归约器抛错）⇒ **整轮**不合并、通道值保持轮初、**版本不推进** | FR-012 · SC-013 |

## §6 校验规则（V-9…V-14 · 本 feature 新增 · 与 B7F1 的 V-1…V-8 同族）

| # | 场景 | 失败信号 | 落点 |
|---|---|---|---|
| **V-9** | 节点返回值**既不是 `dict`、也不是 `Command`、也不是 `list`、也不是 `None`**（**含空列表**） | 内置 **`TypeError`**（与 B7F1 **V-4** 同族） | FR-001 |
| **V-10** | 命令列表的**元素类型非法**（非 `Command` / 非 `dict`） | 内置 **`TypeError`** | FR-001 |
| **V-11** | `Command.update` **既不是 `dict`** **又不是** list/tuple of 2-tuples | 内置 **`TypeError`** | FR-010 |
| **V-12** | `Command.goto` 的**形态非法**（非 `str` / 序列含非 `str`） | 内置 **`TypeError`** | FR-007 |
| **V-13** | `Command.goto` 的**目标不在节点表**（或为空串 / `START`） | 内置 **`ValueError`**（点名目标） | FR-007 · 裁定 8 |
| **V-14** | `Command.goto == Command.PARENT` | 内置 **`NotImplementedError`**（点名「子图属 v2 能力」） | FR-005 · 裁定 7 |

⚠️ **异常族的刻意偏离（登记项 R-4）**：B7F1 的「一个 feature 只用**两种**内置异常
（`ValueError` / `TypeError`）」⇒ 本 feature 引入**第三种**（`NotImplementedError`）⇒
理由 = 「**合法常量但能力未实现**」与「**值写错了**」是**两种**语义（澄清轮第 2 次 Q2 · 发起者拍板）
+ 仓库已有 `NotImplementedError` 的既有用法（`interrupt()` / `StateGraph` 未接线）⇒ **刻意偏离 · 已登记**。
⚠️ **V-13 与 V-14 MUST NOT 合并**：前者是「**写错了**」· 后者是「**合法但没实现**」⇒ 失败信号**可区分**（SC-005）。

## §7 不变量（I-1…I-14 · 可自动判定）

| # | 不变量 | 判定方式 |
|---|---|---|
| **I-1** | 节点返回值**只有三种合法形态**（`dict` / `Command` / `list[Command \| dict]`） | 形态穷举 + 非法形态 ⇒ `TypeError` |
| **I-2** | 三种形态**归一后共用同一条合并路径** | 同一 key 分别以三种写法写入 ⇒ 合并结果**逐项相等** |
| **I-3** | `Command.update` 的写入**归源节点** | `node_writes` 的 key 集合含源节点名 |
| **I-4** | 命令列表的写入**按列表顺序**合并 | 归约型通道的结果与「按序逐条写入」**逐元素相等** |
| **I-5** | 列表里**每条**命令的 `goto` 各自成边 | 全部目标**都**在下一轮被执行 |
| **I-6** | `dynamic_edges[X]` 每次执行**整体替换** | X 再次执行且无 `goto` ⇒ 旧目标**不再**被触发 |
| **I-7** | `goto` 目标**下一轮**才被触发 | 同一轮内目标**未**被执行 |
| **I-8** | `goto` 目标**无「有值」门槛** | 目标订阅的通道都没值 ⇒ 仍被执行（入参为空 `dict`） |
| **I-9** | `goto` 目标的入参 = **正常稀疏读**的结果 | 与 `read_channels(子映射)` **逐字相等**（B7F1 契约 **I-2**） |
| **I-10** | 目标**读得到**源节点本次 `update` 的内容 | 目标入参含该内容 |
| **I-11** | 动态边与静态边**叠加** | 静态边目标与 `goto` 目标**都**被触发 |
| **I-12** | `END` **不产生跳转**、**不终止整张图** | 静态边目标仍被执行；更新照常生效 |
| **I-13** | 空槽位 / 空列表 = **明确无操作** | 零写入 + 零跳转 + 节点仍计入执行记录 |
| **I-14** | `SuperStepResult` 的字段数 == **4** | `fields()` 长度断言（**MUST NOT** 为记录跳转而扩字段） |

## §8 规模与性能口径

| 项 | 口径 |
|---|---|
| 归一开销 | **O(返回值规模)**（一次遍历 + 一次 dict 合并） |
| 动态边表的写入 | **O(目标数)** / 每次节点执行 |
| 触发判定的额外成本 | **O(节点数 × 动态边数)**（每个目标节点多扫一眼动态边表）⇒ 仍是**单遍** |
| 空间 | 动态边表 ≤ **O(节点数 × 目标数)**；随调度状态持有 ⇒ 调用方持有 ⇒ 跨轮存活 |
| ⚠️ **MUST NOT** | 用墙钟耗时做断言（CI 假红）⇒ **结构口径**（执行次数 / 调用次数 / 逐元素相等 / 集合相等 / 逐字相等） |
