## 2. 入口（**名字与既有参数逐字不变** · 增一个 keyword-only 参数）

| 项 | 契约 |
|---|---|
| 入口 1（单轮） | `run_super_step(spec: GraphSpec, state: SchedulerState, *, max_concurrency: int \| None = None) -> SuperStepResult` |
| 入口 2（多轮） | `run_super_steps(spec: GraphSpec, state: SchedulerState \| None = None, *, max_steps: int = 10007, max_concurrency: int \| None = None) -> SuperStepResult` |
| **新增参数** | `max_concurrency` —— **keyword-only** · 缺省 **None**（⇒ **缺省上限 `min(32, cpu+4)`** · **上游同款**）· **上游同名同义**（`RunnableConfig["max_concurrency"]`） |
| **并发度** | `min(本轮触发任务数, max_concurrency or min(32, cpu+4))`；`max_concurrency=1` ⇒ **逐个执行**（**串行基线**） |

| ⚠️ **校验时机** | **入口即失败** ⇒ 即**一进门就报错** ⇒ **哪怕本轮没有任何节点要跑**也 MUST 报错（**上游同款** · 标准库线程池在**构造时**校验 `max_workers`）⇒ ⇒ 「零节点的一轮 MUST NOT 创建任何线程」**与之不冲突**（**不建池** ≠ **不校验参数**） |

| **串行模式的语义** | 与**并发前的既有行为逐字一致**（**节点名序** · 逐个执行 · 首个失败者即抛出）⇒ 它是「并发前的黄金基线」 |

## 3. 一个 super-step 的**七个阶段**（**顺序固定** · ③′ 为本 feature 细分）

| 阶段 | 内容 | 本 feature 的变化 |
|---|---|---|
| ① 触发判定 | 枚举触发源 · 比版本号 | **零改动** ⇒ 顺序 = **节点名序**（**上游同款** · `_algo.py:482`） |
| ② 任务准备 | 构造入参（`read_channels(子映射)` · 子映射按**通道映射顺序**）· 消费版本 | **零改动** ⇒ 入参在执行前**固定**（FR-011） |
| ③ **并发执行** | **全部**被触发的任务**并发**跑（线程池）⇒ 每个任务产出一个**结果槽** | ★ **新增并发** |
| ③′ **判定与落回** | 判定「有异常 / 有中断 / 全成功」⇒ 按**节点名序**落回（**成功节点落回** · **被中断节点不落回**）⇒ ⚠️ **本阶段不抛任何异常** | ★ **新增** |
| ④ 写入收集 | 待写入**按节点分组** | **零改动** |
| ⑤ 写入合并 | 每通道**一次** `Channel.update(values)` · 快照 + 回滚 · 步末清空 | **零改动**（⚠️ 出错轮**不进入**本阶段） |
| ⑥ **收尾** | 有真实异常 ⇒ **抛出**（原对象）· 有中断 ⇒ **合并抛出**一个 `GraphInterrupt` | ★ **新增** |

> ⚠️ **本契约 §3 是阶段模型的**唯一权威**（**2026-11-13 拍板**）⇒ `data-model.md` §4 / §2.3 与
> `tasks.md` **T014** MUST 与本表**逐字一致**。
> ⚠️ **既有五阶段（① ② ③ ④ ⑤）的语义与顺序不变** ⇒ B7F1 契约 §4 的**阶段编号**仍成立
> （本 feature 只把阶段 ③ 细分为 ③ / ③′，并追加阶段 ⑥）⇒ **MUST NOT** 重排。
> ⚠️ **阶段 ⑥ 的顺序**：**先合并、后抛中断** ⇒ 用户接住异常后从调度状态读到的**已是合并后**的值。
> ⚠️ **「抛出」只发生在阶段 ⑥**（真实异常与中断**都**在 ⑥ 抛）⇒ 阶段 ③′ 只做**判定与落回**。

## 4. 并发执行（**线程**）

| 项 | 契约 |
|---|---|
| 机制 | **标准库线程池**（`concurrent.futures.ThreadPoolExecutor`）· MUST **NOT** 引入 async / 事件循环 |
| 并发度 | `min(本轮触发任务数, max_concurrency or min(32, cpu+4))` ⇒ 缺省**有上限**（**上游同款**）· 超出者**排队** |
| 零节点 | MUST **NOT** 创建任何线程 ⇒ MUST **NOT** 建池 |
| 线程池生命周期 | **每轮新建 + 每轮关闭** ⇒ 本轮结束后**零悬挂线程**（**上游同款** · `_executor.py:93-119`） |
| 线程名 | 前缀 `freegraph-node`（便于诊断与线程计数断言） |
| 执行期共享写 | **零** ⇒ 工作线程**只**产出**结果槽** ⇒ MUST **NOT** 在执行期改写 `SchedulerState` |
| 执行期共享读 | 只读 `spec`（节点表 / 通道表）⇒ MUST **NOT** 在执行期改写它们 |
| 提交顺序 | **节点名序** ⇒ 「首个异常」的选取 = **扫结果槽的第一个** |
| ⚠️ **失败处置** | 首个真实异常出现 ⇒ **取消「排队未启动」**的任务（`Future.cancel()` → `True`）⇒ **运行中**的任务**不中断**、但**被等待**（**上游同款** · `_runner.py:679-680`）⇒ **实测**（E-2d / E-2f / E-2g）⇒ ⇒ **MUST NOT** 取消**运行中**的任务 |
| ⚠️ **判据分两层** | **端到端**只比「本轮最后实际被启动了哪些节点」⇒ MUST **NOT** 把「排队者一定没跑」写成硬判据（**上游端到端 15/15 次排队者照跑** ⇒ 上游自己也达不到 ⇒ 会偶发红）；**机制层**另有一条**能确定复现**的夹具断言 `cancel()` → `True` |
| `BaseException` | `KeyboardInterrupt` / `SystemExit` **不**被捕获 ⇒ 直接中止整轮（**上游同款** · `_runner.py` 的 `except Exception`） |

## 5. 判定与落回（**节点名序**）

| 情形 | 判定 | 落回 | 后续 |
|---|---|---|---|
| **全部成功** | 无异常、无中断 | 成功节点：`node_versions` **+1** · `dynamic_edges` = 本次跳转目标（**整体替换** · 含空集） | 正常进入下一轮 |
| ⚠️ **有真实异常** | 取**节点名序最靠前**的失败节点 | **不**落回 `node_versions` / `dynamic_edges`（**整轮原子**）· **不合并任何写入**（**含跑成功的节点** · **X-3**） | **抛出**该异常（原对象）· **不进入下一轮** · 取消排队未启动者 |
| **有中断（无异常）** | 中断节点视为**未完成** | 成功节点：同「全部成功」；中断节点：**不**落回版本 / 跳转目标 · **不**产出写入 | **先合并、后抛**合并异常 · **不进入下一轮**（暂停） |
| **异常 + 中断同现** | **异常优先**（**上游同款**） | 同「有真实异常」⇒ ⇒ 中断元组**随之丢弃** | **抛出**真实异常 |

> ⚠️ **落回顺序恒为节点名序** ⇒ 调度状态在并发下的**演化**完全可复现。
> ⚠️ **中断节点的版本不推进** ⇒ 它**不会**被自己的边再次触发（**恢复**时它会被**重跑** · **上游同款**：
> `snapshot.next` **仍保留**被中断的节点 ⇒ 归 **B10F1**）。
> ⚠️ **出错轮**与**中断轮**的分界 MUST **逐字可判**：**出错轮一个都不合并** · **中断轮合并（别的节点）**。

## 6. 错误传播（**原样** · **确定性**）

| 项 | 契约 |
|---|---|
| 抛出对象 | **节点名序最靠前**的失败节点所抛的**原对象**（`raise exc` ⇒ **同一对象**） |
| 类型 / 消息 | **逐字**不变 ⇒ MUST **NOT** 包装成别的异常类型 |
| 对象 identity | `caught is raised_by_node` ⇒ **True**（B7F1 契约 **I-15** 不破） |
| 其余失败 | MUST **NOT** 被静默丢弃 ⇒ 以**异常附注**（`BaseException.add_note`）记录在抛出的那个异常上 |
| 附注的约束 | MUST **NOT** 改变异常的**类型 / 消息 / 对象 identity** ⇒ 调用方 `except` 到的仍是他自己认识的那个异常 |
| ⚠️ **附注的内容** | **固定格式**且 MUST 同时含**节点名** · **异常类型名** · **异常消息**三样 ⇒ 形如 `其它并发失败 · 节点 <节点名>：<异常类型名>: <异常消息>` ⇒ ⇒ 判据可自动断言 ⇒ MUST **NOT** 只写其中一两样 |
| ⚠️ **已取消任务** | 其异常 MUST **NOT** 被收集（未发生 ⇒ 无异常） |
| ⚠️ **其余任务** | **排队未启动**者**被取消** · **运行中**者**不中断**、但**被等待**（**上游同款**） |
| 停止 | 抛出 ⇒ **不进入下一轮**（不带着坏状态继续跑） |
| 整轮原子 | 该轮产生的**全部**待写入**不合并**（**含跑成功的节点**）；通道值 == **轮初**；通道**写入版本不推进**；**节点执行版本不推进**；**跳转目标不落回** |

> ⚠️ **「首个」的确定性**：MUST 取「**节点名序**最靠前」者 ⇒ MUST **NOT** 依赖「谁先跑完」
> ⇒ ⚠️ **比上游更严**（上游从 `done` **集合** `pop()` ⇒ **竞态** · **实测** 50 次 ⇒ **26 / 24**）
> ⇒ 偏离登记 **X-1** ⇒ MUST **如实标注**。

## 7. `GraphInterrupt` 的**合并抛出**（**C17**）

| 项 | 契约 |
|---|---|
| 收集范围 | 一轮内**全部**节点抛出的 `GraphInterrupt`（MUST **NOT** 只取第一个） |
| 元素 | 该异常 **`args[0]`（≡ `payload`）的**元素**（`Interrupt` 对象 · **原样** · 不包装）⇒ MUST 带 `.value` 与 `.id`（**C17** · L1 `errors.py:110`）⇒ ⚠️ MUST **NOT** 是 `payload` **本身**（`payload` 是**元组** ⇒ 直接塞进去会得到**嵌套元组** ⇒ 元素**没有** `.value` / `.id` ⇒ **SC-010 不可判定**） |
| ⚠️ **用户写法** | MUST 是 `raise GraphInterrupt((Interrupt(value=…, id=…),))` —— **1-元组**（上游 `langgraph/types.py:967` **同款**）⇒ ⚠️ 传**单个** `Interrupt` 会抛 `TypeError`（L1 的 `tuple(interrupts)` 不可迭代 · **实测**）⇒ **不得**写成「`raise GraphInterrupt(payload)`（单个对象）」 |
| 内核的职责 | **只收集 + 合并抛出** ⇒ MUST **NOT** 生成、改写或校验载荷 ⇒ 「**自动生成 `.id`**」归 **B10F1**（上游同款） |
| ⚠️ **载荷形态** | **元组**（`tuple[Interrupt, ...]`）· **上游同款**（`_runner.py:690` · `errors.py:102-107`）⇒ ⇒ **MUST NOT** 落进任何**字段** |
| ⚠️ **落点** | **以抛出的方式**交给调用方（**一个** `GraphInterrupt`）⇒ **MUST NOT** 落 `SchedulerState` 的字段 ⇒ ⇒ **`SchedulerState()` 构造签名逐字不变** ⇒ **零新增字段** |
| ⚠️ **顺序** | **节点名序** ⇒ ⚠️ **比上游更严**（上游从 `done` **集合** `pop()` ⇒ **竞态** · **实测** 200 次 ⇒ **199 / 1**）⇒ 偏离登记 **X-7** |
| ⚠️ **中断轮不产出结果对象** | 入口在抛出该异常时 MUST **不**返回 `SuperStepResult`（四字段一个都不给）⇒ 调用方 MUST 从**自己持有的调度状态**读通道值（合并**已经**发生 ⇒ 状态**没丢**）⇒ ⇒ 「把异常**转成**结果键 `__interrupt__`」的义务归 **B10F1**（下游 **D-1**） |
| 中断节点自身 | 视为**未完成** ⇒ **无写入** · **不**推进执行版本 · **不**登记跳转目标 |
| 同轮其它节点 | 写入**照常合并**（中断**不是**「出错」）⇒ ⇒ 与「出错轮**一个都不合并**」**分界清晰** |
| 中断之后 | **不进入下一轮**（暂停等待恢复 · 归 **B10F1**） |
| 制造入口 | 本 feature **只交付收集** ⇒ `interrupt()` **不**接线（归 **B10F1**）⇒ 用户**直接 `raise GraphInterrupt(payload)`** 即可触发 |
| 结果键 | **`__interrupt__` 键不在本 feature**（归 **B10F1** · 下游承接 **D-1** · **T-9**） |

## 8. 合并语义（**零改动** · 与串行逐项一致）

| 项 | 契约 |
|---|---|
| 合并路径 | B7F1 的**批量**路径（每通道**一次** `Channel.update(values)`）· MUST **NOT** 为并发另写一条 |
| 合并顺序 | **节点名序**（`_group_writes` 按**节点名序**遍历）⇒ **非交换归约器**的结果**可复现** |
| 归一 | 节点返回值的三形态（`dict` / `Command` / `list[Command \| dict]`）**先归一**为同一份待写入 ⇒ 合并器**只见一种输入** |
| `Command.update` | 与普通返回值**同一条**路径（未知 key ⇒ `InvalidUpdateError`） |
| 冲突 | 覆盖型通道同轮多写 ⇒ `InvalidChannelUpdateError`（**V-6** · 合并阶段判定 ⇒ 并发不改变它） |
| 并发 vs 串行 | 同一份规格在两种模式下的**最终状态**与**待写入序列** MUST **逐项相等** |

## 9. 报告口径（`SuperStepResult` · **四字段冻结面零改动**）

| 字段 | 契约 |
|---|---|
| `state` | 合并后的**稀疏**通道值字典（**不变**）⇒ ⚠️ MUST **NOT** 塞入 `__interrupt__`（形态污染 · 裁定 25） |
| `executed` | 本轮**被启动过**的节点名 · **节点名序**（**含**被中断的节点 · **上游同款**）· **不含**被取消的节点（从未被启动）· 字段数**仍为 4** |
| `node_writes` | 按节点分组的待写入（**不变**）⇒ **被中断 / 失败**的节点**不**在其中（它们没有写入） |
| `steps` | 实际迭代轮数（**含**空轮 · **不变**）⇒ ⚠️ **中断轮不产出结果对象** ⇒ 「挂起时 `steps` 如实计」的**载体**归 **B10F1**（**T-5**） |

> ⚠️ **语义收紧（登记）**：既有措辞是「被执行的节点名（**按执行顺序**）」⇒ 并发下「执行顺序」不确定
> ⇒ 本契约把语义**收紧**为「**被启动过**的节点 · **节点名序**」⇒ 结果**可复现**
> ⇒ MUST **回溯修订** B7F1 契约 §5.3 的措辞（plan 登记项 **PR-7** / **T-1**）。
> ⚠️ **上游同款**：上游把「谁被启动」（任务清单 · **含**被中断的节点）/「谁写了东西」（写入通道 · 不含）
> /「谁中断了」（`__interrupt__` 单独一个键）分成**三个独立通道** ⇒ freegraph **同款**。
> ⚠️ **为什么**不新增第 5 个字段（**裁定 25** · 依宪法 **v1.10.0 原则 XII** 重判）：
> ① **层次对应优先于容器对应** —— 上游的「结果」是**状态字典** ⇒ `__interrupt__` 是**字典的 key**
> ⇒ freegraph 的对应物是**门面返回的 dict** ⇒ ⇒ 给「**单轮结果对象**」加字段是**错位搬运**；
> ② L2 照上游**抛** ⇒ **抛了就无结果对象** ⇒ 新增字段**永远是空元组** ⇒ **死字段**；
> ③ **结构化载体另有其人** —— L1 的 **`StateSnapshot.interrupts`**（**已存在** · **上游同款**）⇒
> **零新增 · 零破冻结面** ⇒ ⇒ **四字段零改动**。

## 10. 失败信号汇总（**V-15…V-19**）

| # | 触发条件 | 信号 | 附加约束 |
|---|---|---|---|
| **V-15** | 一轮内多个节点失败 | **原对象**原样抛出（**节点名序**最靠前者）+ 其余以**附注**记录（**三样齐全**） | 不包装 · 不静默丢弃 · 不依赖完成时刻 |
| **V-16** | 节点抛出 `GraphInterrupt` | **不是失败**（该节点未完成）+ 载荷被**原样**收集 ⇒ **合并抛出**一个 | 不触发整轮不合并 · 不生成 / 改写 / 校验载荷 |
| **V-17** | 异常与中断同现 | 抛**真实异常**；中断元组**随之丢弃** | 中断不掩盖失败 · **不**自创留痕形态 |
| **V-18** | `max_concurrency` 非法 | `TypeError`（类型不符）/ `ValueError`（`< 1`）· 均点名该参数 · **入口即失败** | 显式失败 · **哪怕本轮无节点也报** |
| **V-19** | 节点返回非法类型 | 内置 `TypeError`（B7F1 **V-9** 同款）· **原样**传播 | **与并发无关** ⇒ 零改动 |

> **零新增异常类型** ⇒ L1 的 20 符号面零改动（G7 恒绿 · **清单驱动** ⇒ 判据零改动）。
> （⚠️ **2026-11-13 订正 · X1 / R-10**：L1 基线由 **18** 改为 **20**）

## 11. 不变量（**逐条可断言** · I-1…I-17）

| # | 不变量 | 判定方式 |
|---|---|---|
| **I-1** | 同轮两个节点**重叠执行** | 屏障夹具放行 / 时间窗重叠 > 0 |
| **I-2** | 同轮两个节点**各执行恰好 1 次** | 副作用计数 == 1 |
| **I-3** | 首个异常：**类型 / 消息 / 对象 identity** 逐字一致 · 由「**节点名序**最靠前」者决定 | `type` / `str` / `is` + 重复 ≥ 3 次 |
| **I-4** | 其余并发失败**均被附注记录**（丢弃 == 0）且附注**含三样** | `__notes__` 逐条断言 |
| **I-5** | 异常后**后续 super-step 不执行** | 执行计数 == 0 |
| **I-6** | 并发与串行（`max_concurrency=1`）：**最终状态 + 待写入序列逐项相等** | 双模式对照 |
| **I-7** | 重复运行 ≥ 3 次 ⇒ 状态与执行序列逐项相等 | 重复对照 |
| **I-8** | 同一通道的**合并顺序 == 节点名序** | 归约型通道的元素顺序 |
| **I-9** | 执行期间**通道正式值不被改写** | 执行期外部观察 |
| **I-10** | 出错轮：通道值 == 轮初 且 **写入版本不推进**（**含跑成功者**） | 快照对照 |
| **I-11** | 出错轮：执行版本与跳转目标 == 轮初 | 调度状态快照 |
| **I-12** | 中断元组长度 == 中断节点数；`.value` 逐字正确；**顺序 == 节点名序** | 元组断言 |
| **I-13** | 中断节点写入**不生效**；其它节点写入**照常合并**；**出错轮**则**一个都不合并** | 三断言 |
| **I-14** | 中断轮之后**不进入下一轮** | 轮次计数 |
| **I-15** | 异常**优先**于中断；中断元组**随之丢弃** | 双断言 |
| **I-16** | **零悬挂线程**；连续 ≥ 10 轮线程数不增长 | `threading.enumerate()` |
| **I-17** | **取消语义**：排队未启动者被**取消**（机制级夹具）· 运行中者**跑完并被等待** | 确定性夹具 + 时间窗 |

## 12. 边界（本契约**不**规定的事）

- **`interrupt()` 的产生与恢复** —— 归 **B10F1**（本契约只处理「节点抛出 `GraphInterrupt`」）。
- **结果里的 `__interrupt__` 键** —— 归 **B10F1**（**元素类型 = 元组** · **T-9**）。
- **载荷 `.id` 的自动生成** —— 归 **B10F1**（上游同款）。
- **`StateSnapshot` 的生产者**（`get_state()`）—— 归 **B15F1（M3）**（本契约只登记 `StateSnapshot.interrupts` 这个落点 · **下游承接 D-7**）。
- **async / 事件循环 / 可插拔执行器抽象** —— **v2** 范围。
- **`Send` 的动态 fan-out** —— 归 **B11F1**。
- **`recursion_limit` 与静态中断点** —— 归 **B13F1**。
- **checkpoint / 状态历史 / time-travel** —— 归 **B14F1 / B15F1 / B16F1**。
- **节点级重试 / 超时 / 取消运行中的任务** —— 不在 v1 范围（⇒ 一个不返回的节点会阻塞本轮 · 登记 **DR-3**）。
- **多源汇合边（AND / 屏障）** —— 归**独立 feature**（**B7F4**）· 偏离登记 **X-5**（本 feature **MUST NOT** 顺手做）。
- **可观测面（span / trace / 并发分组）** —— 归 **B18F1 / B19F1**（下游承接 **D-3**）。
- **用户节点函数的线程安全** —— **用户的责任**（内核不加锁 · 不代偿）。
- **`Command` 作为图的输入 / `resume` 的恢复效果** —— 归 **B10F1 / B7F3**。
- ⚠️ ~~多会话隔离（同一份规格并发跑多次）~~ —— **已由 2026-11-12 P2-b 落地** ⇒ **不再是本 feature 的限制**
  ⇒ 只做门面级承接（**B7F2 / B7F3** · **D-4** / **B14F1** · **D-5**）。
