## §2 EM-1 · 任务结果槽（**新增的内部形状** · 名字由本 plan 冻结）

### 2.1 形状

```python
# 内部私有 · 不导出 · 不进兼容矩阵 · 落在 src/freegraph/runtime/_concurrency.py
@dataclass(frozen=True, slots=True)
class _TaskOutcome:
    """一个任务在**执行期**产出的**私有**结果（执行期**零共享状态写**）。"""

    writes: dict[str, tuple[Any, ...]]   # 待写入（通道 key → 值序列）
    gotos: tuple[str, ...]                # 跳转目标（`Command.goto` 解析后的）
    error: BaseException | None           # 真实异常（原对象 · **不包装**）
    interrupts: tuple[Interrupt, ...]     # 该节点 `GraphInterrupt.args[0]`（≡ `payload`）的
                                           #   **元素**（`Interrupt` 对象 · 原样 · 不包装）
                                           #   ⚠️ MUST NOT 是 `payload` 本身（那是元组 ⇒ 嵌套元组）
```

> ⚠️ **名字由本 plan 冻结**：`_TaskOutcome`（**前导下划线** ⇒ 私有 ⇒ 不进 `__all__`）。

### 2.2 为什么要「结果槽」而不是「直接写调度状态」

并发写共享可变状态是**竞态来源**（即便 CPython 的 dict 写入是原子的，「读-改-写」与「迭代」
仍不安全）⇒ ⇒ 执行期每个任务 MUST 只产出**自己的结果槽**（待写入 / 跳转目标 / 异常 / 中断）
⇒ ⇒ 轮末 MUST 由调度器按「**节点名序**」**统一落回**（FR-010 · 裁定 11）。

### 2.3 结果槽的生命周期

```text
阶段 ③（并发）
  ├─ 正常     ──► writes / gotos 就位 · error=None · interrupts=()
  ├─ 抛异常   ──► error=原对象 · writes=() · gotos=() · interrupts=()
  └─ 抛中断   ──► interrupts = 该节点 `GraphInterrupt.args[0]`（≡ `payload`）的**元素**
                     （`Interrupt` 对象 · 原样）· error=None · writes=() · gotos=()
        │
        ▼
阶段 ③′（判定与落回 · **不抛任何异常**）
  ├─ 有 error  ──► 标记「本轮出错」⇒ **不合并任何写入** + **调度状态不落回**（整轮原子 · FR-010）
  ├─ 有 interrupts ──► 收集进「中断元组」（按节点名序）· **被中断节点不落回**
  └─ 无 error  ──► 成功节点**照常落回**（执行版本 +1 · 跳转目标整体替换）
        │
        ▼
阶段 ④（收集 · 按节点名序遍历结果槽）
  └─ 待写入**按节点分组**（顺序恒定 · 节点名序）
        │
        ▼
阶段 ⑤（合并 · 零改动）
  ├─ 出错轮 ──► **不进入本阶段**（一个都不合并 · 含跑成功的节点）⇒ 通道值保持轮初
  └─ 中断轮 ──► 合并**成功节点**的写入（被中断节点的写入丢弃）
        │
        ▼
阶段 ⑥（收尾 · **唯一的「抛出」点**）
  ├─ 有真实异常 ──► **抛出该 error**（原对象）⇒ 中断元组**随之丢弃**
  └─ 有 interrupts（无真实异常）─► **抛出合并后的 GraphInterrupt**（载荷 = 元组 · 节点名序）
```

> ⚠️ **阶段模型的唯一权威 = `contracts/concurrency-contract.md` §3**（**2026-11-13 拍板**）⇒
> 本节与 `tasks.md` **T014** MUST 与之**逐字一致**（含「**抛出**只发生在**阶段 ⑥**」）。
> ⚠️ **顺序是关键**（**裁定 9 / 10 / FR-014**）：
> ① **真实异常先抛**（⇒ 中断元组**随之丢弃**· 上游同款 · research **E-2e**）；
> ② 中断轮 ⇒ **先合并、后抛**（⇒ 用户接住异常后从调度状态读到的**已是合并后**的值 · Q12）。

## §4 状态机（一个 super-step 内的**七个阶段** · ③′ 为本 feature 细分）

> **既有五阶段**（B7F1 契约 §4）：① 触发判定 → ② 任务准备 → ③ 任务执行 → ④ 写入收集 →
> ⑤ 写入合并 ⇒ 本 feature 把阶段 ③ **细分**为 ③（**并发执行**）/ ③′（**判定与落回**）并**追加**
> 第 ⑥ 阶段「**收尾（抛出）**」⇒ 阶段 ① / ② / ④ / ⑤ 的**语义与编号逐字不变**。
> ⚠️ **阶段模型的唯一权威 = `contracts/concurrency-contract.md` §3**（**2026-11-13 拍板**）⇒
> 本节与 `tasks.md` **T014** MUST 与之**逐字一致**。

| # | 阶段 | 产物 | 本 feature 的变化 |
|---|---|---|---|
| ① | **触发判定** | 被触发的节点集合 | **零改动**（顺序 = **节点名序** · P2-c 已落地） |
| ② | **任务准备** | 任务集合 + **入参** | **零改动**（入参 = `read_channels(子映射)` · 子映射按**通道映射顺序**）⇒ **全部**入参在**任何节点执行前**确定 |
| ③ | **任务执行** | 节点返回值 / 异常 / 中断 | ★ **并发化**：线程池（**每轮**新建 + 关闭）· 每任务一个**结果槽** · **零共享状态写** |
| ③′ | **判定与落回** ★新增 | 判定结果 + 调度状态落回 | ★ 只做**判定与落回**（**不抛任何异常**）⇒ **成功节点照常落回** · **被中断节点不落回** · **出错轮一个都不落回** |
| ④ | **写入收集** | **待写入**（按节点分组） | **零改动**（`_collect_writes`）⇒ 但**顺序**由「完成时刻」改为「**节点名序**」 |
| ⑤ | **写入合并** | 合并后的状态 + 通道版本 + 步末清空 | **零改动**（`_merge_writes` · 批量 · 每通道**一次** `update`）⇒ ⚠️ **出错轮不进入**本阶段（整轮原子） |
| ⑥ | **收尾** ★新增 | **抛出**（真实异常 / 合并后的中断） | ★ **唯一的「抛出」点**：有真实异常 ⇒ **抛出**（原对象）· 有中断 ⇒ **合并抛出**一个（载荷 = 元组 · 节点名序） |

### 4.1 「并发执行」子阶段的口径（阶段 ③）

| # | 口径 | 值 |
|---|---|---|
| 1 | **机制** | 标准库 `concurrent.futures.ThreadPoolExecutor`（**每轮**新建 + 关闭） |
| 2 | **并发度** | `min(本轮任务数, max_concurrency or min(32, cpu+4))` ⇒ 缺省**有上限**（**上游同款**） |
| 3 | **零节点** | **MUST NOT** 创建任何线程 ⇒ **MUST NOT** 建池 |
| 4 | **提交顺序** | **节点名序**（⇒ 「首个异常」的选取 = **扫结果槽的第一个**） |
| 5 | **隔离** | 每任务一个**结果槽** ⇒ 执行期**零共享状态写** |
| 6 | **取消** | 首个真实异常 ⇒ 取消**排队未启动**的 future（`cancel()` → `True`）· **运行中者不中断**、但**被等待** |
| 7 | **异常** | 取「**节点名序**最靠前」的失败节点 ⇒ 原对象抛出（类型 / 消息 / **对象 identity** 逐字一致） |
| 8 | **附注** | 其余失败以 `add_note` 记录 ⇒ 格式：`其它并发失败 · 节点 <名>：<类型名>: <消息>` |
| 9 | **中断** | 收集进结果槽（取该节点 `GraphInterrupt.args[0]` ≡ `payload` 的**元素**）⇒ 轮末合并 ⇒ **一个** `GraphInterrupt`（载荷 = **元组** · **节点名序**）⇒ **抛出** |

### 4.2 报告口径（`SuperStepResult` 的**四个字段**）

| 字段 | 语义 | 本 feature |
|---|---|---|
| `state` | 本轮结束时的**稀疏**通道状态 | **零改动** ⇒ ⚠️ **MUST NOT** 塞入 `__interrupt__`（形态污染 · 裁定 25） |

## §6 校验规则（**V-15…V-19** · 本 feature 新增 · 与 B7F1 的 V-1…V-8 / B9F1 的 V-9…V-14 同族）

| # | 触发条件 | 失败信号 | 口径 |
|---|---|---|---|
| **V-15** | 一轮内**多个**节点失败 | **原对象**原样抛出（**节点名序最靠前**的那个）+ 其余失败以**附注**记录（固定格式：`其它并发失败 · 节点 <名>：<类型名>: <消息>`） | MUST **NOT** 包装 · MUST **NOT** 静默丢弃 · MUST **NOT** 依赖完成时刻 · ⚠️ **比上游更严**（**X-1**）|
| **V-16** | 节点抛出 `GraphInterrupt` | **不是失败** ⇒ 该节点视为**未完成**（无写入 · **不**推进执行版本 · **不**登记跳转目标）+ 载荷被**原样**收集 | MUST **NOT** 当作出错（⇒ 不触发整轮不合并）· MUST **NOT** 生成 / 改写 / 校验载荷 · ⚠️ **顺序** == **节点名序**（**X-7**）|
| **V-17** | 一轮内**同时**出现真实异常与中断 | 抛**真实异常**（原对象）· 中断元组**随之丢弃**（**上游同款**） | MUST **NOT** 让中断掩盖失败 · MUST **NOT** 自创留痕形态（**X-4**）|
| **V-18** | `max_concurrency` 传入非法值 | 类型不符（非 `int` / 非 `None`）⇒ 内置 `TypeError`；`< 1` ⇒ 内置 `ValueError`（两者均点名该参数）⇒ **入口即失败**（**哪怕本轮没有节点要跑**） | 显式失败优于隐式真值化 · **上游同款**（标准库线程池在**构造时**校验） |
| **V-19** | 节点函数返回非法类型 | 内置 `TypeError`（B7F1 的 **V-9** 同款）⇒ **原样**传播（MUST **NOT** 被并发包装） | 与并发**无关** ⇒ **零改动** |

> ⚠️ **零新增异常类型** ⇒ L1 的 20 符号面**零改动**（G7 恒绿 · **清单驱动**）· `freegraph.runtime.__all__` 仍 20。
> （⚠️ **2026-11-13 订正 · X1 / R-10**：L1 基线由 **18** 改为 **20** —— 上游对齐批次 P3 已扩面）
> ⚠️ **V-15 的「附注」** 用 **标准库**的异常附注机制（`BaseException.add_note` · **Python 3.11** 引入）
> ⇒ **不改变**异常的**类型 / 消息 / 对象 identity** ⇒ B7F1 契约 **I-15** 不破。
> ⚠️ **V-18 的 `bool`**：Python 的 `bool` 是 `int` 的子类 ⇒ 上游 `ThreadPoolExecutor(max_workers=True)`

## §7 不变量（**I-1…I-17** · 可自动判定）

> **每条** MUST 有**可执行的断言**（tasks 阶段的用例逐条承载）⇒ **MUST NOT** 只写散文。

| # | 不变量 | 判定方式 | 对应 SC |
|---|---|---|---|
| **I-1** | 同轮的两个节点**重叠执行**（重叠时长 > 0 / 屏障夹具放行） | 屏障夹具 + 时间窗测量 | SC-001 |
| **I-2** | 同轮的两个节点**各执行恰好 1 次** | 副作用计数 == 1 | SC-001 |
| **I-3** | 首个异常：**类型 / 消息 / 对象 identity** 逐字一致 · 且由「**节点名序**最靠前」者决定 | `type` / `str` / `is` 三断言 + 重复 ≥ 3 次 | SC-002 / SC-029 |
| **I-4** | 其余并发失败**均被附注记录**（丢弃数 == 0）且附注**含三样**（节点名 / 类型名 / 消息） | `__notes__` 逐条断言 | SC-014 |
| **I-5** | 异常后**后续 super-step 不执行**（下游执行计数 == 0） | 执行计数 | SC-003 |
| **I-6** | 并发与串行（`max_concurrency=1`）的**最终状态 + 待写入序列逐项相等** | 双模式对照 | SC-004 |
| **I-7** | 同一规格重复运行 **≥ 3** 次 ⇒ 最终状态与执行节点序列**逐项相等** | 重复对照 | SC-005 / SC-026 |
| **I-8** | 同一通道上多个写入的**合并顺序 == 节点名序** | 归约型通道的元素顺序断言 | SC-005 / SC-016 |
| **I-9** | 执行期间**通道的正式值不被改写** | 执行期外部观察 == 轮初值 | SC-006 |
| **I-10** | 出错轮：**全部**通道值 == **轮初**（逐字）且**写入版本不推进**（**含跑成功者**） | 快照对照 | SC-007 |
| **I-11** | 出错轮：**全部**节点的执行版本与跳转目标 == **轮初** | 调度状态快照对照 | SC-008 |
| **I-12** | 中断元组**长度 == 中断节点数**；每个元素的 `.value` **逐字正确**；**顺序 == 节点名序** | 元组断言 | SC-009 / SC-010 |
| **I-13** | 中断节点的写入**不生效**；同轮其它节点的写入**照常合并**；**出错轮**则**一个都不合并** | 三断言 | SC-011 |
| **I-14** | 中断轮之后**不进入下一轮** | 轮次计数 | SC-012 |
| **I-15** | 真实异常**优先**于中断；中断元组**随之丢弃** | 双断言 | SC-013 |
| **I-16** | 本轮结束后**零悬挂线程**；连续 **≥ 10** 轮后线程数**不增长** | `threading.enumerate()` 计数 | SC-025 |
| **I-17** | **取消语义**：排队未启动者被**取消**（机制级夹具）· 运行中者**跑完并被等待** | 确定性夹具 + 时间窗 | SC-028 |

## §8 规模与性能口径

| 维度 | 口径 |
|---|---|
| **并发度** | `min(本轮任务数, max_concurrency or min(32, cpu+4))` ⇒ 缺省**有上限**（**上游同款**）⇒ 线程数 ≤ **12**（本机 cpu=8） |
| **线程创建开销** | 每轮 O(任务数) 次线程创建（`ThreadPoolExecutor` 内部按需创建 ⇒ 实际 ≤ 并发度） |
| **合并开销** | **零增量**（`_group_writes` / `_merge_writes` 一字不改） |
| **结果槽内存** | O(任务数 × 每节点的写入规模) ⇒ 与既有「待写入」同量级 |
| **⚠️ MUST NOT** | 用**墙钟耗时**做判据（CI 假红）⇒ 判据用「执行次数 / 屏障放行 / 逐元素相等 / 逐字相等 / 线程计数」（§7） |
| **⚠️ 已知的性能代价** | 每轮新建 + 关闭线程池（线程创建开销 ~ 数十 µs / 线程）⇒ v1 **接受**（换取「零悬挂线程」的可判定性） |
| **⚠️ 已知的功能限制** | 用户节点函数**必须线程安全**（裁定 16 · 内核不加锁）⇒ 文档 MUST 写明 |
