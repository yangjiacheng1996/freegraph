# Feature Specification: B12F1 · 节点执行 + 并发执行 + 错误传播 + `GraphInterrupt` 合并

**Feature Branch**: `b12f1-concurrency-errors`

**Created**: 2026-11-11（初版）· **2026-11-12 修订**（上游对齐 **B** 口径 · 修订清单 **V-1…V-7**）· **2026-11-13 对账补记**（**V-8** · 回溯修订清单扩为 **T-1…T-11**）

**Status**: Draft

**Input**: User description: "B12F1 · 节点执行 + 并发执行 + 错误传播 + `GraphInterrupt` 合并 —— 让调度内核能**真正执行节点函数**，并处理三件在真实使用中立刻会遇到的事：① **同一 super-step 内的多节点并发执行**；② **节点抛异常时的错误传播**；③ **多个节点同时中断时的 `GraphInterrupt` 合并**。本 feature 的判定是：**并行节点不被串行化**、**首个异常被正确抛出**。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 同一轮的两个节点都真的并行跑（Priority: P1）

作为用户，我从 `START` 分叉到两个节点时，我希望它们**都被执行**、并且**真的同时在跑**
（而不是一个跑完另一个才跑，也不是只跑了其中一个）。

**Why this priority**: 这是本 feature 的**主目标**与立项书小目标「**并行节点不串行化**」的直接落点；
若这一点不成立，本 feature 交付的一切（错误传播 / 中断合并）都建立在错误的地基上。

**Independent Test**: 给两个节点各装一个**屏障夹具**（两边都到齐才放行）⇒ 串行执行会**死锁**、
并发执行会**放行** ⇒ 单独实现本故事即可得到一个可验收的垂直切片。

**Acceptance Scenarios**:

1. **Given** 一个从 `START` 分叉到 `left` / `right` 两个节点的图，**When** 运行它，**Then**
   两个节点**各自**恰好执行 **1** 次（副作用计数各 == 1），且两者的**执行时间窗有重叠**
   （重叠时长 > 0，或屏障夹具被放行）。
2. **Given** 同一张图，**When** 以「串行模式」（`max_concurrency=1`）运行同一份规格，**Then**
   两个节点仍各执行 **1** 次、最终状态与并发模式**逐项相等**（并发只改**时序**，不改**语义**）。
3. **Given** 一轮里被触发的节点数 **超过**并发度上限（缺省 `min(32, cpu+4)`），**When** 运行它，
   **Then** 超出的节点**排队**执行（不是被丢弃，也不是被串行化到「一次只跑一个」），
   且**全部**节点最终各执行 **1** 次（**上游同款**）。

### User Story 2 - 节点抛异常时拿到的是原始异常（Priority: P2）

作为用户，我的节点里有个 bug 抛了 `ValueError`，我希望 freegraph 把它**原样**抛给我，
而不是包成 `RuntimeError`、也不是静默吞掉、也不是只告诉我「某个节点失败了」。

**Why this priority**: 「如实反映用户代码的行为」是运行时的基本义务；错误信息被包装或吞掉，
会让最难排查的一类问题变成最难排查的一类问题。

**Independent Test**: 让节点抛一个自定义异常 ⇒ 断言捕获到的**异常类型**、**消息**与
**异常对象 identity** 与节点内抛出的一致；再断言**下游节点一次都没跑**。

**Acceptance Scenarios**:

1. **Given** 一个节点抛出 `ValueError("boom")`，**When** 运行图，**Then** 调用方捕获到的异常
   **类型**是 `ValueError`、**消息**逐字为 `"boom"`、**对象**与节点内抛出的那个**同一个**。
2. **Given** 同一轮里**两个**节点都抛异常，**When** 运行图，**Then** 抛出的那个异常的
   **类型与消息**与「**节点名序更靠前**的那个失败节点」**逐字一致**（⇒ 结果**可复现**，
   不依赖完成时刻的竞态）；且**其余**失败以**附注**形式记录在抛出异常上（调用方**看得见**）。
3. **Given** 某节点抛出异常，**When** 运行图，**Then** 该轮**之后**的任何 super-step
   **不再执行**（下游节点的执行计数 == 0），且该轮产生的写入**一个都不生效**
   （通道值与**本轮开始前**逐字相等）。
4. **Given** 一轮里有节点在**排队等待**（并发度已满），**When** 其中一个节点失败，**Then**
   **排队未启动**的任务被**取消**（不执行），而**运行中**的任务**跑完并被等待**
   （上游同款）。

### User Story 3 - 多个中断被完整收集（Priority: P3）

作为实现者，两个节点同时请求人工审批时，我希望拿到**两个**中断，而不是一个 ——
否则待审批项会悄悄丢一个，人工审批就漏了。

**Why this priority**: 这是 HITL（人机协同）场景的**正确性底线**；丢一个待审批项 = 用户
永远等不到那个审批 = 流程卡死。

**Independent Test**: 两个节点各抛一个 `GraphInterrupt`（载荷不同）⇒ 断言捕获到的中断
**载荷是一个长度 == 2 的元组**，且各元素的 `.value` **逐字正确**。

**Acceptance Scenarios**:

1. **Given** 同一轮里两个节点各抛一个 `GraphInterrupt`（载荷 `"approve-A"` / `"approve-B"`），
   **When** 运行图，**Then** 调用方捕获到**一个** `GraphInterrupt`，其**载荷是长度 == 2 的元组**，
   且两个元素的 `.value` **分别**逐字为 `"approve-A"` / `"approve-B"`（MUST NOT 只保留第一个）。
2. **Given** 某节点抛出 `GraphInterrupt`，**When** 运行图，**Then** 该节点的**自身写入不生效**，
   而同轮**其它**节点的写入**照常合并**（中断是控制流，不是「出错」）。

### User Story 4 - 并发不改变状态的语义（Priority: P4）

作为用户，我关心的是**结果**而不是**时序**：同一张图，跑一次和跑十次、并发跑和串行跑，
最终状态必须**一模一样**；对非交换的归约器尤其如此。

**Why this priority**: 并发引入的是**语义风险**而不是性能收益 —— 若「并发跑出来的状态」依赖
谁先跑完，那这个框架的输出就不可复现，**不可复现的图运行时没有价值**。

**Independent Test**: 同一份规格（带非交换归约器）分别以并发 / 串行 / 重复 **≥ 3** 次运行 ⇒
逐项比对最终状态与待写入序列。

**Acceptance Scenarios**:

1. **Given** 一张带**非交换归约器**（如「拼接列表」）的图，**When** 分别以并发与串行运行，
   **Then** 最终状态**逐项相等**；同一通道上多个写入的**合并顺序**在两种模式下**逐项相同**。
2. **Given** 同一份规格，**When** 重复运行 **≥ 3** 次，**Then** 每次的最终状态与执行节点序列
   **逐项相等**（差异 == 0）。

### Edge Cases

- **一轮里只有一个节点** ⇒ 并发机制 MUST NOT 引入任何额外开销或行为差异（单节点 = 无并发可言）。
- **一轮里零个节点**（空任务集）⇒ 立即收敛，**MUST NOT** 创建任何线程。
- **一轮里的节点数 > 并发度上限** ⇒ 超出的**排队**（上游同款）⇒ MUST NOT 丢弃、也 MUST NOT 退化成一个一个跑。
- **节点函数自己抛 `GraphInterrupt` 与抛普通异常** ⇒ 两者**语义不同**：前者是控制流（收集后**合并抛出**）、
  后者是失败（原样抛出）；同一轮里**同时**出现 ⇒ **真实异常优先**（MUST NOT 让中断掩盖崩溃）。
- **同一轮里多个节点都抛 `GraphInterrupt`** ⇒ MUST **合并成**一个异常（载荷 = 元组），
  MUST NOT 只保留第一个（MUST NOT 逐个抛）。
- **节点函数返回了非法的返回值**（如 `None`）⇒ 与 B7F1 的 **V-9** 同款：显式失败（`TypeError`），
  且该失败 MUST **原样**传播（MUST NOT 被并发包装）。
- **节点函数阻塞很久**（用户代码慢）⇒ 其余节点 MUST **不被阻塞**（并发语义）；
  但本 feature **不提供**节点级超时（MUST NOT 越界到 B13F1 / 重试能力）。
- **节点函数永不返回**（卡死）⇒ 本轮**永不结束** ⇒ 异常**也**迟迟不抛（V-2 的代价 · 已登记）
  ⇒ **内核不取消运行中的任务**（上游同款）⇒ 用户须在**节点内部**自行兜底。
- **节点函数修改了共享的外部对象** ⇒ 用户责任（MUST NOT 由内核加锁掩盖；见 Assumptions）。
- **节点函数内部再调用 freegraph 的其它 API** ⇒ 本 feature **MUST NOT** 保证其线程安全
  （跨线程复用同一张图 / 同一调度状态不在本 feature 的承诺内）。
- **本轮有节点失败、同时另有节点产出写入** ⇒ 该轮**全部**写入**不合并**（整轮原子），
  且**调度状态**（执行版本 / 跳转目标）**也不落回**（⇒ 无「幽灵触发」）。
- **本轮有节点失败、同时另有节点排队未启动** ⇒ 排队者**会被取消**（V-2 · 上游同款的**机制**），
  但**端到端**排队者**常常照跑**（**实测**上游 **15/15** 次照跑 ⇒ 失败线程一退出，空出来的
  跑位立刻把排队任务捡起来跑）⇒ ⇒ 判据 MUST **分两层**（端到端比集合 · 机制层用确定性夹具），
  MUST **NOT** 把「排队者一定没跑」写成硬判据（**上游自己也达不到** ⇒ 会偶发红）。
- **`Command.goto` 指向同一个目标**（多个节点都跳向 X）⇒ X 在下一轮**至多被触发一次**
  （与静态边同款），MUST NOT 因并发而重复触发。
- **节点名与通道名同名** ⇒ 触发源的两个命名空间（`("c", key)` / `("e", 节点名)`）**互不干扰**
  （B7F1 冻结面）。
- **用户节点函数本身不是线程安全的**（如用非线程安全的全局计数器）⇒ 结果可能不可复现 ⇒
  用户的责任（MUST 在文档与 Assumptions 中写明）。
- **两个节点的**名字**只差大小写 / 前缀** ⇒ **节点名序**必须是**确定的**全序（MUST NOT 依赖哈希序）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001（同轮任务 MUST 并发执行）**：同一 super-step 内的**全部**被触发节点任务 MUST
  **并发**执行（MUST NOT 被串行化）；并发 MUST 用**线程**实现（标准库线程池）⇒ MUST NOT
  引入 async / 事件循环抽象（v2 范围）。
  ⚠️ **并发度**（**V-1 · 上游同款**）：缺省 MUST 为 **`min(32, cpu+4)`**（**有上限**）
  ⇒ 实际并发度 = `min(本轮任务数, 缺省上限)`；**显式** `max_concurrency=N` ⇒
  实际并发度 = `min(本轮任务数, N)`（**N MUST NOT 被 32 再夹一次**）⇒ 超出上限者**排队**。
  ⚠️ **上游同款**：上游**同步**路径用线程池执行节点任务（`langgraph/pregel/_executor.py:40-52`
  的 `BackgroundExecutor` · `:54-75` 的 `submit`）· 线程池容量由 `max_concurrency` 决定
  （`langchain_core/runnables/config.py:660-674`）⇒ freegraph v1 的「线程并发」与上游同构。
  ⚠️ **零节点的一轮** MUST NOT 创建任何线程。

- **FR-002（写入收集 MUST 保持「待写入 → 轮末统一合并」）**：并发任务的产出 MUST **先收集**为
  「待写入」，MUST NOT 在节点执行期间改写通道的**正式值**；合并 MUST 发生在**本轮末尾**
  （轮次边界内），且 MUST 走 B7F1 的**批量**合并路径（每个通道**一次** `Channel.update(values)`）。
  ⚠️ MUST NOT 为并发另写一条合并路径（否则「未知 key 只对 `dict` 报错」这类分叉迟早出现）。
  ⚠️ **`Command.update` 的写入 MUST 与普通返回值走同一条合并路径**（B9F1 裁定 4 的延续）。

- **FR-003（首个异常 MUST 原样传播）**：节点抛出的异常 MUST **原样**向上传播给调用方 ——
  异常的**类型**、**消息**与**对象 identity** MUST 与节点内抛出的那个**逐字一致**；
  MUST NOT 包装成别的异常类型、MUST NOT 静默吞掉。
  ⚠️ **「第一个」的判定 MUST 是确定性的**：MUST 取「**节点名序**最靠前**的那个失败节点」的异常
  ⇒ MUST NOT 依赖「谁先跑完」（完成时刻的竞态）⇒ ⚠️ **比上游更严**（上游 `done.pop()` ⇒ 竞态）
  ⇒ MUST **如实标注**（偏离登记 **X-1**）。
  ⚠️ **失败时 MUST 取消「排队未启动」的同轮任务**（**V-2 · 上游同款**）：运行中的任务 MUST
  **不中断**、但 MUST **被等待** ⇒ ⇒ 「本轮跑过哪些节点」**可复现**（被取消者**未被启动** ⇒
  MUST NOT 出现在 `executed` 里）。

  ⚠️ **中断轮 MUST NOT 产出 `SuperStepResult`**（**澄清轮 Q12 · 发起者拍板**）：入口在**抛出**
  该异常时 MUST **不**返回结果对象（四字段一个都不给）⇒ 调用方接住异常后 MUST 从**自己持有的
  调度状态**读通道值（合并**已经**发生 ⇒ 状态**没丢**）⇒ ⇒ 「把异常**转成**结果键
  `__interrupt__`」的义务归 **B10F1**（下游承接 **D-1**）。
  ⚠️ **`SuperStepResult` 的四字段冻结面 MUST 零改动**（`state` / `executed` / `node_writes` /
  `steps`）⇒ 本 feature MUST **NOT** 为中断另加结果字段 ⇒ 结果的 `__interrupt__` **键**归 **B10F1**
  （下游承接 **D-1** · 回溯修订 **T-9**）。

  ⇒ `steps` **当前无载体** ⇒ 该口径的**载体**转移到**将来 B10F1 产出的结果对象**：届时
  MUST **如实计**「**实际跑过的轮数**」（中断轮算 **1**）⇒ MUST **NOT** 补那个「发现没任务了」的
  **空轮** ⇒ 挂起与跑完是**两种不同的结束方式**（后者 `steps` 比前者**多 1**）⇒ MUST 在文档**写明**。
  ⚠️ **内核 MUST 原样收集载荷**（裁定 20 · 澄清轮 Q6）：MUST **NOT** 生成、改写或校验载荷对象
  ⇒ 元素的 `.value` / `.id` **逐字**等于用户抛出时的载荷；「**自动生成 `.id`**」的义务归
  **B10F1**（上游同款）⇒ 本 feature **零 L1 改动**。
  ⚠️ **L1 冻结面零改动**：MUST **NOT** 改 `GraphInterrupt` 的字段、构造签名与继承关系。

### Key Entities

- **节点任务（node task）**：一个「被触发的节点 + 它这一轮收到的入参」的待执行单元 ——
  **并发度** = `min(本轮任务数, 并发度上限)`（裁定 2 · **V-1**）。
- **并发任务组（concurrent task group）**：同一 super-step 内**全部**被触发的节点任务的集合 ——
  它们**同时**在跑，但**产出被收集后才落回**（FR-002 / FR-010）。
- **任务结果槽（task result slot）**：每个任务在执行期产出的**私有**结果 ——
  「待写入 / 跳转目标 / 异常 / 中断」四项（FR-010 · 裁定 11）⇒ 轮末由调度器按**节点名序**
  统一落回。
- **首个异常（first failure）**：本轮**失败节点**中「**节点名序最靠前**」的那个所抛出的异常 ——
  MUST 以**原始类型与消息**抛出（裁定 5 / 6）⇒ ⚠️ **比上游更严**（上游取完成时刻的竞态）。
- **中断集合（interrupt set）**：本轮**全部**节点抛出的 `GraphInterrupt` 的 **`args[0]`（≡ `payload`）
  的元素**序列 —— 每个元素带 `.value` / `.id`（**C17**）⇒ **合并抛出**为一个 `GraphInterrupt` ·
  **载荷 = 元组**（裁定 7 / 8 · **V-3**）⇒ **不落调度状态字段**。
- **待写入（pending writes）**：节点产出、**轮末统一合并**的写入；**按节点分组**保留
  （B7F1 FR-006）⇒ 并发只改**产出时刻**，MUST NOT 改**归并顺序**（裁定 3 / 15）。
- **节点名序（node-name order）**：节点名**字典序** —— 并发下唯一被承认的**确定性顺序**
  （合并顺序 / 报告顺序 / 首个异常顺序三者统一用它）⇒ **上游同款**（`_algo.py:482`）。
- **并发度上限（concurrency cap）**：`max_concurrency` 给出的**同时在跑**的任务数上限 ——
  缺省 `min(32, cpu+4)`（**上游同款**）· 显式 `N` ⇒ `min(本轮任务数, N)`（裁定 2 / 18）。
