## Clarifications

### Session 2026-11-06

- **Q1（`Node` 命名冲突 · 公开符号面）**：节点函数协议与图结构节点元素在提示词中**同名**
  （两者都叫 `Node`），而公开符号面只能有一个 `Node`。→ **A：图结构元素保留
  `Node` / `Edge`**（与上游 `langchain_core.runnables.graph` 同名，且 B22F1 的 SC-004
  已按「`Graph` / `Node` / `Edge` 类型名可判定」写死），**节点函数协议改名 `NodeFunc`**。
  理由：下游只有 B22F1 依赖图元素的名字，无任何下游依赖「节点函数协议」的名字；
  协议名与 4 类协议表的字面不符这一代价，在**冻结记录**中写明裁定即可。
  → 「`Node`」一词此后**唯一**指图结构节点元素。
- **Q2（`Span` 类型归属）**：`TraceSink` 协议的签名必须引用一个**已存在**的 span 类型，
  而「自有 `Span` 数据类」原被列为 B18F1 的交付物。→ **A：B2F1 落 `Span` 纯数据类**
  （含 C23 必带四项），**B18F1 只负责「生产」span（行为）**。理由：契约冻结要求字段面
  先冻结，否则 B19F1（`TraceSink` 接入）会踩在未冻结面上。→ B18F1 的交付物口径相应
  收窄为「span 生产接入」，类型字段面以本 feature 为准。
- **Q3（C27 的协议面范围）**：C27 要求「存储与查询 MUST 经由同一协议、后端可替换」，
  但 SC-001 与 §7 实体表只列 4 类协议 + `CompiledGraph` 协议。→ **A：本 feature 只落
  C27 的请求 / 返回纯数据结构**（`TraceQuery` + 结果集合 = span 列表），**不落第五个
  协议**；「同一协议」作为**约束文字**记入冻结记录与冻结对照表（C27 标「数据已冻结 /
  协议面挂起（B20F1）」）。理由：**协议面此刻定死，若后续 feature 增多导致要改，
  就是大面积返工**——把方法集留到有后端实现经验（B20F1 / B20F2）之后一次定准，
  风险最低。
- **Q4（图结构数据类的字段名与容器形态）**：`Graph` / `Node` / `Edge` 的字段名与容器
  形态最终定成什么？ → **A**：字段清单**逐字冻结**为 ——
  `Graph.nodes: tuple[Node, ...]` / `Graph.edges: tuple[Edge, ...]`；
  `Node.id`（节点名）/ `Node.name`（别名，缺省归一为 id）/ `Node.metadata`（可选附加信息）；
  `Edge.source` / `Edge.target` / `Edge.conditional: bool` /
  `Edge.condition: str | None`（条件名）。理由：保留上游 `langchain_core.runnables.graph`
  的**核心字段名**（`id` / `name` / `source` / `target` / `conditional`）作兼容锚点，
  同时**砍掉**装对象引用的 `data`（上游那里装的是可调用对象 / pydantic 对象，
  freegraph 的纯数据纪律装不下），容器用**不可变元组**（与不可变记录自洽）。
- **Q5（`Checkpointer` 协议的冻结粒度）**：检查点协议在本 feature 冻结到多细（只冻结方法名
  与语义，还是连参数与返回结构一起定死）？ → **A：只冻结「方法名 + 语义 + 最小约束」**——
  恰为六个方法；读写面 MUST 能承载**检查点标识**；载荷 MUST 为**纯数据**；
  **参数与返回结构挂起 B14F1**。理由：风险最低——现在钉死形状，后期大概率返工；
  且 B14F1（内存）/ B15F1（SQLite）两个后端一起给出经验后再定形状更准；
  本 feature 仍守住「六方法齐全」这个可判定判据。冻结表 C19 标「协议面已冻结 /
  载荷形状挂起（B14F1）」。
  > **B2F1 第六轮复核补充（2026-11-06 · 发起者裁定）**：**冻结粒度上调为
  > 「方法名 + 语义 + 参数名 + 最小约束」**——**方法名与参数名已冻结**（逐字按
  > `data-model.md` §2.2：`get_tuple` / `list` / `put` / `put_writes` /
  > `delete_thread` / `get_next_version`，首参名 `config`、类型 `RunConfig`，
  > `delete_thread` 的参数名 `thread_id`、类型 `str`），理由同 Q8 的参数名裁定
  > （协议签名不写死参数名即无法实现，静态类型检查 SC-004 与对外文档都需要确切签名）；
  > **挂起的只有返回类型与载荷形状**（仍归 B14F1）。冻结表 C19 的标注相应改为
  > 「**已冻结 / 载荷形状挂起（B14F1）**」。
- **Q6（`Span` 数据类的字段清单与字段名）**：`Span` 的字段最终定成什么？ → **A：11 字段
  逐字冻结** —— `id`（span 唯一标识）/ `name`（span 名）/ `attributes`（属性，命名对齐
  `gen_ai.*`）/ `parent`（**父 span 的 `id`**，无父为空）/ `start_time` / `end_time`
  （UTC ISO-8601 字符串）/ `context`（附加上下文），**外加必带四项** `thread_id` /
  `run_id` / `node`（节点名）/ `checkpoint_id`。理由：三个 `_id` 名字是宪法原则 VII 与
  Q8 §3.4.1 已写死的；补 `id` 是因为「父级」必须靠**标识**引用（放对象引用则 JSON
  序列化落地不了，C27 第 ③ 条作废）；`node` 与既有 `Node.id`（节点名）对齐，
  避免同一概念两个词。
- **Q7（`Store` 协议的寻址形态与冻结粒度）**：`Store` 的「命名空间」长什么样（层级元组
  还是点分字符串）？ → **A：只冻结语义层** —— 恰为六个方法；命名空间 = **层级路径**
  （多段），键 = 字符串；取值 = **纯映射**（可 JSON 序列化）；**具体载体形态与
  `batch` 的操作表示挂起 v2**（v1 无实现）。理由：与 Q3 / Q5 一致的取舍——v1 无任何实现
  会用到这个形状，此刻定死只有返工风险、没有收益；「命名空间是层级路径」这一层语义
  已足够让 freechain 做设计输入。（注：上游存在**两套**并存口径——长期存储接口用层级
  元组 `langgraph/store/base/__init__.py:71`，检查点命名空间用字符串，freegraph 暂不
  选边，待有实现经验再定。）
  > **B2F1 第六轮复核补充（2026-11-06 · 发起者裁定）**：**冻结粒度上调为
  > 「方法名 + 语义 + 参数名 + 最小约束」**——**方法名与参数名已冻结**（逐字按
  > `data-model.md` §2.4：`get` / `search` / `put` / `delete` / `list_namespaces` /
  > `batch`；`namespace` / `key` / `value` / `namespace_prefix` / `prefix` / `ops`）；
  > **挂起的只有命名空间的载体类型与 `batch` 的操作表示**（仍归 v2）。
  > **参数名逐字对齐上游（兼容锚点 · 2026-11-06 第六轮复核核实）**：`search` 的首参名为
  > **`namespace_prefix`**、`list_namespaces` 的首参名为 **`prefix`**——二者是**上游
  > LangGraph 1.2.11 的原样命名**（核实 `langgraph/store/base/__init__.py`
  > `search(self, namespace_prefix, /, …)` / `list_namespaces(self, *, prefix=None, …)`），
  > freegraph **刻意逐字镜像**（D-09 的「保留上游核心名作兼容锚点」原则）⇒
  > **MUST NOT** 为「一个概念一个名字」而改名（① 改之即偏离上游；② 两者连**参数形态**都不同
  > ——`search` 的是位置参数、`list_namespaces` 的是关键字参数，本就不是同一个参数位）。
  > **上游的这个命名分歧在此显式登记**（宪法原则 VIII 的证据纪律）。
- **Q8（`CompiledGraph` 各方法的返回类别）**：编译产物协议里各方法返回什么、查不到状态时
  返回空值还是抛异常？ → **A：冻结到「方法名 + 语义 + 返回类别 + 参数名（占位名）」** ——
  `invoke` → **完整状态字典**；`stream` → **事件迭代器**（元素为纯数据字典，mode 取值为
  字符串，枚举归 B8F2）；`get_graph(xray=False)` → **`Graph`**；
  `get_state` → **状态快照，查不到时返回空值**（不抛异常）；
  `get_state_history` → 状态快照迭代器；`update_state(config, values, as_node=None)` →
  **状态快照**（**参数顺序同属冻结面**——逐字见 `data-model.md` §2.5）。**行为细节**归各自实现 feature（`invoke` → B7F3、`stream` → B8F2、
  状态查询 → B15F1、`update_state` → B16F1）。理由：与前三轮取舍一致；返回类别是
  freechain 写适配层的**最低必需信息**（再少就写不了）；「查不到返回空值、不抛异常」
  与本项目「不抛无谓异常、让上层兜住」的基调一致。
  > **B2F1 复核补充（2026-11-06 · 文档一致性复核）**：**参数名**原挂起各实现 feature，
  > 但协议签名**不写死参数名即无法实现**（静态类型检查 SC-004 与对外文档都需要确切签名），
  > 且四个下游 feature 各自实现在即、改名成本高 ⇒ 改为**参数名按
  > `data-model.md` §2.5 的签名**冻结**为**占位名**（`input` / `config` / `stream_mode` /
  > `xray` / `as_node`）；**行为语义**仍挂起；下游确需改名者走**契约修订**流程
  > （见 Assumptions「协议冻结的粒度」），MUST NOT 就地改型。
- **Q9（span 的「开始 → 结束」两次回调收到什么）**：两次回调收到的是不是同一个对象？
  → **A：`Span` 冻结为不可变记录** —— 开始回调收到「`end_time` 为空」的实例，
  结束回调收到**同 `id`、`end_time` 已填的新实例**，两次**按 `id` 配对**。
  理由：守住纯数据纪律（与 B1F1 已冻结的「不可变记录 + 字段级相等语义」一致）；
  「开始时的快照不会被事后改写」是可断言的性质（B19F1 的嵌套与配对测试依赖它）；
  配对正好复用已冻结的 `Span.id` 字段。
- **Q10（公开符号清单的冻结方式）**：契约层对外暴露的符号清单要不要在 spec 里逐字
  列出？ → **A：spec 逐字列出本 feature 新增的 10 个公开符号**，并声明**完整**清单
  （含 B1F1 已有的 8 个，共 18 个）的**唯一权威仍是 `contracts/public-api.md`**
  （沿用 B1F1 已定的口径）。理由：spec 自包含地写死「新增了什么」，冻结记录可直接引用；
  而完整清单**不复制**进 spec，避免两处手工维护漂移。新增 10 个 = `NodeFunc` /
  `Checkpointer` / `TraceSink` / `Store` / `CompiledGraph` / `Graph` / `Node` / `Edge` /
  `Span` / `TraceQuery`。
- **Q11（`TraceQuery` 的字段名）**：trace 查询请求结构的字段最终叫什么？ → **A：沿用
  span 侧已冻结的字段名口径** —— `run_id` / `thread_id` / `node`（与 span 侧**同名**）
  + `start_time` / `end_time`（时间范围，**UTC ISO-8601 字符串**，与 span 的起止字段同名）。
  五个字段**全部可空、可组合**；全空 = 取全部。理由：一个概念在项目里只有一个名字，
  是本项目「术语纪律」最省心的做法；时间字段名与 span 侧同名后，用户从 span 上读到
  的时间可直接当过滤条件用，零转换。
- **Q12（公开数据类的哈希语义）**：`Graph` / `Node` / `Edge` / `Span` 能不能放进 `set`
  或当字典的键？   → **A：明确不可哈希**，只保证「字段级相等」；文档 MUST 写明，
  用户需按 `id` 等标识自行去重。理由：这些类型含映射型容器（`metadata` /
  `attributes` / `context`），要可哈希就得把 Q4 / Q6 刚定下的字段清单推翻重做；
  「含容器的数据记录不可哈希」是常规代价（B1F1 的 `StateSnapshot` 早已如此并写进文档）。
  > **逐类理由（第五轮复核补记 · 2026-11-06）**：`Edge` 四字段**全是标量**、
  > `Graph` 的不可哈希来自**元素不可哈希**——二者并非「含映射字段」，
  > 故「不可哈希」对这两类**不是**「含映射字段」的自然结果，而是一条**显式约定**
  > （`Edge` 须显式 `__hash__ = None`，`Graph` 随元素不可哈希）——**逐类说明见 FR-006**。
- **Q13（四份交付物的落盘位置）**：冻结对照表 / 冻结记录 / 公开符号清单 / 人工验证记录

  对照表 + 冻结记录**合并**落 `specs/b2f1-contracts-protocols/contracts/public-api.md`

  `specs/b1f1-contracts-core/contracts/public-api.md`（后者作为 B1F1 的历史快照保留、

## User Scenarios & Testing *(mandatory)*

### User Story 1 - freechain 只靠协议实现自己的持久化后端 (Priority: P1)

作为 freechain（LangChain 替代层）的开发者，我希望能拿到 freegraph 的**检查点协议**，
从而把 freegraph 产生的快照与待写入数据写进**我自己的**存储（比如 freechain 自带的
数据库层），而不必等待 freegraph 提供某种特定后端——以便跨仓库分层真正成立
（freechain 只依赖契约，不依赖 freegraph 的内部实现）。

**Why this priority**: 持久化是 freechain 的第一落地场景；若协议面缺失，freechain
只能等 freegraph 的具体后端就绪（或反向依赖 freegraph 内部模块），跨仓库分层即告失效。

**Independent Test**: 实现一个**只声明协议方法**的假检查点后端（不继承任何 freegraph
基类），把它交给静态类型检查器断言「是该协议的实例」，并断言运行时结构化子类型检查
同样接受它——即算独立交付。

**Acceptance Scenarios**:

1. **Given** 一个仅声明协议方法的假检查点后端，**When** 交给静态类型检查器判定，**Then** 判定通过（类型检查器接受其为该协议实例），且判定不要求显式继承。
2. **Given** 上述假后端，**When** 用运行时结构化子类型判定，**Then** 判定通过（用户无需显式继承即可满足协议）。
3. **Given** 一个**缺少其中任一方法**的假后端，**When** 做结构化子类型判定，**Then** 判定失败（协议面是「方法集合齐全」而非「鸭子类型宽松通过」）。
4. **Given** 只有 freegraph 基础包的环境（未装任何 LangChain 家族包），**When** 导入协议，**Then** 导入成功，依赖闭包为空集。

### User Story 2 - 上层注入自己的可观测接收端 (Priority: P2)

作为用户，我希望能传入一个实现了**可观测协议**的对象来接收运行轨迹，从而把 freegraph
的运行过程接到我已有的日志系统——以便我不必让 freegraph 引入任何 SDK 或服务。

**Why this priority**: 「不注入即零开销零外呼」是本项目的红线（宪法原则 I / IV）；
协议面是这条红线的落点，没有它，上层只能被迫接受 freegraph 自带的可观测形态。

**Independent Test**: 实现一个假接收端，收集「span 开始 / span 结束」两类回调，
断言它通过静态类型检查与运行时结构化子类型判定，并断言回调成对（异常路径下同样成对）。

**Acceptance Scenarios**:

1. **Given** 一个假接收端，**When** 交给静态类型检查器判定，**Then** 判定通过，且判定不要求显式继承。
2. **Given** 该假接收端，**When** 运行时发出「span 开始」与「span 结束」，**Then** 两次回调均被收到且携带同一个运行标识（一次运行一个运行标识）。
3. **Given** 一个**缺少「当前 span」方法**的假接收端，**When** 做结构化子类型判定，**Then** 判定失败。
4. **Given** **未注入**接收端的一次运行，**When** 检查回调次数与外部可见行为，**Then** 回调次数为 0、无任何出站、行为与注入前完全一致。

### User Story 3 - 图结构可被外部读取与绘制 (Priority: P3)

作为用户，我希望能拿到一个**自有类型**的图结构对象（节点 + 边），以便我自己渲染图、
生成文档配图或对图结构做结构断言（例如在 CI 里断言「3 个节点、2 条边」）——以便我不必
为了看一眼图结构就把 LangChain 家族拖进依赖树。

**Why this priority**: 图结构类型是本项目**唯一必须"重写而非复用"**的 LangChain 特有件；
复用即把 `langchain-core` → `langsmith` 拖回依赖树，直接破红线。

3. **Given** 一个只装了 freegraph 基础包的环境，**When** 导入契约层并使用三项协议，**Then** 导入成功、依赖闭包为空集、无任何副作用。

### Edge Cases

- **`Node` 一词的归属（已裁定）**：节点函数协议与图结构节点元素曾同名。现裁定：
  **图结构节点元素 = `Node` / `Edge`**（B22F1 依赖其名），**节点函数协议 = `NodeFunc`**。
  → 公开符号面 MUST NOT 出现第二个 `Node` 含义；后续 feature MUST NOT 复用 `NodeFunc`
  指代别的概念。
- **协议名只有名字、没有签名细节**：本 feature MUST 冻结到**「方法名 + 语义 + 参数名 +
  最小约束」级**（**方法名与参数名已冻结**——协议签名不写死参数名即无法实现；返回类型 /
  载荷 / 命名空间载体等**未冻结部分的粒度按协议分别裁定**，见各协议的 FR 与 Clarifications）——
  否则「契约冻结」名不副实；但**不实现任何方法体**——协议全是抽象方法，导入契约层
  不产生任何行为。
- **协议带默认实现 vs 纯抽象**：若为协议方法提供默认实现，则「实现方只声明部分方法」
  会静默通过结构化子类型判定，掩盖缺实现——本 feature 采用**纯抽象**（无默认实现）。
- **结构化子类型判定的宽松性**：结构化子类型判定只比对**方法名是否存在**，不比对签名
  ——因此「缺一个方法」必须判失败、「签名写错」判不出来。后者由静态类型检查承担
  （见 User Story 1 / 2 的独立验收）。
- **图的节点集合与边集合的元素类型**：MUST 是本层定义的纯数据类；
  MUST NOT 是「外部库的结构类型」——否则等于把依赖拖回来。
- **图结构数据类承载「节点别名」**：节点名唯一（C25），别名是**附加显示信息**，
  MUST NOT 与节点名互相覆盖；别名缺省时的可判定语义 MUST 明确（缺省 = 与节点名同值）。
- **条件边的信息承载**：条件边 MUST 能表达「这是条件边」以及条件信息；
  普通边与条件边 MUST 可区分——否则上层无法渲染分支。
- **未注入可观测接收端**：协议面 MUST NOT 引入「默认实现一个空接收端」的做法
  ——那是行为，属 B19F1；本 feature 只保证「不注入即无回调、无出站」。
- **检查点协议与「检查点标识」**：C23 要求 span 必带「检查点标识」，故检查点协议的
  读写面 MUST 能承载该标识；但其**具体载体形状**在本 feature 只冻结「是纯数据」，
  细化归 B14F1（见 Assumptions）。
- **单次运行标识由谁生成**：MUST 由运行时层生成，**MUST NOT** 进运行配置的字段清单
  （C22 · D11 已冻结）——因此本 feature MUST NOT 往运行配置上加任何字段。
- **「会话标识」缺省**：会话标识可为空（未指定会话）；单次运行标识 MUST NOT 为空。
- **span 的父子关系与 JSON 可序列化**：span 的 `parent` MUST 是**父 span 的标识（字符串）**
  而非对象引用——否则 C27 的「请求 / 返回结构 MUST JSON 可序列化」落不了地，
  嵌套调用树也须靠标识而非对象引用还原。
- **span 的时间字段形态**：起止时刻 MUST 用 **UTC 的 ISO-8601 字符串**（与
  `StateSnapshot.created_at` 同口径），避免各生产者各写各的格式导致时间线排序出错。
- **trace 存储与查询协议的方法体**：本 feature **不**定义该协议（Q3 裁定），
  实现与协议面归 B20F1 / B20F2；本 feature 只交付其请求 / 返回的**纯数据结构**。
- **协议层读环境变量**：契约层 MUST NOT 读任何环境变量（`LANGSMITH_*` / `LANGCHAIN_*` 等），
  MUST NOT 发起任何出站请求。
- **协议层 import 内部模块**：契约层内部相对导入合法；指向顶层 `freegraph` 或包外
  `freegraph.*` 的导入 MUST NOT 出现（B1F1 已定的口径，本 feature 沿用）。
- **同名第三方包劫持**：契约层的公开符号 MUST 使用包内绝对解析（`from .x import y`），
  MUST NOT 被环境中的同名字符串劫持。
- **下游拿到协议后想扩展**：协议**不提供**基类继承链（架构纪律 PD-1）——扩展靠组合
  或结构化子类型判定，不靠继承。
- **查询一个从未跑过的会话的状态**：`get_state` MUST 返回**空值语义**（空快照），
  MUST NOT 抛异常（Q8 裁定）——用户脚本不必到处兜异常；「空快照」的字段取值规则由
  B15F1 细化，但「不抛异常」这一条本 feature 已冻结。
- **`update_state` 写入的归属节点名不合法**（指向不存在的节点）：本 feature 只冻结
  「接受『待写入值 + 归属节点名』」这一形状，**校验规则归 B16F1**。
- **接收端在开始时把 span 存进列表，事后想补结束时刻**：MUST NOT 依赖「回头改那个对象」
  ——`Span` 不可变（Q9），结束时刻在**同 `id` 的新实例**上；接收端若需要完整记录，
  应在结束回调时用新实例覆盖或另存（按 `id` 配对）。
- **想把节点或 span 放进 `set` 去重**：MUST 失败（不可哈希，Q12）——用户须按
  `id` / `node` 等标识字段自行去重（例如 `{n.id for n in graph.nodes}`）。

### Functional Requirements

- **FR-001**: 系统 MUST 以**协议**（标准库的类型协议机制）定义**节点函数协议 `NodeFunc`** ——
  节点函数契约：`Callable[[StateDict], StateDict | Command | list[Command | StateDict] | None]`
  （入参为稀疏状态字典，返回部分状态字典 / 命令原语 / **命令列表** / 空值）。协议 MUST 支持**运行时结构化子类型判定**，
  用户无需显式继承即可满足。
  > **命名裁定（Q1）**：节点函数协议名为 **`NodeFunc`**；`Node` 一词专指**图结构节点元素**。
  > **⚠️ 回溯修订（2026-11-11 · B9F1 · 发起者特批 · 破 L1 冻结面）**：原口径为
  > `StateDict | Command | None`（**三形态**）⇒ **增补「命令列表」**（`list[Command | StateDict]`）
  > ⇒ **四形态**。**理由**：① 上游 LangGraph 的 `ToolNode` **自身即返回命令列表**
  > （多个工具各返回一个 `Command` ⇒ 汇总成列表返回 · `prebuilt/tool_node.py:890-920` 实测）
  > ⇒ freegraph **须与上游同款**；② 「命令列表」**不引入写者竞争**（一个节点的产出 · 按**列表顺序**
  > 串行生效）且**覆盖型通道的同轮重复写显式失败**（`InvalidChannelUpdateError`；上游同款：
  > `last_value.py:56-64` 的 `INVALID_CONCURRENT_GRAPH_UPDATE`）⇒ 语义**安全且可复现**；
  > ③ 协议 MUST 与运行时**一致**（否则「用 `NodeFunc` 标注的节点」在**类型层**无法表达列表返回）。
  > **不变**：C5 / C6 的**条目本身**（Q8 §3.4 为唯一权威）**一字未动**；变更的只是
  > `NodeFunc.__call__` 的**承载签名** ⇒ **G7 / G8 恒绿**（符号**集合**与**数量**不变）。

- **FR-002**: 系统 MUST 以协议定义**检查点协议 `Checkpointer`** —— 方法集合恰为
  `get_tuple` / `list` / `put` / `put_writes` / `delete_thread` / `get_next_version`
  （快照取回 / 历史列举 / 快照写入 / 待写入数据写入 / 会话删除 / 版本号生成）。
  MUST 支持运行时结构化子类型判定。MUST 只定义**类型与语义**，MUST NOT 提供任何方法体。
  **冻结粒度（Q5 裁定 · 2026-11-06 复核修订）**：本 feature 冻结**方法名 + 语义 + 参数名 +
  最小约束** ——
  ① 方法集合**恰为**上述六个（不多不少）；② **方法名与参数名逐字按 `data-model.md` §2.2
  冻结**（`get_tuple` / `list` / `put` / `put_writes` / `delete_thread` / `get_next_version`；
  首参名 `config`、类型 `RunConfig`；`delete_thread` 的参数名 `thread_id`、类型 `str`）——

  都需要确切签名）；③ **返回结构与快照 / 待写入数据的载荷形状挂起 B14F1** 细化（本 feature
  MUST NOT 为其新增专属载荷数据类）；④ 读写面 MUST 能承载**检查点标识**

- **FR-003**: 系统 MUST 以协议定义**可观测接收端协议 `TraceSink`** —— 方法集合恰为

  ① 方法集合**恰为**上述六个；② **方法名与参数名逐字按 `data-model.md` §2.4 冻结**

- **FR-005**: 系统 MUST 定义**编译产物协议 `CompiledGraph`** —— 编译产物的对外能力面

  MUST 支持运行时结构化子类型判定。
  **冻结粒度与返回类别（Q8 裁定）**：本 feature 冻结**方法名 + 语义 + 返回类别
  + 参数名（占位名）** ——
  ① `invoke` → **完整状态字典**；  ② `stream` → **事件迭代器**（**元素类型 = `dict[str, Any]`**（纯数据字典）；**mode 取值为字符串

  下游确需改参数名者 MUST 走**契约修订**流程，MUST NOT 就地改型。

- **FR-006**: 系统 MUST 定义**图结构数据类** —— `Graph`（图）/ `Node`（图节点元素）/
  `Edge`（边元素）。MUST 是**纯数据类**（不可变记录 + 字段级相等语义），MUST NOT 复用

  **类型名 MUST 恰为 `Graph` / `Node` / `Edge`**（B22F1 的 SC-004 已按此写死）。
  **字段清单 MUST 逐字冻结为**（Q4 裁定）：
  - `Graph.nodes: tuple[Node, ...]`（节点集合）/ `Graph.edges: tuple[Edge, ...]`（边集合）
    —— **不可变元组**，元素为本层定义的纯数据类；
  - `Node.id: str`（**节点名**，唯一）/ `Node.name: str | None = None`（**别名**，缺省
    **归一为 `id`**——构造后恒为字符串）/ `Node.metadata: Mapping[str, Any]`（可选附加信息，
    可为空映射；构造期**浅拷贝**）；
  - `Edge.source: str`（起点节点名）/ `Edge.target: str`（终点节点名）/
    `Edge.conditional: bool`（是否条件边）/ `Edge.condition: str | None`（条件名，
    非条件边时为空）。
  MUST NOT 引入承载**对象引用**的字段（如上游的 `data`——纯数据纪律）。
  **相等与哈希语义（Q12 裁定）**：MUST 保证**字段级相等**（同字段值 → 相等）；
  MUST **不可哈希**（放入 `set` / 作字典键 MUST 失败）——`Node` / `Span` 因**含映射字段**，
  `Graph` 因**元素不可哈希**；**`Edge` 四字段全为标量**，dataclass 会自动生成 `__hash__`，
  故 MUST 靠**类体显式 `__hash__ = None`** 达成不可哈希（依据见 `data-model.md` §4.3）；
  用户按 `id` 等标识自行去重。

- **FR-007**: **全部**协议 MUST 支持运行时结构化子类型判定（`runtime_checkable` 语义），
  以便用户无需显式继承即可满足协议；且协议 MUST 为**纯抽象**（MUST NOT 提供会掩盖
  「缺实现」的默认方法体）。
  > **方法集的判定口径**：方法集合以**集合相等**判定；**MUST NOT** 把「成员的**定义顺序**」
  > 纳入冻结面——`typing.Protocol` 的成员集合是 `set`（CPython 3.11 / 3.12 实测：
  > `{'c','b','a'}`），其迭代顺序随 `PYTHONHASHSEED` 变化 ⇒ 按序断言必然 flaky。

- **FR-008**: 契约层 MUST NOT import 任何 freegraph 内部模块（运行时 / 图定义 / 持久化 /
  可观测等）；MUST NOT import `langchain` / `langchain-core` / `langgraph*` / `langsmith`。
  包**内部**相对导入合法（沿用 B1F1 口径）。

  （span 列表）；③ 请求与返回结构 MUST **JSON 可序列化**（纯数据，不含不可序列化
  对象）；④ **「存储与查询 MUST 经由同一协议、后端可替换」**这一约束 MUST 以文字形式
  记入冻结记录与冻结对照表（协议面**挂起**，归 **B20F1**）；⑤ 表结构 / 文件格式 MUST
  视为**内部实现细节**（对外只暴露查询面）。

  > ——协议面此刻定死，后续 feature 增多导致要改即是大面积返工。

### Key Entities

- **节点函数协议（`NodeFunc`）**: 节点函数的契约 —— `f(state) -> 部分状态 | 命令原语 | 空值`；
  协议面（鸭子类型）由执行内核消费；对应契约 C5 / C6；**命名经 Q1 裁定**
  （`Node` 专指图结构节点元素）。
- **检查点协议（`Checkpointer`）**: 快照 + 历史 + 待写入数据的持久化面；
  六个方法（`get_tuple` / `list` / `put` / `put_writes` / `delete_thread` /
  `get_next_version`）；对应契约 C19；实现归 B14F1（内存）/ B15F1（SQLite）。
- **可观测接收端协议（`TraceSink`）**: span 推送接收端（回调式，非拉取式）；
  三个方法（`on_span_start` / `on_span_end` / `current_span`）；对应契约 C23 / C24；
  接入归 B19F1。
- **长期存储协议（`Store`）**: 按「(命名空间, 键)」寻址的长期记忆面；六个方法
  （`get` / `search` / `put` / `delete` / `list_namespaces` / `batch`）；
  命名空间 = **层级路径**、取值 = **纯映射**（具体载体形态挂起 v2 · Q7）；
  对应契约 C20；**v1 只定义协议、无实现**。
- **编译产物协议（`CompiledGraph`）**: 编译产物的对外能力面；六个方法
  （`invoke` / `stream` / `get_graph` / `get_state` / `get_state_history` /
  `update_state`）；返回类别已冻结（Q8）——完整状态字典 / 事件迭代器 / 图结构 /
  状态快照 ×3；对应契约 C10 / C11 / C12 / C13。
- **图结构数据类（`Graph` / `Node` / `Edge`）**: 图结构的自有类型 —— 字段清单逐字冻结
  （Q4）：`Graph.nodes: tuple[Node, ...]` / `Graph.edges: tuple[Edge, ...]`；
  `Node.id`（节点名）/ `Node.name`（别名，缺省归一为 id）/ `Node.metadata`；
  `Edge.source` / `Edge.target` / `Edge.conditional` / `Edge.condition`（条件名）；
  对应契约 C13 / C14 / C15 / C25；**必须自有重写**，不得复用外部库类型；
  **不得有承载对象引用的字段**（上游的 `data` 被砍）；**不可哈希**（Q12）。
- **span 类型（`Span`）**: 可观测事件的数据载体 —— **11 字段逐字冻结**（Q6）：
  `id` / `name` / `attributes` / `parent`（父 span 的 id）/ `start_time` / `end_time` /
  `context` + **必带四项** `thread_id` / `run_id` / `node`（节点名）/ `checkpoint_id`；
  **不可变记录**（Q9）——结束由「同 id 的新实例」承载，两次回调按 `id` 配对；
  **不可哈希**（Q12），只保证字段级相等；
  对应契约 C23 / C24 与数据格式 DF4；**类型面经 Q2 裁定归本 feature**，生产行为归 B18F1。
- **trace 查询请求结构（`TraceQuery`）**: C27 的请求载体 —— **5 字段逐字冻结**（Q11）：
  `run_id` / `thread_id` / `node` / `start_time` / `end_time`（时间范围，UTC ISO-8601
  字符串）；全部可空、可组合，全空 = 取全部；MUST JSON 可序列化。
- **trace 查询结果结构**: C27 的返回载体 —— span 列表（有序集合），MUST JSON 可序列化。
- **会话标识 / 单次运行标识**: 两级标识 —— 会话级（由运行配置承载、用户可指定）/
  运行级（由运行时生成、用户 MUST NOT 指定或覆盖、一次运行一个）；对应契约 C22 /
  C23 字段约定（D11 已冻结）。
