# Feature Specification: B7F4 · 多源汇合边（AND / 屏障）

**Feature Branch**: `b7f4-multisource-join`

**Created**: 2026-11-13

**Status**: Draft

**Input**: User description: "B7F4 · 多源汇合边（AND / 屏障）—— 让**调度内核**能表达并正确执行「**多源汇合边**」：一条边的**源是多个节点**、目标是**一个**节点，且目标 MUST 等到「**该边的所有**源都跑过」才被触发（**AND / 屏障**语义）⇒ ⚠️ **组内全 · 组间任一**：一个节点同时有「单源入边」与「多源入边」时，**任一**入边满足即触发（**上游同款** · 实测 **E-3** · 澄清轮 **C-Q1** / 裁定 3 ⇒ 见 **FR-003**）。上游 `langgraph` 的 `StateGraph.add_edge([a, b], c)` 早已支持该形态；freegraph 的 `GraphSpec.edges` 是 `dict[str, tuple[str, ...]]`（**源只能是单个节点名**）⇒ **不可表达** ⇒ 本 feature 补齐这个**能力缺口**。实现路线 = **在触发层实现，不新增通道类型**（多源边的语义 = 「所有源的版本 > 各自的 `seen`」）⇒ 与上游的屏障通道**可观察行为等价** ⇒ **不破** B5F1 的通道冻结面 ⇒ **零新增**导出符号。⚠️ 本 feature **破 B7F1 的冻结面**（**发起者已于 2026-11-12 明确同意**）：B7F1 契约 §1 / §3.1 / §3.2 / §4 / §5 / §7（I-12）· B7F1 的 `spec.md`（FR-002 / FR-013 / Edge Cases）· `data-model.md`（V-2）· 以及 B7F1 的**冻结断言** ⇒ MUST **回溯修订**（**既有断言一条不删 ⇒ 拆分**为「单源口径」与「多源口径」两族）⇒ MUST 落**发起者追认**（追认文字落 `harness/verification/B7F4/manual-verification.md`）。"

- **Q4**：多源边的判定式到底是「**所有**源都跑过才触发」（提示词字面），还是「**每条入边各成一组 · 组内全 · 组间任一**」（上游实测）？
  → **A**（**上游实测口径**）：上游把**单源边**与**多源边**做成**两个不同的触发通道** ⇒
  目标节点的触发集合是**通道的并集** ⇒ **任一**通道可用即触发 ⇒ ⇒ **组间是「任一」**。
  ⇒ **实测 E-3**：目标节点同时有「单源入边」与「多源入边（其中一源永不可达）」⇒
  **上游仍然执行了目标节点**（`{'msgs': ['a','b','c']}`）⇒ ⇒ 若按提示词字面（「所有源都跑过」）实现 ⇒ **与上游不一致** ⇒
  ⇒ 依原则 XI ① MUST **照抄上游** ⇒ 落点：FR-003 · 裁定 3 · 差分 **D-18** · 语义点 **P-06**。
- **Q5**：屏障被消费（`seen` 记账）的**范围** —— 消费**全部**触发源，还是只消费**本次满足的那一组**？

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 两个并行分支汇合到一个下游（Priority: P1）

作为用户，我的图里有 `a`、`b` 两个并行分支（例如「两路检索都回来再汇总」），
它们**都完成后**才能进入 `c` ⇒ 我希望上游代码里的 `add_edge(["a", "b"], "c")`
在 freegraph 里**原样可用**（不必拆成「中间节点 + 条件边」的手工绕行）。

**Why this priority**: 这是本 feature 的**能力缺口本体** —— 上游早已支持、freegraph **不可表达** ⇒
不补齐则「从上游迁移」在**最常见的并行汇合**处就会卡住 ⇒ ⇒ **P1**。

**Independent Test**: 构造一张含多源汇合边的图并跑到底 ⇒ 断言「`c` 的执行**严格晚于** `a` 与 `b`」
⇒ **不依赖**其他 feature ⇒ 可**独立**验收。

**Acceptance Scenarios**:

1. **Given** 一个含 `a`、`b`、`c` 三个节点、`a` 与 `b` 都可达、且 `("a","b")` 汇合到 `c` 的图，
   **When** 跑完整张图，**Then** `c` **执行一次**且**严格晚于** `a` 与 `b`（两者都完成后才跑）。
2. **Given** 同一张图，**When** 以**串行**方式跑（一个节点一个节点地跑），
   **Then** 结果与并发档**逐字一致**（屏障语义与并发无关）。
3. **Given** `a` 与 `b` 在**同一轮**里都被触发，**When** 该轮结束，
   **Then** `c` 在**下一轮**被触发（屏障的合取在**下一轮**判定 · 与普通边同款）。

### User Story 2 - 屏障没齐时下游静默等待（Priority: P2）

作为用户，我希望「**屏障没齐**」时下游**静默等待**（而不是提前跑、也不是直接报错）——
因为「某个源本轮还没跑到」是**正常的调度中间态**，不是错误。

**Why this priority**: 屏障最常见的**误用**就是「把『还没齐』当成『永远不会齐』」⇒
必须证明「不齐 ⇒ 不跑 + 不抛错 + 图正常收敛」⇒ ⇒ **P2**。

**Independent Test**: 造一张「屏障的某个源**永不可达**」的图 ⇒ 断言「屏障目标的执行计数 == 0」
且「整张图**正常收敛**、**不抛错**」⇒ **独立**验收。
⚠️ **前置限定（澄清轮 C-Q1 的直接推论）**：该屏障目标 MUST **只有**这一条多源入边 ⇒
否则按「**组间任一**」的口径，它仍会被**别的**入边触发（见 Edge Cases「单源边与屏障边并存」）。

**Acceptance Scenarios**:

1. **Given** 一张含多源汇合边的图，其中**一个源不可达**（无入边）、且该目标**没有别的入边**，
   **When** 跑完整张图，**Then** 屏障目标的**执行计数 == 0**。
2. **Given** 同一张图，**When** 跑完整张图，**Then** 图**正常收敛**（**不抛错** · 不报「屏障未齐」之类的错）。
3. **Given** 一个**只由屏障**触发、且屏障**齐了**的目标节点，
   **When** 它的某个源**没有**可写通道（入参为空 `dict`），
   **Then** 它**照常执行**（屏障只看「**源跑过**」，不看「源写了什么」）。

作为维护者，我希望屏障语义与上游 `add_edge([a,b], c)` **逐字同款**，

2. **Given** 一张「单源边 + 屏障边并存、屏障不齐」的图，**When** 对跑两侧，

3. **Given** 差分探针的**屏障场景组**，**When** 在 CI 的 **Linux 全量档**真跑，

### Edge Cases

- **源缺失**：多源边的**某个**源不在节点表里 ⇒ **构造期**显式失败（内置 `ValueError`）⇒
  MUST **点名**缺失的源名 ⇒ **零新增**错误类型。
- **源重复**：多源边的元组里**重复**写了同一个源（`("a","a")`）⇒ MUST **去重**（保序）⇒
  去重后只剩一个源 ⇒ 等价于**单源**口径（行为一致）⇒ MUST NOT 因此报错。
- **源为空**：多源边的元组**为空**（`()`）⇒ **构造期**显式失败（内置 `ValueError`）⇒
  （上游是「**静默永不触发**」⇒ freegraph **比上游更严** ⇒ 登记 **X-02**）。
- **入口哨兵参与屏障**：多源边的元组里含 `__start__` ⇒ **构造期**显式失败（内置 `ValueError`）⇒
  （上游**同样显式失败** ⇒ 同族）。
- **多源边指向 `__end__`**：多源边的目标是**入口终止哨兵** `__end__` ⇒ **构造期**显式失败
  （内置 `ValueError` · **V-16**）⇒ （上游 `add_edge(["a","b"], END)` ⇒ **被接受但静默 no-op**
  ⇒ 目标**从未执行** · **不报错** ⇒ freegraph **比上游更严** ⇒ 登记 **X-04** · 澄清轮 **C-Q9**）。
- **边键类型非法**：边键**既非 `str` 亦非 `tuple`**（如 `123`）⇒ **构造期**显式失败
  （内置 **`TypeError`** · **FR-021**）⇒ （上游 `add_edge(123, "a")` ⇒ **同族** `TypeError` ⇒ 同族）。
- **多源边的目标数 ≠ 1**：多源边指向**多个**目标 ⇒ **构造期**显式失败（内置 `ValueError`）⇒
  （上游 `add_edge(starts, end)` 只有**一个**目标 ⇒ 照抄形态）。
- **单源边与屏障边并存于同一目标**：目标既有「单源入边」又有「多源入边」⇒
  **任一**入边满足即触发（**组间任一** · 上游同款）⇒ ⇒ **实测 E-3**：屏障不齐也会跑。
- **屏障后齐**：目标先因**单源边**跑过一次，之后屏障的最后一个源才跑 ⇒
  目标**再跑一次**（上游同款 · **实测 E-5**）⇒ ⇒ 「消费口径」MUST 只消费**已满足的组**。
- **同一轮内至多触发一次**：屏障目标在同一轮内 MUST 至多被触发 **1** 次（与既有「一轮内至多一次」同族）。
- **源的入参为空**：源节点**不订阅任何通道**（入参是空 `dict`）⇒ 它**照样算「跑过」**⇒
  屏障的合取只看「**跑过**」，不看「写了什么」。
- **屏障目标自己也是某个源的祖先**：图里有环（`("a","b") → c` 且 `c → a`）⇒
  屏障语义照常判定（触发判定是**逐轮**的 · 不做环检测）⇒ 收敛性由既有的**步数上限**兜底。
- **多源边指向不存在的目标**：目标不在节点表里 ⇒ **构造期**显式失败（内置 `ValueError` · **V-2** 同族）
  ⇒ **归 `V-2`**（**NOT** `V-16` · 澄清轮 **C-Q18**）⇒ ⇒ **MUST 点名**该目标
  ⇒ ⇒ 校验顺序：形态 `V-16` **先于** 缺源 / 缺目标 `V-2`（**C-Q15** 同款）。
- **元组键的**顺序**：元组里源的**书写顺序 MUST NOT** 影响语义（AND 是**无序合取**）⇒
  `("a","b")` 与 `("b","a")` **行为逐字一致**。

  同款）⇒ ⇒ **上游同族**（`TypeError` · **实测 E-10**）⇒ ⇒ **零新增**错误类型（澄清轮 **C-Q10**）。
