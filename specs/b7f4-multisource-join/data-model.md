## 2. 图规格（`GraphSpec`）—— **边表**

### 2.1 边表的**形态**

```text
edges : dict[str | tuple[str, ...], tuple[str, ...]]
          │              │                │
          │              │                └── 目标节点名序列（**保序**）
          │              └── 源：**单个**节点名（`str`）**或** **多个**节点名（`tuple`）
          └── 源：**单个**节点名（`str`）
```

| 键的形态 | 语义 | 目标的个数 | 触发语义 |
|---|---|---|---|
| `"a"`（**单源**） | 普通边 | **任意个**（**既有行为不变**） | 组 = **单元素** ⇒ ∃ 组即「**任一**源越过 `seen`」 |
| `("a", "b")`（**多源**） | **AND / 屏障**边 | **恰为一个**（V-16）**且 MUST NOT 为 `__end__`**（V-16 · **X-04**） | 组 = **两个元素** ⇒ ∃ 组即「**所有**源越过 `seen`」 |

> ⚠️ **单源边的写法逐字不变**（裁定 1）⇒ **既有调用方零改动**（FR-001）。

### 2.2 多源边的**规范化**（**不在构造期改写用户的 `dict`**）

| 输入 | 规范化后的**源序列** | 说明 |
|---|---|---|
| `("a", "b")` | `("a", "b")` | 原样（保序） |
| `("b", "a")` | `("b", "a")` | **顺序保留** ⇒ 但语义与 `("a","b")` **逐字一致**（组内合取**无序** · 语义点 P-14） |
| `("a", "a")` | `("a",)` | **去重保序**（裁定 2 · 与上游 `set(starts)` 同款）⇒ 等价**单源口径** |
| `()` | —— | **V-16**（构造期显式失败 · 澄清轮 C-Q6） |
| `("__start__", "b")` | —— | **V-16**（构造期显式失败 · 澄清轮 C-Q3 · 上游 E-7 同族） |
| `("a", "b")` → 目标 `__end__` | —— | **V-16**（构造期显式失败 · 澄清轮 **C-Q9** · 上游 **E-9** 静默 no-op ⇒ **更严** · **X-04**） |

> ⚠️ **规范化发生在「触发源枚举」期**（**不改写**用户的 `edges`）⇒ `GraphSpec` 的**字段不可改写**
> 口径（data-model §1）**零破**（research **DR-4**）。

### 2.3 边表的**校验规则**（**构造期显式失败**）

| 编号 | 场景 | 失败信号 | 消息要求 | 依据 |
|---|---|---|---|---|
| **V-2**（**扩展**） | 边的**源**不在节点表里（**多源边的每个源**都查） | 内置 **`ValueError`** | **点名**（**全部**）缺失的源名 | FR-002 · 裁定 8 · 上游 E-8 同族 |
| **V-2**（**扩展** · 澄清轮 **C-Q18**） | **多源边的目标**不在节点表里 | 内置 **`ValueError`** | **点名该目标** | FR-002（追加）· 裁定 8（追加） |
| **V-2**（不变 · 澄清轮 **C-Q18**） | 边的**目标**不在节点表里（**含多源边的目标** · 与契约 §2.2 **同口径**） | 内置 **`ValueError`** | 点名目标 | B7F1 既有 |
| **V-2**（不变） | 单源边的**源**不在节点表里（**入口哨兵 `__start__` 豁免**） | 内置 **`ValueError`** | 点名源 | B7F1 既有 |
| **V-16**（**新增**） | 多源边的**元组为空** | 内置 **`ValueError`** | 点名该边 | FR-017 · 裁定 6 · **X-02**（比上游更严 · 上游 E-6 静默） |
| **V-16**（**新增**） | 多源边的**元组含 `__start__`** | 内置 **`ValueError`** | 点名该边 | FR-017 · 裁定 7 · 上游 E-7 同族 |
| **V-16**（**新增**） | 多源边的**目标数 ≠ 1** | 内置 **`ValueError`** | 点名该边 | FR-017 · 裁定 5 · 上游 `state.py:1551` 同款 |
| **V-16**（**新增**） | 多源边的**目标为 `__end__`** | 内置 **`ValueError`** | 点名该边 | FR-017 · 澄清轮 **C-Q9** · 语义点 **P-15** · 上游 **E-9** 静默 no-op ⇒ **更严** · **X-04** |
| （**类型**，非 V 编号） | 边键**既非 `str` 亦非 `tuple`** | 内置 **`TypeError`** | 点名键的类型 | **FR-021** · 裁定 17 · 语义点 **P-16**（上游 **E-10** 同族 ⇒ 照抄）· research **DR-5** |

> ⚠️ **失败信号 MUST 逐条唯一**：同一场景出现两种异常类型的次数 MUST == **0**。
> ⚠️ **类型问题 ⇒ `TypeError`；语义问题 ⇒ `ValueError`** ⇒ **零新增错误类型**（B7F1 契约 §2.1.1 不变式）。
> ⚠️ **校验的**优先级**（澄清轮 **C-Q15** · 发起者 2026-11-13 拍板）**：
> **形态校验（`V-16`）MUST 先于缺源 / 缺目标校验（`V-2`）** ⇒ ⇒ 元组同时命中两者时
> （典型 = 元组含 `__start__`）⇒ **归 `V-16`** ⇒ ⇒ 失败信号仍是内置 `ValueError`
> ⇒ ⇒ 差异**只在错误消息**（⇒ 测试断言 MUST 只断言**异常类型**与**点名**，**MUST NOT** 断言消息的逐字文本）。
> ⚠️ **追加（澄清轮 **C-Q18**）**：**多源边的「目标不在节点表」归 `V-2`**（语义校验族 · 与源缺失**同族**）
> ⇒ ⇒ **NOT** 归 `V-16`（形态校验族）⇒ ⇒ 校验顺序与上条**同款**（形态 `V-16` **先于** `V-2`）。

## 3. 触发源组（**本 feature 的新概念**）

### 3.1 定义

```text
groups(N) = 每条指向 N 的入边各成一个组
             · 单源边  "a"   → N   ⇒ 组 = (("e", "a"),)
             · 多源边  ("a","b") → N ⇒ 组 = (("e", "a"), ("e", "b"))
             · 动态边  "a" → N（`Command.goto`）⇒ 组 = (("e", "a"),)
```

| 属性 | 口径 |
|---|---|
| **组的单位** | **每条入边一个组**（不是「每个源一个组」）⇒ 组的**成员**才是触发源<br>⚠️ **补充（澄清轮 **C-Q16**）**：**同成员的多条边合成一组**（见下方「组的去重」· research **DR-3**）⇒ ⇒ 「每条入边一个组」是**枚举期**的口径，**去重后**才是 `groups(N)` 的内容 |
| **组的来源** | 静态边 ∪ 动态边（**同处一个空间** · B7F1 契约 §3.1） |
| **组的去重** | 按**成员集合**（`frozenset`）去重（**保序**）⇒ 同成员的两条边合成一组（research **DR-3**）<br>⚠️ **与上游的对照（2026-11-13 · 实测 E-11 · 旧附注已被证伪 · 本行为面零分叉）**：上游把顺序写进 **join 通道名** ⇒ 两条边**同时存在**时是两个不同通道 ⇒ **但上游的触发汇总按**节点**去重**（`triggered_nodes: set[str]` · `_algo.py:476-482`）⇒ ⇒ **上游同样只触发 1 次** ⇒ ⇒ freegraph 的「按成员集合去重 ⇒ 合并为一组 ⇒ 触发一次」**与上游逐字同款** ⇒ ⇒ **无需偏离登记** ⇒ ⇒ 以**差分场景 D-27** 锁住（防回归） |
| **组的顺序** | **边表的声明顺序**（静态在前 · 动态在后）⇒ 记账顺序**可复现** |
| **动态边** | **恒为单元素组**（`Command.goto` 指向**一个**节点名 · 裁定 11） |

### 3.2 组的**判定**（**组内全 · 组间任一**）

```text
节点 N 被触发 ⟺ ∃ 组 g ∈ groups(N) : ∀ s ∈ g : version(s) > seen(N)[s]
```

| 情形 | 判定式 | 退化 |
|---|---|---|
| **单源边**（组 = 单元素） | `∃ g : version(s) > seen(s)` | **逐字退化**为 B7F1 的旧判定式（**零行为变化**） |
| **多源边**（组 = N 个元素） | `∀ s ∈ g : version(s) > seen(s)` | **屏障**语义（**上游同款** · E-1 / E-2） |
| **单源 + 多源并存** | `∃` 两个组 ⇒ **任一**满足即触发 | **上游同款**（E-3 / E-4 · 澄清轮 C-Q1） |

> ⚠️ **`seen(N)[s]`** = `SchedulerState.versions_seen[N][("e", 源节点名)]`（**逐源各一条** · 裁定 10）。
> ⚠️ **入口哨兵 `__start__`** 的版本**恒为 1**（B7F1 契约 §3.1）⇒ 它**不能**出现在多源组里（V-16）。
> ⚠️ **入口终止哨兵 `__end__`** 在 freegraph 里**不是节点**（只作 `Command.goto` 的目标）⇒
> ⇒ 它**不能**作为多源边的**目标**（**V-16** · 澄清轮 **C-Q9** ⇒ **比上游更严** · **X-04**）。

## 4. 已消费版本（`seen`）—— **逐源各一条 · 只记已满足的组**

### 4.1 记账规则

| 时点 | 记账范围 | 依据 |
|---|---|---|
| 节点 N 被**准备执行**时 | **只记「已满足的组」的成员**（每个成员一条 `seen[(kind, ident)] = version(ident)`） | FR-004 · 裁定 4 · 上游 E-5 同款 |
| **未满足的组** | **不记** ⇒ 屏障后来齐了**仍能再次触发** | 语义点 **P-08** · E-5 |

### 4.2 单源口径的**等价性**（**SC-005** 的机械依据）

```text
单源边 ⇒ 组 = 单元素 g = {s}
  · 已满足 ⟺ version(s) > seen(s) ⇒ 记账后 seen(s) = version(s)      （与旧口径**逐字一致**）
  · 未满足 ⟺ version(s) ≤ seen(s)
           ⇒ 版本**只增不减** ⇒ version(s) == seen(s)
           ⇒ 旧口径的「记 seen(s) = version(s)」是**同值记账**
           ⇒ **可观察行为零变化** ⇒ **既有断言一条不删**
```

> ⚠️ 这是「**破冻结面**但**不削弱判据**」的**核心论证**（宪法 v1.8.0）⇒ MUST 落进契约与人工验证记录。

### 4.3 `SchedulerState` —— **零改动**

| 字段 | 状态 |
|---|---|
| `versions_seen` | **结构不变**（节点名 → {触发源 → 版本}）⇒ 多源组的记账**逐源各一条** |
| `step` / `channel_versions` / `node_versions` / `dynamic_edges` / `channels` | **零改动** |

## 5. 一个 super-step 的状态机（**七阶段** · 沿用 B12F1 的口径）

> ⚠️ **阶段模型不变**（B12F1 契约 §3 · **七阶段**）⇒ 本 feature **只**改阶段 ① 与阶段 ② 的**触发口径**。

| # | 阶段 | 本 feature 的改动 |
|---|---|---|
| ① | **触发判定** | 「∃ 触发源」⇒「**∃ 组 g：∀ s∈g**」⇒ **顺序口径（节点名序）逐字不变** |
| ② | **任务准备** | 「消费**全部**触发源」⇒「消费**已满足的组**的源」⇒ **入参构造 / 原子性 / 顺序全部不变** |
| ③ | **并发执行** | **零改动**（B12F1） |
| ③′ | **判定与落回** | **零改动**（B12F1） |
| ④ | **写入收集** | **零改动** |
| ⑤ | **写入合并 + 步末清空** | **零改动** |
| ⑥ | **收尾** | **零改动** |

### 5.1 屏障的**轮次时序**（**典型三段式**）

```text
第 1 轮   a 执行（版本 a = 1）   b 执行（版本 b = 1）   c **未**被触发（屏障组未齐 / 或已齐但轮末才推进）
第 2 轮   c 被触发（组 {a,b}：version(a)=1 > seen(a)=0 且 version(b)=1 > seen(b)=0）⇒ c 执行
```

> ⚠️ **屏障在「最后一个源跑完」的**下一轮**判定**（与普通边**同款** · research **DR-8**）⇒
> ⇒ **两个源在同一轮并发跑**时，屏障在**下一轮**满足（**不是**同轮）。

### 5.2 「屏障后齐」的**二次触发**（上游 E-5 同款）

```text
第 1 轮   a 执行（版本 a = 1）  b 执行（版本 b = 1）
第 2 轮   c 被触发（组 {a} 满足）⇒ c 执行 ⇒ **只记组 {a}**（seen(a)=1；seen(b)=0）
第 2 轮   d 执行（版本 d = 1）  ⇒ 组 {b,d}：version(b)=1 > seen(b)=0 ✓ 且 version(d)=1 > seen(d)=0 ✓
第 3 轮   c **再次**被触发 ⇒ c 再执行一次（**上游同款** · E-5）
```
