## 2. 门禁定义（Gate）

**判定的权威**：`contracts/architecture-gates.md`（**冻结面**）。

| 字段 | 取值 | 说明 |
|---|---|---|
| **编号** | `G1`…`G30` | 唯一 · 连续 · **不可重开**（裁定 4） |
| **内容** | 一句话 | 判据的**人读**表述 |
| **判定方式** | 见契约 §1 | 判据的**机读**表述 |
| **范围（扫描域）** | 路径 / 目录 | MUST **显式**声明（MUST NOT 默认全仓） |
| **反向用例** | 有 / 无 | 8 条**强制** · 2 条**不强制**（裁定 14） |
| **执行环境** | 进程内 / 子进程 / 隔离 venv / 网络命名空间 | 需要隔离的 MUST **在隔离中执行** |
| **落点** | `harness/scripts/gates/gate_GNN_*.py` | **可独立执行** · 退出码即判定（FR-016） |

**状态机**（极简 —— 门禁只有两种终态）：

```
[未执行] ──执行──> [通过(退出码 0)] 
                └─> [失败(退出码 ≠ 0)] ──> [修复后重跑]
```

**无**「跳过」终态：G3 的 `skip` 是**既有**门禁的行为（判据零改动），
**新门禁 MUST NOT 引入 skip** —— FR-006 ② 明令「取不到许可证明 ⇒ 失败」。

## 3. 依赖闭包（Dependency Closure）

**定义**：某个 **extras 变体**下，freegraph 自身声明的依赖**递归展开**后的**全部包名**集合。

| 属性 | 规则 |
|---|---|
| **归一化** | 包名统一 **小写** + `_` → `-`（PEP 503 规范化） |
| **基础闭包** | 变体 = ∅（基础安装）⇒ MUST == **空集**（SC-002） |
| **全闭包** | 全部 **6** 个变体的**并集**（用于许可证判定） |
| **逐变体闭包** | 每个变体**单独**一份（用于黑名单判定 + 报错指名变体） |
| **展开深度** | **无上限**（递归到闭包末端）—— 间接引入的黑名单包 MUST 被抓出 |
| **传递依赖的 extras** | **不展开**（只取基础依赖）· [dependency-gate.md](./contracts/dependency-gate.md) §2.3 |

**关系**：

```
变体 V ──展开──> 闭包 C(V)
变体 V1 ∧ V2 ──合并──> C(V1 ∪ V2)
C(∅) = ∅                    ← 基础安装 MUST 为空集
C(V) ⊆ 全闭包
```

## 4. 许可证据（License Evidence）与 SPDX 表达式

### 4.1 许可证据

| 属性 | 规则 |
|---|---|
| **被检查的包集合** | **（依赖闭包中的包）∪（取证作用域根下扫到的 `*.dist-info` / `*.egg-info` 所对应的包）** —— **并集口径**（spec **裁定 25** / architecture-gates G23 📌 块）。MUST NOT 只查其中之一：只查闭包 ⇒ 注入的假元数据不可见（**反向用例空转**）；只查作用域根 ⇒ 正常路径**空门禁 ⇒ 违宪** |
| **证据读取顺序** | ① 取证作用域根下的 `<name>-<version>.dist-info/METADATA`（或 `.egg-info/PKG-INFO`）⇒ ② 该包**已安装**的元数据（`importlib.metadata`）—— **先到先得** |
| **来源** | 四级有序：`License-Expression` → `License` → `License ::` 分类器 → `dist-info/licenses/` 授权文件原文 |
| **取到即止** | 前一级命中即**采用**，MUST NOT 再往下取 |
| **取不到** | 四级全无 ⇒ **违规**（判失败并**指名**该包）· FR-006 ② |
| **规范化** | 交给 SPDX 解析器（`packaging.licenses`）—— **不得**用子串匹配 |

### 4.2 SPDX 表达式

| 规则 | 说明 |
|---|---|
| **叶子判定** | 表达式的**每一个叶子标识符** MUST ∈ 白名单 {MIT, Apache-2.0, BSD-2-Clause, BSD-3-Clause, PSF-2.0} |
| **运算符** | `AND` / `OR` / `WITH` / 括号 —— 由 `packaging.licenses` 解析（**不得**手工切分） |
| **解析失败** | 非 SPDX 的散文式名称 ⇒ **判失败**（`protobuf` 的 `3-Clause BSD License` 即此例） |
| **禁用名单** | 叶子命中 Elastic-2.0 / AGPL / SSPL / BUSL / GPL / MPL / LGPL ⇒ **失败**（点名报出） |
| **点名名单** | `langgraph-api` / `langgraph-runtime-inmem` / `phoenix` ⇒ **即使许可证合规也拒** |

## 5. 层条目（Layer Entry）与导入边（Import Edge）

### 5.1 层条目

| 字段 | 规则 |
|---|---|
| **路径** | **目录优先 + 文件精确**：目录 ⇒ **最长前缀**匹配；文件 ⇒ 精确匹配（**最长前缀优先** ⇒ 更具体者胜出） |
| **层** | `L1`…`L6` 或 `—`（跨层单元） |
| **例外** | `—` 或 `facade-L1-L3`（**当前唯一**） |
| **未登记** | MUST 判**失败**并指名（MUST NOT 静默放行）—— 但 `src/freegraph/`（L1）与 `harness/scripts/gates/` 已作**目录级兜底** ⇒ **新增一个顶层模块不再落入「未登记」**（2026-11-08 订正 · M10） |
| **可判定的声明** | **不在本表** —— 一切 MUST / MUST NOT 约束落在 `layer-registry.md` **§0.3**（说明列**不参与判定**） |

### 5.2 导入边

| 字段 | 规则 |
|---|---|
| **源 / 目标** | 模块路径（`src/freegraph/...` 形式） |
| **解析** | `import X` · `import X.Y` · `from X import ...` · `from . import ...`（相对导入 ⇒ 按包的层级解析） |
| **第三方 import** | **不**产生层边（G2 / G17 判） |
| **判定** | **允许方向 = 层编号递增**（高层可 import 低层）· **反向 import 违规** · **同层 import 仅 L1 与 L6 允许，L2–L5 之间禁止横向依赖**（立项书 §5.1 铁律 3）· 跨层单元 ⇒ 只可 import L1 及更低（`facade-L1-L3` 例外除外） |

**关系**：

```
模块 M ──位于──> 层条目 E(M)         （唯一 · 最长前缀）
模块 M ──导入──> 模块 N ──位于──> 层条目 E(N)
边 (M→N) 合规 ⟺ allow(E(M), E(N))
```

`allow` 的真值表（**2026-11-08 分析轮订正 · 与 spec FR-008 · `layer-registry.md` §0.2 规则 2 ·
`architecture-gates.md` G25 第 3 条 四处逐字一致**）：

| E(M) | E(N) | 合规 | 依据 |
|---|---|---|---|
| L3 | L1 | ✅（递增） | 层编号递增 = 允许方向 |
| L1 | L3 | ❌（反向） | 反向 import 违规 |
| L1 | L1 | ✅（**同层 · 唯一例外之一**） | 立项书 §5.1 铁律 3 **只禁「L2–L5 之间」**的横向依赖 ⇒ **未禁 L1 同层**；且**仓库现状**存在 L1 → L1 同层 import（`src/freegraph/contracts/__init__.py` → `protocols.py` 的 `from .xxx import ...`）⇒ 按「层编号严格递增」实现会把**已冻结的契约层判红**（违反 PR-4） |
| L6 | L6 | ✅（**同层 · 唯一例外之二**） | 立项书 §5.1 铁律 4（L6 是唯一可横向依赖 L5 的层）⇒ L6 内部同层 import 不在禁列 |
| L3 | L3 | ❌（**同层横向依赖 · L2–L5 之间禁止**） | 立项书 §5.1 依赖方向铁律**第 3 条**（如持久化层不得 import 可观测层，关联只经由 L1 的协议） |
| L4 | L5 | ❌（**反向 import** —— L4 不得 import L5） | 立项书 §5.1 铁律 3（持久化层不得 import 可观测层 · 关联只经由 L1 的协议）+ 铁律 1（只能向下依赖） |
| `—`（跨层） | L1 | ✅ | 跨层只可 import L1 与更低层 |
| `—`（跨层） | L2 | ❌ | 跨层单元不得 import L2 及更高层 |
| `—`（跨层 · `facade-L1-L3`） | L2 / L3 | ✅（例外） | 注册表显式声明的 ARCH-1 唯一例外 |
| `—`（跨层 · `facade-L1-L3`） | L4 / L5 | ❌ | 门面仍不得 import L4 / L5 |

> **📌 「—」→「—」的判定（2026-11-08 分析轮订正 · 与 spec FR-008 ④ · `layer-registry.md` §0.2 规则 3 · architecture-gates G25 第 4 条 **四处口径一致**——关键措辞逐字相同：「同一跨层单元内部」·「不产生层边」·「不构成违规」·「同一注册表条目」·「模块定位口径」）**：
> 真值表的「—」表示**跨层单元**；但跨层单元之间的 import **并非一律允许** ——
> **同一注册表条目内部**（同一跨层单元的模块互相引用）⇒ **不产生层边 ⇒ ✅**；
> **不同跨层单元之间** ⇒ ❌（沿用 FR-008「跨层单元只能 import L1 与更低层」）。
> ⇒ 判定所需的**模块定位口径**（把 `import _gatekit` 这类顶层 import 落到具体路径）见
> `layer-registry.md` §0.2 规则 3 的注：**同一注册表条目** ⇒ 单元内部引用（无层边）·
> **其它条目** ⇒ 按层间方向判定 · **无法解析到仓库内路径** ⇒ 第三方（无层边）。

> **📌 一条具名的例外（2026-11-08 分析轮订正 · M10）**：**顶层包 `src/freegraph/__init__.py`（L1）
> MUST NOT import 任何内部层（含同层 L1）** —— 该约束落在 `contracts/layer-registry.md` **§0.3 的可判定声明 L-1**
> ⇒ 由 **G25** 判（**优先于**上表的「L1 → L1 允许」）；而「L1 契约层**内部**零内部层 import」由**既有 G2** 承担
> （`layer-registry.md` §0.3 **L-2**）· **G25 不重复判**。

## 6. 出站记录（Egress Record）

| 字段 | 说明 |
|---|---|
| **目标** | `host:port` |
| **栈帧** | 调用栈快照（**只读**，不改写语义） |
| **归因** | `framework`（框架出站）· `user`（用户出站） |

**归因算法**（裁定 19 · research D-11）：

```
frames[0] = 最靠近连接发生处
for f in frames:
    if f.module ∈ sys.stdlib_module_names:  continue   # 跳过标准库帧
    return "framework" if f.path.startswith("freegraph/") else "user"
return "user"                                          # 全是标准库帧 ⇒ 用户出站
```

**约束**：

- **只观测、不阻断** ⇒ 夹具**只包装** `socket.connect` / `socket.create_connection`，
  **放行**全部连接（FR-009 ② · 裁定 7）；
- **只对 `framework` 断言 == 0**；`user` **记录在案但不判失败**（FR-009 ②）；
- freegraph **不得**安装任何出网拦截机制（FR-009 ③）⇒ 夹具是**测试侧**工件，
  MUST NOT 出现在 `src/freegraph/**` 内。

## 8. 断网排除项（Offline Exclusion）

**载体**：`tests/gates/data/offline_exclusions.txt`（**纯文本** · 可机读 · 与测试**同址** ⇒ 同提交）。

| 字段 | 规则 |
|---|---|
| **用例标识** | MUST 能唯一定位到一条测试（`文件::测试名` 或 pytest 的 nodeid） |
| **排除理由** | MUST **逐条**写明（FR-010 ④） |
| **排除类别** | **仅限两类**：(a) **断网任务自身**（不可嵌套）；(b) **语义上必须能建立连接**的用例 |
| **新增判据** | 新测试进入仓库时，MUST 有一条**事先写下的判据**决定去留（FR-010 ⑤） |

**格式**（每行一条，`#` 开头为注释）：

```
# <用例标识>  ::  <排除理由>
tests/gates/test_gates.py::test_egress_attribution_records_user_egress :: 需要建立一次真实连接以验证「用户出站」归因；断网下该连接必然失败（属假红，非 freegraph 缺陷）
```

2. **白名单恰好 5 个 id**（SC-014）—— 既不多也不少。
3. **门禁实现中「等价标识符对照表 / 家族判定 / 豁免入口」的条数 == 0**（FR-018 · SC-014）。
4. **门禁总数 == 30**（G1–G30）· **编号连续**（裁定 4）。
5. **既有门禁 G1–G20 的判据句**零改动（裁定 8 · 除 §4 登记的 G3 常量填充）。
6. **「框架出站」条目数 == 0**（SC-006）。
