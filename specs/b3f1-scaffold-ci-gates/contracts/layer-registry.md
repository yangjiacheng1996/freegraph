## 0. 格式

### 0.1 条目语法

一行一条目，管道分隔，**4 列**：

```
| <路径> | <层> | <例外> | <说明> |
```

| 列 | 取值 | 含义 |
|---|---|---|
| **路径** | 反引号包裹的仓库相对路径 | **目录** ⇒ 前缀匹配（该目录下的一切）；**文件** ⇒ 精确匹配 |
| **层** | `L1`…`L6` 或 `—` | 代码归属层；`—` = **跨层单元**（不属于任何单一层） |
| **例外** | `—` 或 `facade-L1-L3` | ARCH-1 的例外标记；当前**唯一**例外 = 公开 API 门面 |
| **说明** | 自由文本 | 人类可读备注（不参与判定） |

### 0.2 判定规则（G25 MUST 逐条遵守）

1. **匹配**：模块路径先按**目录前缀**匹配，再按**文件精确**匹配；
   **最长前缀优先**；**未匹配到任何条目 ⇒ 判为「未登记」并判失败**（MUST NOT 静默放行）。
2. **允许方向**（**口径三处逐字一致** —— spec FR-008 · 契约 G25 第 3 条 · `data-model.md` §5.2）：
   **层编号递增**（高层可 import 低层）；**反向 import 违规**；
   **同层 import 仅 L1 与 L6 允许，L2–L5 之间禁止横向依赖**（立项书 §5.1「依赖方向铁律」第 3 条）。
   > **📌 同层口径的裁定（2026-11-08 分析轮订正 · 已拍板 · 不得重新讨论）**：
   > 立项书 §5.1 铁律 3 只禁「**L2–L5 之间**」的横向依赖，**未禁 L1 / L6 的同层 import**；
   > 且**仓库现状**存在 **L1 → L1 同层 import**（`src/freegraph/contracts/__init__.py` 与
   > `src/freegraph/contracts/protocols.py` 的 `from .xxx import ...`）⇒ 若按「层编号严格递增」实现，
   > G25 上线当天即把**已冻结的契约层代码判红** ⇒ 违反 PR-4「feature 必须能独立通过门禁」。
   > ⇒ 故**同层 import 的唯一例外 = L1 与 L6**（L6 的横依赖能力见 立项书 §5.1 铁律 4）。
3. **跨层单元**：
   - 只能 import **L1 与更低层**；
   - MUST NOT 被 **L2–L5** import（**L6 除外** —— L6 = 应用层，按定义经由**公开 API 门面**使用内核，
     故 L6 → 门面是**正确方向**）；
   - **工程设施类**跨层单元（如 `harness/scripts/gates/`）**额外** MUST NOT 被**任何** `src/` 下的层
     import —— 它是**构建期**代码，不属运行时依赖图；
   - 带 `facade-L1-L3` 例外的条目 ⇒ 允许 import **L1–L3**，仍**不得** import **L4 / L5**；
   - **同一跨层单元内部**的模块互相 import ⇒ **不产生层边 ⇒ 不构成违规**
     （spec FR-008 ④ · 2026-11-08 分析轮订正）—— 而**不同**跨层单元之间的 import **仍**适用本规则第 1 条
     （「只能 import L1 与更低层」⇒ 违规）。
     > **📌 模块定位口径（判定的机械步骤 · 与 spec FR-008 ④ / `data-model.md` §5.2 / `architecture-gates.md` G25 第 4 条 **四处口径一致**——关键措辞逐字相同：「同一跨层单元内部」·「不产生层边」·「不构成违规」·「同一注册表条目」·「模块定位口径」）**：
     > import 的目标 MUST 先被**定位到具体路径**（以被检根 + `sys.path` 解析）⇒
     > 落在**同一注册表条目**下 ⇒ **单元内部引用**（不产生层边）·
     > 落在**其它条目**下 ⇒ 按层间方向判定 ·
     > **无法解析到仓库内路径** ⇒ 视为第三方 ⇒ 不产生层边。
     > ⇒ **本条是必需的**：本 feature 的 10 个门禁脚本 MUST 复用同一份共享判定库
     > （`harness/scripts/gates/_gatekit.py`）⇒ 门禁脚本 `import _gatekit` 属「单元内部引用」；
     > 若无本条，按「只能 import L1 与更低层」的字面读法即被判违规 ⇒ **G25 上线当天把 10 个门禁脚本全部判红**
     > ⇒ 违反 PR-4「feature 必须能独立通过门禁」。
4. **未登记层**（代码尚不存在）：条目**照样登记** ⇒ 新增该层下的代码时**门禁实现零改动**（FR-008 ③）。
5. **扫描域**：本表声明的**全部跨层单元路径**（当前 = `harness/scripts/gates/` 与 `harness/proposals/`
   —— `src/freegraph/graph.py` 已在 `src/freegraph/**` 之内）
   **一并纳入 G25 的扫描域** —— 跨层单元自身的 import 方向**同样受检**
   （「只能 import L1 与更低层」·「不得被 L2–L5 import」）⇒ 否则本表的跨层单元条目**形同虚设**。

## 3. 变更纪律

- **新增一层 / 新增跨层单元** ⇒ **只改本文件**，门禁实现**零改动**（FR-008 ③）。
- **改动某模块的层归属** ⇒ **只改本文件**；MUST 同步复核该模块的**全部** import 方向。
- 本文件是**冻结面**：改层归属 = 改架构契约 ⇒ MUST 走评审（同 spec 的其它冻结面）。
- **MUST NOT** 在门禁实现里硬编码任何层归属（除本文件的解析结果）⇒ 否则「一处判据两处实现」。
