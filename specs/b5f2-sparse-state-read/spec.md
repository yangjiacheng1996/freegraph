## User Scenarios & Testing *(mandatory)*

### User Story 1 - 空 key 不出现在节点入参里（Priority: P1）

作为用户，我的状态 schema 有 `messages` 与 `llm_calls` 两个 key；当 `llm_calls` 尚未被写入过时，
我希望节点收到的那个 `dict` **不含** `llm_calls`，从而 `state.get('llm_calls', 0)` 返回 `0` 而不是 `None`
—— 否则 `None + 1` 直接抛 `TypeError`，我的脚本在验收点上崩掉。

**Why this priority**: 这是 **C4 稀疏状态**契约本身，是全项目**最易被静默破坏**的两条契约之一；
提示词 §10 明写「测试若写成『节点入参包含所有 schema key』的宽松断言，就等于没有防线」⇒
**否定式**断言必须先落地。

**Independent Test**: 手写一组通道状态（一个已写入、一个未写入）⇒ 走读取入口 ⇒ 断言
`"llm_calls" not in node_input` 且 `node_input.get("llm_calls", 0) == 0`。**不经由图执行**。

**Acceptance Scenarios**:

1. **Given** 一个已写入的通道与一个从未写入的通道，**When** 读取该组通道的状态，**Then** 结果只含已写入通道的 key
2. **Given** 结果 `dict` 不含未写入的 key，**When** 调用 `node_input.get('llm_calls', 0)`，**Then** 返回 `0`（不是 `None`）
3. **Given** 一个值为 `None` 的通道，**When** 读取状态，**Then** 该 key **出现**在结果里且值为 `None`（`None` 是合法值，不是「空」）
4. **Given** 读取前后的通道状态，**When** 比对通道当前值，**Then** 读取**未改变**任何通道的值

### User Story 2 - 节点入参是普通 dict（Priority: P2）

作为用户，我希望节点收到的第一个参数是**普通 `dict`** —— 不是自定义映射、不是属性对象 ——
这样 `state.get(key, default)` 与 `state["key"]` 的语义完全符合直觉，任何人接手我的节点代码都不会踩坑。

**Why this priority**: C4 的两条断言（`not in` 与 `.get(default)`）只有在**普通 `dict`** 上才成立；
若传入自定义映射，`not in` / `.get` 的行为可能与 `dict` 不同 ⇒ P1 的防线会被绕过。

**Independent Test**: 读取一次状态 ⇒ 断言 `type(result) is dict`；再断言结果里每个值与通道里的值**同一对象**。

**Acceptance Scenarios**:

1. **Given** 读取结果，**When** 检查其类型，**Then** `type(result) is dict` 成立（不是 `dict` 的子类）
2. **Given** 读取结果，**When** 用 `result["key"]` 取值，**Then** 与通道当前值**逐字相等**
3. **Given** 读取结果，**When** 修改结果 `dict` 的**键集合**，**Then** 通道状态**不受影响**（结果 `dict` 是新建的）

### User Story 3 - 与 LangGraph 的行为可逐项比对（Priority: P3）

作为维护者，我希望有一套**可复用的差分夹具**：给定**同一份图规格**，分别在 `langgraph` 与 `freegraph` 上执行，
断言两者的**节点入参**、**输出状态**、**事件序列**一致 —— 从而把「freegraph 与 LangGraph 等价」从一句**主张**
变成一条**可复现的证据**。

**Why this priority**: 这是立项书 §4.2 S5「等价证据三层」的第 **②** 层；它同时是 C4 / C8 两条契约
在 B8F1 的**唯一验证载体**（提示词 §2 / §10）⇒ 现在建立，后续两个 feature 直接复用。

**Independent Test**: 准备一份「有归约器 + 无归约器 + 空 key」混合的图规格 ⇒ 跑差分夹具 ⇒
断言三项投影的差异 == 0；`langgraph` 缺席时该用例被**标记跳过**而非失败。

**Acceptance Scenarios**:

1. **Given** 一份混合 schema 的图规格，**When** 在两侧分别执行，**Then** 节点入参的 key 集合与各 key 的值**逐项相等**
2. **Given** 同一份图规格，**When** 在两侧分别执行，**Then** 最终输出状态**逐 key 相等**
3. **Given** 同一份图规格，**When** 在两侧分别执行，**Then** 归一化后的事件序列**逐项相等**
4. **Given** 运行环境**没有** `langgraph`，**When** 执行差分夹具，**Then** 用例被**标记跳过**且**无失败**

### User Story 4 - fresh 读视图不污染通道正式值（Priority: P4）

作为用户，我的条件边（下一 feature 落地）需要读到「**当前值 + 本节点本次写入**」；
但我**不希望**这次「预读」把写入提前固化进通道 —— 否则同一 super-step 内的后续写入会看到「已经写过了」的状态。

**Why this priority**: 这是 **C8**（条件边读 fresh 状态）的**实现基础**；C8 的回归测试属 **B8F1**，
但读取原语必须在本 feature 就位（提示词 §7 口径提醒）。

**Independent Test**: 手写通道状态 + 一组待写入值 ⇒ 走 fresh 读入口 ⇒ 断言视图**含**本次写入、
且通道的**绑定与可用性判定**（`is_available()` 的结果 + `get()` 的取值）在读取**前后不变**
（**零污染判据的作用域** · 已知面见 Edge Cases · 裁定 29）。

**Acceptance Scenarios**:

1. **Given** 一个已写入的通道与一组待写入值，**When** 走 fresh 读，**Then** 视图里的该 key **包含**待写入值
2. **Given** 同上，**When** 比较读取**前**后通道的**绑定与可用性判定**，**Then** 两者的 `is_available()` 结果与
   `get()` 取值**逐字相等**（零污染 · 作用域见 FR-009）
3. **Given** 一个**归约型**通道与一组待写入值，**When** 走 fresh 读，**Then** 视图里的值 == 归约后的结果
4. **Given** 同上，**When** 走**非** fresh 读，**Then** 视图里的值 == 通道当前值（**不含**待写入值）

### User Story 5 - 状态读取只有一处实现点（Priority: P5）

作为维护者，我希望「稀疏读」与「fresh 读」两条语义**收敛**到同一个模块的两个入口，
这样上游行为变化时我只需要改**一处**；否则两条语义迟早会分叉成「读出来的状态有时候有 key、有时候没有」。

**Why this priority**: 提示词 §2 的**架构纪律**（「状态读取 MUST 收敛为单一抽象点」）；
它是 C4 / C8 两条契约能被**长期守住**的结构前提。

**Independent Test**: 全仓扫描 —— 状态读取入口的**实现点数 == 1**（一个模块）；内核路径上对
`langgraph` / `langchain*` / `langsmith` 的导入次数 == 0。

**Acceptance Scenarios**:

1. **Given** 全仓源码，**When** 统计状态读取入口的实现点，**Then** 恰为**一个**模块
2. **Given** 内核路径 `src/freegraph/**`，**When** 扫描对 `langgraph` / `langchain*` / `langsmith` 的导入，**Then** 次数 == 0
3. **Given** 发行元数据，**When** 检查 `Requires-Dist`，**Then** `langgraph` / `langchain*` / `langsmith` 出现次数 == 0

### Edge Cases

- **通道值为 `None`**：`None` 是**合法用户值** ⇒ 该通道「**有值**」⇒ MUST 出现在读取结果里且值为 `None`；
  与「从未写入过的空通道」**严格可区分**（裁定 9）。
- **读取结果里的值被调用方就地修改**：结果 `dict` 里的值与通道里的值**同一对象** ⇒ 就地修改会**改到通道的值**
  （浅引用 · 裁定 10）⇒ MUST 在文档里明说，MUST NOT 深拷贝（深拷贝会破坏对象身份且可能失败）。
- **读取结果 `dict` 本身被调用方改键集合**：结果 `dict` 是**新建**的 ⇒ 改键集合**不影响**通道状态。
- **`skip_empty=False` 且存在无值通道**：MUST 抛 `EmptyChannelError`（**不**以 `None` 冒充 · 裁定 3）。
- **`read_channels` 与 `local_read(fresh=False)` 的结果**：二者 MUST **逐字相等**
  （key 集合 + key 顺序 + 逐 key 值同一对象 · FR-038 / SC-033）⇒ **同一稀疏语义只有一处实现**；
  若二者出现差异 ⇒ 属**语义分叉缺陷**（不是「口径相近」）（裁定 33 ④）。
- **通道的 key 为空串**：MUST 照常作为 `dict` 的一个 key 出现（空串是合法 key）。
- **映射里有**不在 schema 里的 key**：读取层 MUST **照常读取**（读取层不做 schema 校验 —— 那是 B4F1 的职责）⇒
  未知 key 的通道若「无值」⇒ 在 `skip_empty=True` 下被跳过。
- **fresh 读时待写入的值与通道当前值类型不匹配**：归约器抛错 ⇒ 该错误**向上传播**；
  通道正式值**不变**（副本被丢弃 ⇒ 零污染）。
- **fresh 读时**就地修改型**归约器改写了通道的值对象**（如 `a.extend(b)` 一类归约器）：副本与原通道
  **浅共享值对象** ⇒ 原通道的**值对象**会被改写 ⇒ ⚠️ **已知面**（research **D-10** · **DR-4** ·
  **上游同构** —— 上游 `checkpoint()` 亦返回同一对象）⇒ **零污染判据的作用域**只覆盖「**绑定与可用性判定**」
  （`is_available()` 的结果 + `get()` 的取值）⇒ 本情形 **MUST NOT** 计入该判据（FR-009 · SC-005）·
  **MUST NOT** 由读取层修复（**不深拷贝** —— 会破坏 FR-005 的对象身份语义 · 对不可拷贝对象会失败 ·
  与上游分叉）⇒ **MUST** 在本节与**人工验证记录**中登记（裁定 29 · Q26）。
- **fresh 读时一步内给同一 key 多个值**：MUST 与写入路径**同款**行为 —— 覆盖型 / 路由型抛
  `InvalidChannelUpdateError`；归约型**按序**逐个归约。
- **fresh 读时待写入的 key 通道无值**：覆盖型 ⇒ 视图里就是待写入值；归约型 ⇒ 通道**首次写入直存**
  （**不调**归约器 · B5F1 裁定 4）⇒ 视图里是待写入值本身。
- **fresh 读时待写入的 key 在通道映射里不存在**（指**待写入映射**的 key · **非** C6 的**节点返回值** key —— 后者属 **B7F1**）：MUST **显式失败**（MUST NOT 静默丢弃写入）——
  写入到未知 key 是用户错误（与 B5F1「非法输入 MUST 显式失败」同立场）；MUST 抛
  `InvalidChannelUpdateError` 且其 `key` 字段指向那个未知 key（裁定 19）。
- **fresh 读读到的通道在复制后被并发改动**：本 feature **不承诺线程安全**（B5F1 裁定 10 同款口径）⇒
  视图是**读取瞬间**的快照，MUST NOT 被承诺为原子快照。
- **通道是第三方自定义 `Channel` 子类**：读取层 MUST 只依赖 B5F1 冻结的四个操作 ⇒ 自定义通道可被读取；
  但 fresh 读的**复制**要求该子类可复制（MUST 在文档里写明这一约束）。
- **`read_channels` 传入空映射**：MUST 返回**空 `dict`**（不是 `None`、不抛错）。
- **`local_read` 的待写入映射为空**：MUST 返回与「非 fresh 读」**逐字相等**的视图。
- **同一通道在同一次 fresh 读里既被读取又被写入**：视图按「先合并本次写入、再取值」计算 ⇒
  视图 == 「写入生效后的状态」；**通道正式值**仍为写入前的值（⚠️ **已知面**：**就地修改型**归约器会改写
  **值对象** ⇒ 见 FR-009 / Edge Cases · 裁定 29）。
- **`langgraph` 缺席**：差分夹具 MUST **skip**（MUST NOT fail）；同时 MUST 有专门 CI **步骤**真实执行它（裁定 11 / 裁定 25）。
- **差分夹具的两侧事件形态不同**：MUST 先**归一化**为 `(步序, 节点名, 写入)` 三元组再比对（裁定 7）。
- **差分夹具的节点返回了 schema 之外的 key**：MUST **显式失败**（两侧都失败 ⇒ 比对结论为「等价地失败」，
  MUST NOT 把失败悄悄吞掉）。
- **差分夹具的图规格里条件边字段非空**（本 feature 恒空 · 裁定 15）：MUST **显式失败**
  （MUST NOT 静默忽略、也 MUST NOT 自行实现路由）⇒ 防止「夹具偷偷越界长成调度器」。
- **差分夹具的图规格里「模型工厂」字段非空**（本 feature 恒空 · 裁定 26）：MUST **显式失败**
  （MUST NOT 静默忽略、也 MUST **NOT** 自行实现 fake 模型注入）⇒ 本 feature 的图规格 MUST **恒为纯本地**
  ⇒ fake 轮与「模型形状的图规格」归 **B25F1**（FR-036）。
- **初始输入里有 schema 之外的 key**：MUST **显式失败**（两侧都失败 ⇒ 等价地失败）⇒
  MUST NOT 静默丢弃、也 MUST NOT 塞进「未知通道」。
- **初始输入的值与归约器不兼容**（如归约型通道的初始值与 reducer 期望的形状不符）：错误 MUST
  **向上传播**且通道保持「无值」⇒ 两侧行为一致。
- **节点函数就地修改了收到的入参字典**：观测到的入参 MUST 仍是**节点执行前**的那一份
  （留存副本 MUST 在节点函数第一行取得 · 裁定 17）⇒ 否则「节点入参」这项比对会测到被改坏的字典。
- **B7F1 接线后 C4 用例仍只断言读取层**：MUST 被 **B7F1** 判为**未承接**（承接口径见 FR-031 / 裁定 18）⇒
  本 feature 侧**不**承担该判定（本 feature 无调度器、无法自证）。
- **挂载点元测试被误写成 import L2**（如 `from freegraph.runtime import ...`）：门禁 **G2** 的内部 import 档
  扫描 `tests/contracts/**` ⇒ 必然**违规**（CI 红）⇒ 元测试 MUST 只做**路径扫描**（FR-032 · 裁定 20）。
- **字段描述里的值类型无法被 B4F1 解析**（如 `Annotated` 里的归约器不是二元）：MUST **显式失败**
  （两侧等价地失败）⇒ MUST NOT 静默跳过该字段。
- **字段描述里某个 key 缺少值类型**：MUST **显式失败**（构造不出 `TypedDict` ⇒ 两边都拼不出图）。
- **调用方省略 `skip_empty` 参数**：MUST 得到**稀疏**结果（缺省 = True · 裁定 22）⇒ 该缺省与上游
  **同构**（parity **P-03**）⇒ **无需**登记形状差异；**真正的**形状差异在**返回类型**
  （上游依 `select` 而变 · freegraph **恒返回 `dict`** · parity **P-05**）。
- **上游对「节点返回空更新」的可观察行为尚未实测**：MUST **NOT** 假定口径（裁定 23）⇒
  夹具 MUST 先按「口径未冻结」标记该情形，不得据此给出「一致 / 不一致」的结论。
- **L2 导出面增长是否波及冻结面**：MUST **NOT**（G7 只管 L1 的 18 符号、G15 / G19 只管门面的 7 符号、
  兼容矩阵与 `THIRD_PARTY_NOTICES` 均不涉及 L2）⇒ `freegraph.runtime.__all__` 12 → 14 是
  **零冻结面变更**（裁定 24）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001（读取抽象 · 单一实现点）**：系统 MUST 提供状态读取的**唯一抽象点** —— 收敛到**同一个模块**内的
  **两个**自由函数（`read_channels` / `local_read`）。全仓 MUST NOT 出现第三个状态读取实现点
  （提示词 §2 的架构纪律 · 裁定 1）。
- **FR-002（读取入口的名字与签名 · 逐字冻结）**：两个入口的名字 MUST 逐字为 `read_channels` 与 `local_read`
  （`harness/prompts/guide.md:566` + **Q8:121 / :132**（契约权威）· ⚠️ 2026-11-10 分析轮第二轮更正：
  原写作「立项书 §5.2 的 B5F2 行」**不成立**）；`read_channels` 的通道入参 MUST 是**「key → 通道」映射**，
  `local_read` 的写入入参 MUST 是**「key → 写入值序列」映射**（与 B5F1 冻结的 `update(values: Sequence[Any])` 同形）。
  两个名字是**跨 feature 契约**（B7F1 / B8F1 直接 import）⇒ MUST NOT 改名或增删别名（裁定 1 / 裁定 14）。
- **FR-003（稀疏读取 · C4）**：`read_channels` MUST 只返回「**当前有值**」的通道对应的 key；
  无值通道的 key **MUST NOT** 出现在结果中（**C4** · 提示词 FR-002 / SC-003）。
- **FR-004（读取结果 = 普通 `dict`）**：读取结果 MUST 是**新建**的**普通 `dict`** —— `type(result) is dict`
  MUST 成立（MUST NOT 是 `dict` 的自定义子类、MUST NOT 是自定义映射或属性对象）
  （C4 · 提示词 P2 · 裁定 10）。
- **FR-005（值的引用语义）**：读取结果里的值 MUST 与通道当前值是**同一对象**（浅拷贝）；
  MUST NOT 深拷贝用户对象（深拷贝会破坏对象身份，且对不可拷贝对象会失败 · 裁定 10）。
- **FR-006（「空」= 「无值」 ≠ 「假值」）**：通道当前值为 `None` ⇒ 该通道**有值** ⇒ MUST 出现在读取结果里
  （值为 `None`）；稀疏判据 MUST NOT 是「值是否为假值」（B5F1 裁定 5 · 裁定 9）。
- **FR-007（`skip_empty` 的两个分支）**：`read_channels` MUST 提供「跳过空通道」与「不过滤」两个模式：
  跳过模式（`skip_empty` 的**缺省** MUST 为 True · 裁定 22）⇒ 无值通道被跳过；
  不过滤模式 ⇒ 读到无值 MUST 抛 `EmptyChannelError`（MUST NOT 以 `None` 冒充 · 裁定 3）。
- **FR-008（fresh 读视图）**：系统 MUST 提供「fresh 读」入口，返回「**当前值 + 本任务本次写入**」的视图
  （提示词 FR-003）；非 fresh 模式 MUST 只返回当前值（不含本次写入）。
- **FR-009（fresh 读零污染 · 作用域 = **绑定与可用性判定**）**：fresh 读 MUST NOT 改变任何通道的
  **绑定与可用性判定** —— 读取前后每个通道的 `is_available()` 的**结果**与 `get()` 的**取值** MUST
  **不变**（提示词 FR-003 · SC-005 · 裁定 29）。

  ⚠️ **已知面（**不计入**本判据 · **MUST NOT** 由读取层修复 · **MUST** 登记）**：「**值对象**被
  **就地修改型**归约器改写」（副本与原通道**浅共享值对象** ⇒ `a.extend(b)` 一类归约器会改写原通道的
  值对象）⇒ 原通道的**值对象**会被改写（research **D-10** · **DR-4** · **上游同构** —— 上游 `checkpoint()`
  亦返回同一对象）⇒ ① MUST **NOT** 由读取层修复（**深拷贝**会破坏 **FR-005** 的**对象身份语义**、对不可拷贝
  对象**会失败**、且与**上游分叉**）⇒ ② MUST **NOT** 计入本判据 ⇒ ③ MUST 在 **Edge Cases** 与
  **人工验证记录**中**显式登记**（裁定 29）。

  归约型走 reducer、覆盖型 / 路由型一次写入即覆盖、一步内多值冲突抛 `InvalidChannelUpdateError`；

### Key Entities

- **稀疏状态读取（`read_channels`）**：状态读的**唯一**稀疏入口 —— 返回「只含有值的 key」的**普通 `dict`**

  读取层 MUST NOT 自行构造通道（FR-002 / 裁定 14）。

- **图规格（graph spec）**：差分夹具的输入 —— 一份**纯数据**的图规格（**字段描述**形式的 schema +
