# 数据模型（Data Model）—— B7F1 的调度内核

**Feature**: `B7F1` · **Spec**: [spec.md](./spec.md) · **契约**: [contracts/superstep-contract.md](./contracts/superstep-contract.md)
**核实环境**: CPython **3.11.16** · 上游 `langgraph` **1.2.11**（核实于 2026-11-10）

> **落位**：全部类型落在 **L2**（`src/freegraph/runtime/superstep.py` · 裁定 17）⇒
> **层注册表零改动**（`src/freegraph/runtime/` 已是**目录条目** ⇒ 新模块**自动**被覆盖）。
> ⚠️ **MUST NOT** 为 `runtime/` 下的新模块**单独立**注册表条目 ⇒ 会造成 L2 → L2 的横向依赖误判。

## 1. 实体总览

| 实体 | 角色 | 生命周期 | 可变性 |
|---|---|---|---|
| **通道映射** `channels` | **状态载体**（key → `Channel`） | 跨轮次 | 通道对象的值**可变**（由调度层写；**跑之前**的**初始化写入**由调用方直接写 ⇒ 唯一豁免 · 裁定 31 · 口径的权威落点 = **spec 的 FR-001 ⚠️** · 裁定 35 —— 本列为**复述**） |
| **图规格** `GraphSpec` | **静态**的图定义 | 跨轮次 | **不可变**（静态） |
| **节点规格** `NodeSpec` | 「订阅哪些通道 → 读 → 写」的规格 | 跨轮次 | **不可变** |
| **调度状态** `SchedulerState` | **每次运行**的调度记录 | **跨轮次**（由调用方持有） | **可变** |
| **待写入** `pending writes` | 本轮产出、轮末合并 | **单轮** | 单轮内累积 |
| **单轮结果** `SuperStepResult` | 一轮（或多轮）的产物 | 单次返回 | **不可变** |

```
调用方
  │
  ├─ 持有 ──► SchedulerState        （已消费版本 + 轮次计数）
  │
  ├─ 持有 ──► GraphSpec              （静态）
  │            ├─ channels: {key → Channel}   ← 状态本体（可变）
  │            ├─ nodes:   {name → NodeSpec}  （保序 ⇒ 执行顺序）
  │            ├─ edges:   {src → (dst, …)}
  │            └─ conditional_edges: {}        （本轮恒空 · 预留）
  │
  └─ 调用 ──► run_super_step(spec, state)          ──► SuperStepResult
               run_super_steps(spec, state=None, *, max_steps=25)  ──► SuperStepResult
```

## 2. 图规格（`GraphSpec`）

> ⚠️ **校验的执行时机 = 构造时**（裁定 32 · 2026-11-11 分析轮第 3 次 · 发起者裁决）：§2 与 §2.1
> 的**约束列**即 `GraphSpec` / `NodeSpec` 的**构造期**校验 ⇒ 构造 ⇒ **即刻显式失败**
> （MUST NOT 推迟到运行期）⇒ 下游 **B6F1 / B7F2** 的适配器 MUST 依赖此口径。

| 字段 | 类型 | 语义 | 约束 |
|---|---|---|---|
| `channels` | `dict[str, Channel]` | 状态本体 | 值 MUST 是 `Channel` 实例；**可变** `dict`（承接 H-4 · B5F1 `build_channels` 的产物 · **FR-034**）· ⚠️ **MUST NOT** 用 `MappingProxyType`（B4F1 的 `SchemaSpec.channels` 是只读映射，形态不同） |
| `nodes` | `dict[str, NodeSpec]` | 节点表 | **MUST 保序**（声明顺序 == 执行顺序 · FR-013）；**MUST 非空** |
| `edges` | `dict[str, tuple[str, ...]]` | 边表（源 → 目标序列） | 源 / 目标 MUST **都在 `nodes` 里** |
| `conditional_edges` | `dict[str, Any]` | **预留**（条件边） | **本轮恒为空**；**非空 ⇒ 显式失败**（FR-033 · 裁定 25）· ⚠️ **缺省值 MUST 用「工厂语义」实现**（dataclass 的 `default_factory` 等价）⇒ **MUST NOT** 用字面可变默认值 `= {}` ⇒ dataclass 抛 `ValueError: mutable default`（**实测**） |

### 2.1 节点规格（`NodeSpec`）

| 字段 | 类型 | 语义 | 约束 |
|---|---|---|---|
| `subscribes` | `tuple[str, ...]` | 订阅的通道 key —— **既管触发、也管入参**（裁定 2） | 每个 key MUST 在 `channels` 里；**入参的 key 顺序按「通道映射的顺序」**（**不是**本字段的声明顺序 · FR-008 ⚠️ · 裁定 26） |
| `run` | `Callable[[dict[str, Any]], dict[str, Any]]` | 节点函数（**C5**） | MUST 可调用；返回值 MUST 是 `dict`（**MUST NOT** `None`） |

> **关系**：`NodeSpec.subscribes` ⊆ `GraphSpec.channels` 的 key 集合；
> `GraphSpec.edges` 的每个端点 ∈ `GraphSpec.nodes` 的 key 集合。

## 3. 调度状态（`SchedulerState`）—— **由调用方持有**

| 字段 | 类型 | 语义 | 变更时机 |
|---|---|---|---|
| `versions_seen` | `dict[str, dict[str, int]]` | **节点名 → {触发源 → 已消费版本}** | 节点被**准备执行**时，消费其**全部**触发源的当前版本（§3 消费规则） |
| `step` | `int` | **执行轮**计数（**不含**空轮）—— 即 **FR-011 的上限计数口径** | 每**执行轮**结束 +1（⚠️ **不是** `SuperStepResult.steps` 的「含空轮的迭代轮数」） |
| `channel_versions` | `dict[str, int]` | **通道 key → 写入版本**（**每通道独立** · D-03） | 通道**成功写入**时 +1；**清空不是写入** ⇒ 不推进 |
| `node_versions` | `dict[str, int]` | **节点名 → 执行版本**（边触发源的版本） | 节点**执行成功**时 +1 |

> ⚠️ **「已消费版本」的记录结构**与上游 `checkpoint["versions_seen"]` **逐字同构**
> （research **D-02** · `_algo.py:264-271`）⇒ 机制可对照。
> ⚠️ **版本归属**：版本**由调度器维护**、**不存进通道对象** ⇒ **B5F1 的四个只读属性（冻结面）零改动**
> （裁定 21 · research **C-2**）。

### 3.1 触发源标识

| 触发源 | 标识 | 版本来源 |
|---|---|---|
| **通道触发源** | `("c", 通道 key)` | `channel_versions[通道 key]` |
| **边触发源** | `("e", 源节点名)` | `node_versions[源节点名]` |

> ⚠️ **两类触发源 MUST 用**不同**的标识空间** ⇒ 避免「通道 key 与节点名同名」时互相覆盖
> （裁定 3 的统一版本口径 + 标识区分）。

### 3.2 触发判定（**逐字**）

```
节点 N 被触发 ⟺ ∃ 触发源 s ∈ sources(N) : has_value(s) ∧ version(s) > seen(N)[s]
```

| 规则 | 内容 |
|---|---|
| **初始化**（裁定 21 · 裁定 31） | 调度器**第一次**查看某通道时，若它**已有值** ⇒ `channel_versions[key] = 1`（「**有值**」即算已写过一次 · research **D-01**）⇒ ⚠️ **「查看」的操作点 = 触发判定阶段枚举该节点的订阅通道时**（必然早于任何写入 ⇒ 版本号唯一确定） |
| **消费** | N 被**准备执行**时 ⇒ `seen(N)[s] = version(s)`（对**全部**触发源） |
> ⚠️ **2026-11-13 · B7F4 回溯修订 R-8（拆分而不删）**：本节**追加**「**多源口径**」的
> 判定式与记账口径 ⇒ ⇒ **上式逐字保留**（**单源口径逐字退化** ⇒ **既有行为零变化**）：
> ```
> 节点 N 被触发 ⟺ ∃ 组 g ∈ groups(N) : ∀ s ∈ g : version(s) > seen(N)[s]
> ```
> * **组** = **每条入边一个组**（**单源边** ⇒ **单元素** · **多源边** ⇒ 该边的**全部**源）
>   ⇒ **组内全 · 组间任一**（**上游同款**）；
> * **记账**：N 被**准备执行**时 ⇒ **只消费「已满足的组」的源** ⇒ **逐源各记一条**
>   `seen[(kind, ident)] = version(ident)` ⇒ **未满足的组不记账** ⇒ 屏障**后来齐了仍能再次触发**
>   ⇒ ⇒ **单源口径的记账逐字不变**（未满足 ⇒ `version ≤ seen` ⇒ 版本只增不减 ⇒
>   `version == seen` ⇒ **同值记账** ⇒ **可观察行为零变化**）。
> ⇒ ⇒ 多源口径的**唯一权威** =
> `specs/b7f4-multisource-join/contracts/superstep-multisource-contract.md` §3.2 / §3.3。
| **合取项（逐触发源）** | 通道触发源：**该通道**无值 ⇒ 该**触发源**不计入（MUST NOT 读成「节点订阅集整体有值」· 裁定 28）· 边触发源：无「值」概念 |
| **未订阅通道的版本基值** | 某通道若**从未被任何节点订阅** ⇒ 永不被「首次查看」⇒ 其写入版本的**基值 MUST 取 0**（`Channel.update()` 返回真 ⇒ +1）⇒ 该通道**无订阅者 ⇒ 永不触发** ⇒ 唯一作用是**消除歧义**（裁定 34） |

## 4. 一个 super-step 的状态机（**五阶段** · FR-001）

```
        ┌──────────────────────── 下一轮 ────────────────────────┐
        │                                                        │
        ▼                                                        │
  ┌───────────┐   ①触发判定    ┌───────────┐   ②任务准备   ┌───────────┐
  │ 轮次开始  │ ────────────► │ 触发集合  │ ────────────► │ 任务集合  │
  │ (step k)  │               │ (有序)    │               │ + 入参    │
  └───────────┘               └───────────┘               └───────────┘
                                                            │ ③任务执行
                                                            ▼
                                                       ┌───────────┐
                                                       │ 节点返回值 │
                                                       └───────────┘
                                                            │ ④写入收集
                                                            ▼
                                                       ┌───────────┐
                                                       │  待写入    │
                                                       │ (按节点分组)│
                                                       └───────────┘
                                                            │ ⑤写入合并
                                                            ▼
                                                  ┌────────────────────┐
                                                  │ 合并后状态 + 版本推进 │
                                                  │ 步末清空（只清路由型）│
                                                  └────────────────────┘
                                                            │
                        ┌───────────────────────────────────┤
                        │ 任务集合为空 ⇒ 立即终止             │ 仍有任务 ⇒ 下一轮
                        ▼                                   ▼
                  ┌───────────┐                      （回到轮次开始）
                  │  收敛     │
                  └───────────┘
```

### 4.1 各阶段的产物与规则

| 阶段 | 产物 | 规则 |
|---|---|---|
| ① 触发判定 | 触发集合（**按节点表顺序**） | §3.2 |
| ② 任务准备 | 每个任务的**入参** | 入参 = `read_channels(子映射)`（B5F2 的稀疏读 · **同一处**实现）· **子映射 MUST 按「通道映射的顺序」构造**（**不是**订阅声明顺序 · FR-008 ⚠️ · 裁定 26）· 每个节点拿到**自己的**字典 |
| ③ 任务执行 | 节点的返回值 | 按**节点表顺序**串行（FR-013）· 异常**原样**传播（FR-015） |
| ④ 写入收集 | 待写入（**按节点分组**） | 执行期间通道**正式值 MUST NOT** 被改写（FR-006） |
| ⑤ 写入合并 | 合并后状态 + 版本推进 + 步末清空 | 契约 §5（合并**按通道映射顺序** · **全部合并成功后**才推进版本 · 出错 ⇒ 快照回滚 + 版本不推进 · **步末清空 = §5.2**） |

> ⚠️ **步末清空属阶段 ⑤**（裁定 33 · 2026-11-11 分析轮第 3 次 · 发起者裁决）⇒
> **单轮入口 `run_super_step` 跑完一轮后同样执行**（与上游「每步末都清未更新的通道」逐字同构）
> ⇒ 两个入口的语义 MUST 一致（同一份规格 · 单轮跑与多轮跑得到相同的通道状态）。

### 4.2 **原子性边界**（FR-032）
| 范围 | 出错时 | 说明 |
|---|---|---|
| **通道的正式值** | **全部回退**（保持轮次开始前的样子） | FR-032 · 契约 §5.4（**快照 + 逐通道回滚**：`clear()` + `update([快照值])` · **不套归约器** ⇒ 逐字还原） |
| **待写入** | **全部丢弃** | 同上 |
| **已消费版本** `versions_seen` | **不**回滚（但异常已向上传播 ⇒ 运行终止） | ⚠️ **已知边界** · research **DR-1** · 登记不改判据 |
| **通道版本** | **一个都不推进**（本轮出错 ⇒ 值回滚 **且** 版本不推进 ⇒ **同进同退**） | ⚠️ **2026-11-11 订正**（裁定 29）：原写「出错的那轮本就没推进」**不成立**（合并是**逐通道**的 ⇒ 前面的通道已成功写入并推进了版本）⇒ 改为「**全部合并成功后才推进**」 |
| **节点版本** | **不**回滚（节点**执行成功**才 +1 ⇒ 执行阶段出错 ⇒ 本就没推进） | 天然自洽 |
> ⚠️ **2026-11-13 · B7F4 回溯修订 R-8（拆分而不删）**：本节的**原子性**口径**不受**屏障影响 ⇒
> ⇒ 屏障**不改变**任何写入 / 合并 / 回滚语义 ⇒ ⇒ **追加**「**记账范围**」的限定：
> ⇒ **只记「已满足的组」的源**（**逐源各一条**）⇒ ⇒ **未满足的组不记账** ⇒
> ⇒ 屏障**后来齐了仍能再次触发**（**上游同款**）⇒ ⇒ **单源口径逐字不变**。

## 5. 单轮结果（`SuperStepResult`）

| 字段 | 类型 | 语义 | 单轮入口 | 多轮入口 |
|---|---|---|---|---|
| `state` | `dict[str, Any]` | 合并后的**稀疏状态** | 本轮合并后的状态 | 最后一轮合并后的状态 |
| `executed` | `tuple[str, ...]` | 执行过的节点名（**按执行顺序**） | 本轮 | **累计** |
| `node_writes` | `dict[str, dict[str, tuple[Any, ...]]]` | **按节点分组**的待写入（节点名 → 通道 key → 值序列） | 本轮 | **累计**：同一节点的**同一通道** ⇒ 跨轮按**轮次先后**拼接值序列（**MUST NOT** 把**不同通道**的值混进同一序列） |
| `steps` | `int` | **实际迭代轮数**（**含**那次用于发现「任务集为空」的**空轮**） | **1** | 实际迭代轮数 |

> ⚠️ **`node_writes` 是 B8F1 的复用前提**（FR-006）：条件边路由要读到「**本节点本次写入**」
> ⇒ MUST 能按节点取到本轮的写入 ⇒ **本 feature MUST NOT** 只保留合并后的按通道序列。
> ⚠️ **「轮数」只认 `steps`**（= **实际迭代轮数** · 含空轮）⇒ 「执行了节点的轮数」
> **不再作为独立判据**（**无字段承载** · 裁定 30）⇒ 一律用 `executed` + `steps`
> 两个**可观测**量表述（SC-006 / US5 同）。
> ⚠️ **两个计数器**：`SchedulerState.step`（§3 · **执行轮** · **不含**空轮 · FR-011 的上限计数口径）
> **≠** `SuperStepResult.steps`（**含**空轮的迭代轮数）⇒ MUST NOT 混用。
> ⚠️ `node_writes` 的**跨轮累计**形态 = 同名节点的同通道值序列按**轮次先后拼接**（**不**按通道重排）。

## 7. 规模与不变量（**逐条可自动判定**）

| # | 不变量 | 可判定方式 |
|---|---|---|
| **I-1** | 节点入参是**普通 `dict`**且只含「订阅集 ∩ 有值集」 | `type(x) is dict` + key 集合相等 |
| **I-2** | 入参由 B5F2 的稀疏读产出；**子映射按「通道映射的顺序」构造** | 与 `read_channels(子映射)` 的结果**逐字相等**（key 集合相同 + 顺序相同 + 逐 key 值同一对象） |
| **I-3** | 同一版本不重复触发同一节点 | 单轮内某节点执行次数 ≤ 1 |
| **I-4** | 未被触发的节点执行次数 == 0 | 执行计数 |
| **I-5** | 同轮双写归约通道 == 两次写入的归约结果 | 与 `operator.add` 逐元素相等 |
| **I-6** | 同轮双写覆盖型 ⇒ 显式失败 | 抛 `InvalidChannelUpdateError` |
| **I-7** | 未知 key ⇒ 显式失败且 `invalid_keys` 完整 | 抛 `InvalidUpdateError` |
| **I-8** | 执行期间通道正式值不被改写 | 任务内读值 == 轮次开始值 |
| **I-9** | 一轮出错 ⇒ 全部通道值逐字不变 | 快照逐 key 比较 |
| **I-10** | 步末只清「本轮未写入的」路由型通道 | 调用计数探针 |
| **I-11** | 重复执行 ⇒ 状态与执行序列逐项相等 | 重复 ≥ 3 次比较 |
| **I-12** | 节点表顺序 == 执行顺序 | 两份规格的执行序列比较 |
| **I-13** | 同一份规格可安全跑两次 | 两个独立 `SchedulerState` 的结果相等 |
| **I-14** | 「条件边」字段恒空；非空即失败 | 填值用例抛错 |
| **I-15** | 节点异常原样传播 | 异常对象 `is` 同一 |

> **规模口径**：**不设**墙钟耗时预算（CI 假红）⇒ 全部判据用**结构口径**
> （执行次数 / 调用次数 / 逐元素相等 / 集合相等）—— 沿用 B5F1 / B5F2 的同款口径。
