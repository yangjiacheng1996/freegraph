## 1. 调度抽象（四个类型 + 两个入口 · 名字逐字冻结）

| 项 | 契约 |
|---|---|
| 宿主模块 | `freegraph.runtime.superstep`（L2 · 独立文件 · 裁定 17） |
| 导出 | `freegraph.runtime.__all__` **新增 6 个**：`GraphSpec` · `NodeSpec` · `SchedulerState` · `SuperStepResult` · `run_super_step` · `run_super_steps`（14 → **20**） |
| 图规格 | `GraphSpec(channels: dict[str, Channel], nodes: dict[str, NodeSpec], edges: dict[str, tuple[str, ...]], *, conditional_edges: dict[str, Any] = <空映射>)` —— ⚠️ **`conditional_edges` 的缺省值 MUST 用「工厂语义」实现**（dataclass 的 `default_factory` 等价）⇒ **MUST NOT** 用字面可变默认值（`= {}`）⇒ dataclass 会抛 `ValueError: mutable default <class 'dict'>`（**实测**）· `channels` MUST 是**可变** `dict`（FR-034 · **MUST NOT** 用 `MappingProxyType` —— B4F1 的 `SchemaSpec.channels` 是只读映射，形态不同） |
| 节点规格 | `NodeSpec(subscribes: tuple[str, ...], run: Callable[[dict[str, Any]], dict[str, Any]])` |
| 调度状态 | `SchedulerState()` —— **由调用方持有**（裁定 16）· 承载「已消费版本」+ 轮次计数 |
| 单轮结果 | `SuperStepResult(state: dict[str, Any], executed: tuple[str, ...], node_writes: dict[str, dict[str, tuple[Any, ...]]], steps: int)` |
| 入口 1（单轮） | `run_super_step(spec: GraphSpec, state: SchedulerState) -> SuperStepResult` |
| 入口 2（多轮） | `run_super_steps(spec: GraphSpec, state: SchedulerState \| None = None, *, max_steps: int = 25) -> SuperStepResult` |
| 依赖 | **只依赖标准库**（`collections.abc` · `dataclasses` · `typing`）· MUST NOT import 第三方（L2 · FR-022） |
| **节点表 MUST 保序** | `nodes` 的**迭代顺序** = **同轮执行顺序**（FR-013 · 裁定 9）⇒ MUST NOT 被调度器重排 |

> ⚠️ **名字是跨 feature 契约**：**B7F2**（`compile()`）· **B7F3**（`invoke()`）· **B8F1**（条件边路由）·
> **B9F1**（`Command`）· **B12F1**（并发）**全部**直接消费本契约 ⇒ 名字与语义**逐字冻结**。
> ⚠️ **「逐字冻结」冻结的是**名字**与**语义**，不是**实现写法**：上表的 `dict[...]` 与「缺省 = 空映射」
> 是**语义要求**（保序 + 可变）⇒ 实现 MAY 用等价机制实现（如 `default_factory`），**MUST NOT** 改变
> 可观察语义（**可增补** · **保序** · **缺省为空**）。
>
> ⚠️ **命名消歧（`state` 二义）**：入口参数 `state` = **`SchedulerState`**（调度记录 · 版本与已消费版本）；
> `SuperStepResult.state` = **合并后的通道值字典**。两者**不是**同一个东西 ⇒ 两个名字**逐字冻结**
> （改名会波及 B7F2 / B7F3 / B9F1 / B12F1）⇒ **MUST NOT** 改名，只 MUST 在文档中消歧。
> ⚠️ **两个计数器**：`SchedulerState.step` = **执行轮**计数（**不含**空轮 · 即 FR-011 的上限计数口径）；
> `SuperStepResult.steps` = **实际迭代轮数**（**含**那次空轮）⇒ 两者**不是**同一个量。

## 2. 图规格（`GraphSpec`）

### 2.1 三部分 + 一个预留字段

| 部分 | 形态 | 语义 | 校验（**MUST 显式失败**） |
|---|---|---|---|
| **通道映射** `channels` | `dict[str, Channel]` | key → 通道（**B5F1** 的 `build_channels` 产物 · **可变** `dict`） | 值 MUST 是 `Channel` 实例；key MUST 是 `str` |
| **节点表** `nodes` | `dict[str, NodeSpec]`（**保序**） | 节点名 → 节点规格 | MUST **非空**；节点名 MUST 是 `str` |
| **边表** `edges` | `dict[str, tuple[str, ...]]` | 源节点名 → 目标节点名序列 | 源 / 目标 MUST **都在节点表里** |
| **条件边** `conditional_edges` | `dict[str, Any]`（**缺省 = 空映射** · 工厂语义） | **本轮恒为空**（预留 · 裁定 25） | **非空 ⇒ 显式失败**（FR-033） |

> ⚠️ **初始化写入豁免**（裁定 31 · 2026-11-11 分析轮 · 发起者批准）：调用方在**跑之前**直接向通道对象
> 写入**初始值** = 「写入只由调度层发起」的唯一豁免（走通道自身的 `update()` ⇒ **通道语义 /
> 归约器口径不绕道**）⇒ 该写入**不进**调度层的版本推进路径（版本按 §3.2 的「首次查看 ⇒ 版本 1」
> 口径初始化）⇒ **跑之后**（含任一轮执行期间）的直接写入 MUST NOT 成为触发依据。
> ⚠️ **本节是「初始化写入豁免」口径的**复述**（裁定 35）——**唯一权威落点 = spec 的 FR-001 ⚠️**
> ⇒ 修改该口径时 MUST **同步**本节与 spec 的 FR-002 ⚠️ / Edge Cases / 引文差异 ⑧ / 裁定 31。

### 2.1.1 校验的执行时机与失败信号（**构造时** · 逐条唯一）

| 项 | 口径 |
|---|---|
| **执行时机** | **构造时** —— `GraphSpec` / `NodeSpec` 的**构造** ⇒ 即刻**显式失败**（MUST NOT 推迟到运行期 · 裁定 32）⇒ 下游 **B6F1 / B7F2** 的适配器 MUST 依赖此口径 |
| **V-1**（`subscribes` 含**不存在**的通道 key） | 内置 **`ValueError`**（裁定 32 —— data-model §6 原写「`KeyError` / 内置 `ValueError`」二选一 ⇒ **收敛为 `ValueError`**） |
| **V-2**（边的**源 / 目标**不在节点表） | 内置 **`ValueError`** |
| **V-3**（节点表**为空**） | 内置 **`ValueError`** |
| **V-8**（`conditional_edges` **非空**） | **显式失败**（本轮不实现求值）· **内置 `ValueError`**（与 V-1…V-3 同族 —— 都是「传进来的东西不对」· **一致性订正** ⚠️ **2026-11-11 分析轮第 6 次**：原写「类型不冻结」⇒ 与本表「不变式」行的「只用**两种内置异常**」**自相矛盾** ⇒ **冻结为 `ValueError`**（判据**只收紧**：原口径允许任意类型 ⇒ 本口径唯一化）· 落点：spec **SC-025** · data-model §6 · tasks **T060**） |
| **V-4**（节点返回值**不在** {`dict`, `Command`, `list[Command \| dict]`} 之内，含 `None`） | 内置 **`TypeError`**（**运行期** · FR-009） |
> ⚠️ **回溯修订（2026-11-11 · B9F1 · 发起者特批 · 破 L1 冻结面）**：本行原为「节点返回值**不是 `dict`**」⇒ **B9F1 放宽**了返回形态（增 `Command` 与**命令列表**）⇒ 本行随之改为「**不在三形态之内**」（`None` **仍然**显式失败 —— 该口径**未放宽**）⇒ 见 B9F1 的 **裁定 21**。
| **不变式** | 一个 feature 只用**两种内置异常**（`ValueError` / `TypeError`）⇒ 「同一场景出现两种异常类型」的出现次数 MUST == **0** · ⚠️ **2026-11-11 分析轮第 6 次订正**：本行原只覆盖 V-1…V-4 ⇒ **V-8 原写「类型不冻结」**会与之冲突 ⇒ 已冻结为 `ValueError`（**只收紧** · 不新增判据） |

### 2.2 节点规格（`NodeSpec`）

| 字段 | 语义 | 校验 |
|---|---|---|
| `subscribes: tuple[str, ...]` | 该节点**订阅**的通道 key —— **既管触发判定、也管入参内容**（裁定 2） | 每个 key MUST 在 `channels` 里 |
| `run: Callable[[dict[str, Any]], dict[str, Any]]` | 节点函数（**C5**：`f(state: dict) -> dict`） | MUST 可调用 |

> ⚠️ **「订阅」是**同一个**集合**（FR-008 的 ⚠️ 段）⇒ MUST NOT 存在「订阅了某通道却读不到它的值」的情形。
> ⚠️ 节点**不订阅**任何通道、只被**边**触发 ⇒ 其入参是**空 `dict`**（合法）。

## 3. 触发判定（**版本号** · 两类触发源）

### 3.1 触发源与版本

| 触发源 | 标识（**逐字冻结**） | 版本 | 何时 +1 |
|---|---|---|---|
| **通道触发源** | `("c", 通道 key)` | 该通道的**写入版本**（**每通道独立** ⇒ 与上游的**全局**单调计数器构成**机制差异** · research **D-03** · parity **P-02**） | 该通道被**成功写入**（`Channel.update()` 返回**真**）时 |
| **边触发源** | `("e", 源节点名)` | 该节点的**执行版本** | 该节点**执行成功**返回时 |

> ⚠️ **两类触发源的标识 MUST 用**不同的空间**（`"c"` / `"e"` 前缀）** ⇒ 避免「通道 key 与节点名同名」
> 时互相覆盖（data-model §3.1 · 裁定 3）。

### 3.2 判定规则（**逐字**）

```
节点 N 被触发 ⟺ ∃ 触发源 s ∈ sources(N) : has_value(s) ∧ version(s) > seen(N)[s]
```

* `seen(N)` = `SchedulerState` 里 N 的**已消费版本**记录（`节点名 → {触发源 → 版本}` · 裁定 16）。
* **初始状态的版本口径**（裁定 21 · research **D-01**）：调度器**第一次**查看某通道时，
  若该通道**已有值** ⇒ 其版本记为 **1**（「**有值**」即算已写过一次）。
  ⚠️ **「查看」的操作点 MUST 冻结**（裁定 31 · 2026-11-11 分析轮 · 发起者批准）：=
  **触发判定阶段枚举该节点的订阅通道时** ⇒ 必然**早于**任何写入 ⇒ 版本号**唯一确定**
  ⇒ 与「全部合并成功后才推进版本」（§5.1）**互不冲突**。
  ⚠️ **初始值的唯一合法动作**（裁定 31）：跑**之前**由调用方直接向通道对象写入
  （§2.1 的「初始化写入豁免」）⇒ 版本恒为 **1**（初始态）。
* **消费时点**：N 被**准备执行**时，消费其**全部**触发源的当前版本（⇒ 同一版本**不重复触发**）。
* **「有值」是「逐触发源」的合取项**：通道触发源的判定式 =
  `has_value(channel) ∧ version(channel) > seen(N)[channel]`
  —— **不是**「节点订阅集整体有值」（逐节点 AND 的读法**禁止** ⇒ 会让 FR-016 /
  US6 的 C4 节点边界用例不可成立）；**无值**的通道触发源**不计入**
  （`version > seen` 对它不成立）⇒ 与上游 `is_available() ∧` **逐字同源**
  （research **D-01** · 核实版本 `langgraph 1.2.11` · `_algo.py:1260-1278`）。
* **边触发源无「值」概念**：其判定式 = `version(node) > seen(N)[node]`
  （源节点的执行版本本身即「发生过执行」的信号）⇒ 与通道触发源**统一**为
  「单调递增版本 + 可选的有值合取项」。
* **未被订阅通道的版本基值 = 0**（裁定 34 · **2026-11-11 分析轮第 6 次补入本契约** ——
  ⚠️ 该 MUST 原只落在 spec **FR-002 ⚠️** 与 data-model §3.2 ⇒ **唯一权威契约缺它** ⇒ 本节补齐）：
  某通道若**从未被任何节点订阅** ⇒ 永不被「首次查看」⇒ 其写入版本的**基值 MUST 取 0**
  （`Channel.update()` 返回真 ⇒ +1）⇒ 该通道**无订阅者 ⇒ 永不触发**
  ⇒ 唯一作用是**消除歧义**（避免实现各取一个基值 · **可观察影响为零**）。

### 3.3 边触发

| 规则 | 内容 |
|---|---|
| 边 `(P → N)` | P **执行成功**后，其**执行版本** +1 ⇒ N 在**下一轮**被触发（research **D-09** · 与上游 Branch→PUSH **语义等价**） |
| 边与通道**同时**触发 | N **只执行一次**（一个节点一轮内至多一次） |

## 4. 一个 super-step 的五阶段（**顺序固定** · FR-001）

| # | 阶段 | 产物 | 关键规则 |
|---|---|---|---|
| ① | **触发判定** | 被触发的节点集合 | §3 的规则 · 顺序 = **节点表顺序** |
| ② | **任务准备** | 任务集合 + **入参** | 入参 = `read_channels(子映射)`（B5F2 的稀疏读 · **同一处**实现）· **子映射 MUST 按「通道映射的顺序」构造**（**不是**订阅声明顺序 · FR-008 ⚠️ · 裁定 26）· 每个节点拿到**自己的**字典 |
| ③ | **任务执行** | 节点的返回值 | 按**节点表顺序**串行（FR-013）；节点异常 **原样**传播（FR-015） |
| ④ | **写入收集** | **待写入**（按节点分组） | 执行期间通道**正式值 MUST NOT** 被改写（FR-006） |
| ⑤ | **写入合并** | 合并后的状态 + 通道版本 + **步末清空** | §5（合并 MUST 按**通道映射的顺序** · 版本 **全部合并成功后**才推进 · 出错 ⇒ 快照回滚 + 版本不推进 · **步末清空 = §5.2**） |

## 5. 写入合并（**批量** · FR-005）

### 5.1 合并规则

| 规则 | 内容 | 上游对照 |
|---|---|---|
| **批量** | 每个通道**一次** `Channel.update(values)`（`values` = 该通道本轮收到的**全部**写入值，按**节点表顺序**排列） | research **D-07**（上游 `pending_writes_by_channel` ⇒ 逐字同构） |
| **归约型** | 按序逐个归约（`reducer(当前值, 新值)`） | 同上 |
| **覆盖型 · 多写** | **显式失败** —— `InvalidChannelUpdateError`（其 `key` 指向该通道） | 上游同款（`last_value.py` 的 guard） |
| **未知 key** | **显式失败** —— `InvalidUpdateError`（其 `invalid_keys` 列出**全部**未知 key） | ⚠️ 上游 **warning + 静默忽略**（research **D-06** · parity **P-07**） |
| **版本推进** | 合并阶段先记录「本轮**哪些**通道写入了值」（`update()` 返回**真**）⇒ **全部合并成功后**才对它们各 **+1**（**值逐字相等也算推进**）· 本轮出错 ⇒ **一个都不推进** | research **D-03** · FR-002 ⚠️ · §5.4 |
| **校验顺序** | ① **未知 key**（FR-007）→ ② **覆盖型多写**（FR-005 ②）→ ③ **逐通道合并**（§5.4）⇒ 一轮内同时命中多类错误时**只抛第一个**（顺序**固定** ⇒ 可复现） | —（**2026-11-11 分析轮** · 口径补齐） |

### 5.2 步末清空（**只清「本轮未被写入的」路由型通道**）

| 规则 | 内容 | 上游对照 |
|---|---|---|
| 清空范围 | **只**对**路由型**通道调 `clear()`；**且只清「本轮未被写入的」** | research **D-05**（上游对「**本步未更新**的通道」调 `update(EMPTY_SEQ)`） |
| **两个入口都执行** | **单轮入口** `run_super_step` 跑完一轮后**同样**执行本节的步末清空（与上游「**每步末**都清未更新的通道」**逐字同构** · 裁定 33）⇒ 两个入口的**语义 MUST 一致**（同一份规格 · 单轮跑与多轮跑得到相同的通道状态）⇒ MUST NOT 存在「单轮入口保留路由型通道的值」这第三种语义 | 同上（上游的「一步」== freegraph 的单轮入口） |
| **路由型的判定** | MUST 以 `isinstance(channel, EphemeralValue)` 判定（**2026-11-10 分析轮拍板**）⇒ MUST NOT 用「`reducer is None`」等**启发式**（`LastValue`（覆盖型）与 `EphemeralValue`（路由型）**都无归约器** ⇒ 启发式会误清**覆盖型**通道 ⇒ 违反 FR-014 / SC-012 / I-10） | `channel.py:411`（`EphemeralValue` · 路由型）· `channel.py:188`（`LastValue` · 覆盖型） |
| 覆盖型 / 归约型 | MUST **保留**其值（MUST NOT 调 `clear()`） | 上游对其 `update([])` **no-op** · 值保留 |
| 本轮写过的路由型 | MUST **保留**其值到**下一轮**（⇒ B8F1 的条件边路由读得到） | research **D-05** |
| 清空**不是**写入 | 通道版本 MUST **不**推进 ⇒ 订阅者 MUST **不**被再次触发 | FR-014 的 ⚠️ 段 |
| **「本轮被写入过」的判定** | = 本轮该通道 `update()` 返回**真** ⇒ **含**「归约后与旧值**逐字相等**」的情形（与 FR-002 的「逐字相等也算推进」同源）⇒ 该路由型通道本轮**不清空**、其值存活到下一轮 | research **D-03** · FR-002 · FR-014 |

### 5.3 结果对象的字段语义（**`SuperStepResult`**）

| 字段 | 语义 | 单轮入口 | 多轮入口 |
|---|---|---|---|
| `state` | 合并后的**稀疏状态** | 本轮合并后的状态 | **最后一轮**合并后的状态 |
| `executed` | 执行过的节点名（**按执行顺序**） | 本轮 | **累计**（跨轮按轮次先后拼接） |
| `node_writes` | **按节点分组**的待写入（节点名 → 通道 key → 值序列） | 本轮 | **累计**：同一节点的**同一通道** ⇒ 跨轮按**轮次先后**拼接值序列（**MUST NOT** 把**不同通道**的值混进同一序列 —— 通道维度始终保持分组） |
| `steps` | **实际迭代轮数**（**含**那次用于发现「任务集为空」的**空轮**） | 恒为 **1** | 实际迭代轮数 |

> ⚠️ **「轮数」只认 `steps`**（= **实际迭代轮数** · **含**那次用于发现「任务集为空」的**空轮**）⇒
> 空任务集 ⇒ `steps == 1` 且 `executed == ()`；执行了 1 轮 ⇒ `steps == 2`。
> （⚠️ **2026-11-11 分析轮订正** · 裁定 30：原另立「**执行了节点的轮数**」为判据 ⇒ 该量
> **无字段承载**（本契约的四个字段**逐字冻结**）⇒ 取消 ⇒ 一律用 `executed` + `steps`
> 两个**可观测**量表述。）
> ⚠️ `node_writes` 是 **B8F1** 的复用前提（FR-006）⇒ **按节点分组**是 MUST NOT 变更的形态。
> ⚠️ **本表的三列差异 = 跨 feature 冻结的判据**（裁定 34 · 2026-11-11 分析轮第 3 次）⇒
> 「多轮入口的 `executed` 累计 / `node_writes` 按轮次先后拼接 / 单轮入口 `steps` **恒为 1**」
> MUST 在本 feature 有断言（**SC-001**）⇒ 落点 = tasks **T064**。

### 5.4 原子性（FR-032）

| 规则 | 内容 |
|---|---|
| 触发场景 | 节点抛异常 · 节点返回 schema 外的 key · 归约器抛错 · 覆盖型多写冲突 |
| 效果 | 本轮产生的**全部**待写入 **MUST NOT** 被合并 ⇒ 通道的正式值 MUST 保持**本轮开始前**的样子 |
| 禁止 | MUST NOT 留下「一部分通道已更新、一部分没更新」的中间态 |
| **快照** | 合并阶段 MUST 在**首次写入之前**对**本轮将被写入的通道**取快照（值 / 有无值） |
| **回滚** | 任一环节出错 ⇒ MUST 用快照**逐通道回滚**（`clear()` + `update([快照值])` · **MUST NOT** 套归约器 ⇒ 逐字还原）⇒ 该通道值 MUST 与轮初**逐字相等** · 回滚顺序 MUST 与合并顺序一致（按**通道映射顺序**）· ⚠️ **快照为「无值」时的分支**（**2026-11-11 分析轮第 6 次补齐** —— 原文只写「`clear()` + `update([快照值])`」⇒ 未覆盖「轮初本就无值」的通道）：快照**无值** ⇒ **只** `clear()`（**MUST NOT** 调 `update([...])` —— 无值快照**不是**一个可写回的值）；快照**有值** ⇒ `clear()` + `update([快照值])` |
| **版本同退** | 本轮出错 ⇒ 通道的**值**回滚 **且** **写入版本不推进**（FR-002 ⚠️）⇒ 无「值回滚、版本前进」的不一致 · 无**幽灵触发** |
| **豁免** | 回滚路径对覆盖型 / 归约型通道的 `clear()` **不计入** §5.2 的「步末清空」判据（§5.2 只约束**步末**） |
| **合并顺序** | 通道的合并 MUST 按**通道映射的顺序**进行 ⇒ 合并与回滚**可复现**（MUST NOT 依赖字典哈希序） |
| **回滚面** | 四类错误中**只有「归约器抛错」需要真正回滚**：「节点抛异常」发生在**执行阶段** · 「未知 key」与「覆盖型多写」在**合并前**被拦下（§5.1）⇒ 三类**天然**满足整轮原子 |

## 7. 状态与规模的不变量（**逐条可断言**）

| # | 不变量 | 可判定方式 |
|---|---|---|
| **I-1** | 节点入参 MUST 是**普通 `dict`**（`type(x) is dict`）且**只含**「订阅集 ∩ 有值集」 | `type(...) is dict` + key 集合相等 |
| **I-2** | 入参 MUST 由 **B5F2 的稀疏读**产出（**同一处**稀疏语义）⇒ MUST 等于 `read_channels(子映射)` 的结果；**子映射 MUST 按「通道映射的顺序」构造**（**不是**订阅声明顺序 · FR-008 ⚠️ · 裁定 26） | 与 `read_channels(子映射)` 的结果**逐字相等**（key 集合**相同** + key **顺序相同** + 逐 key 值**同一对象**） |
| **I-3** | 同一版本 MUST NOT 重复触发同一节点 | 一轮内某节点的执行次数 ≤ **1** |
| **I-4** | 未被触发的节点执行次数 == **0** | 执行计数断言 |
| **I-5** | 同轮多写归约通道 ⇒ 结果 == **两次写入的归约结果**（逐元素相等） | 与 `operator.add` 逐元素相等 |
| **I-6** | 同轮多写覆盖型通道 ⇒ **显式失败**（**不**静默覆盖） | 抛 `InvalidChannelUpdateError` |
| **I-7** | 未知 key ⇒ **显式失败**，且 `invalid_keys` == 实际未知 key 集合 | 抛 `InvalidUpdateError` |
| **I-8** | 执行期间通道**正式值** MUST NOT 被改写 | 任务内读取的通道值 == 轮次开始时的值 |
| **I-9** | 一轮出错 ⇒ **全部**通道的值与**轮次开始前**逐字相等 | 快照逐 key 比较 |
| **I-10** | 步末 MUST NOT 对覆盖型 / 归约型调 `clear()`；MUST NOT 清「本轮写过的」路由型 | 调用计数（探针通道） |
| **I-11** | 同一份规格重复执行 ⇒ 合并后状态与执行序列**逐项相等** | 重复执行 ≥ 3 次后逐项比较 |
| **I-12** | 节点表顺序 **==** 执行顺序（重排节点表 ⇒ 执行序列随之改变） | 两份规格的执行序列比较 |
| **I-13** | 同一份规格可**安全跑两次**（调度状态由调用方持有 ⇒ 互不干扰） | 两次独立 `SchedulerState` 的结果逐项相等 |
| **I-14** | 「条件边」字段 MUST **恒为空**；非空 ⇒ **显式失败** | 填值用例抛错 |
| **I-15** | 节点异常 MUST **原样**传播（不包装 · 不吞掉） | 异常类型与对象 `is` 同一 |
