## 3. 触发判定（**版本号** · **唯一**触发源 = **边**）

> ⚠️ **2026-11-12 · 上游对齐（P1-0）**：本节**整体重写** —— 触发源**只保留边**，
> 「**通道触发源**」空间（`("c", key)`）**已删除** ⇒ 理由与上游锚点见 §3.0。

### 3.0 为什么只有边（**上游同款**）

| 项 | 上游 | freegraph（**本契约的当前口径**） |
|---|---|---|
| 触发源 | **恒为** `branch:to:<节点>`（**边**） | **恒为** `("e", 源节点名)`（**边**） |
| 节点订阅的状态通道 | 在 `channels=` 里 ⇒ **只决定读什么**，**不参与触发** | 在 `subscribes` 里 ⇒ **只决定读什么**，**不参与触发** |
| 入口 | `START` 伪节点 + `add_edge(START, "a")` ⇒ 入口边只写过一次 | `__start__` 哨兵 + `edges={"__start__": ("a",)}` ⇒ 入口边只写过一次 |

**上游锚点**（核实版本 `langgraph 1.2.11`）：
`langgraph/graph/state.py:1531-1532`（`proc.triggers` 恒为 `branch:to:<node>`）·
`:1534`（节点读的状态通道在 `channels=` · **不参与触发**）·
`langgraph/constants.py:30`（`START = sys.intern("__start__")`）·
`langgraph/graph/state.py:321`（`add_edge(START, "a")` · 入口边的写法）。

**可观察后果**（实测 · 同一拓扑：节点 `a` 写通道 `log`；节点 `b` **订阅** `log` 但**无入边**）：

```
上游      ran = ['a']       ⇒ b 从未执行
freegraph ran = ['a','b']  ⇒ b 被执行 ⇒ 随后 GraphRecursionError（自触发循环）
```

⇒ 本次重写**消除**了「节点写自己订阅的通道 ⇒ 自触发循环」，并使**同一张图**在两侧**跑出同一批节点**。

### 3.1 触发源与版本

| 触发源 | 标识（**逐字冻结**） | 版本 | 何时 +1 |
|---|---|---|---|
| **边触发源** | `("e", 源节点名)` | 该节点的**执行版本** | 该节点**执行成功**返回时 |

**入口哨兵**：源节点名为 `__start__` 的边触发源，其版本**恒为 1**（入口边只写过一次 ⇒
入口节点**只在第 1 轮**被触发一次）⇒ 与上游 `START` 的**同款**语义。

> ⚠️ **触发源标识的空间**：**唯一**的空间（`"e"` 前缀）⇒ 「通道 key 与节点名同名」的消歧需求**不复存在**
> （原「通道触发源」空间随本次重写**删除**）。
>
> ⚠️ **2026-11-13 · B7F4 回溯修订 R-2（拆分而不删）**：引入「**触发源组**」——
> **每条入边一个组**（组 = 该边的**全部**源的边触发源 · `tuple[("e", 源节点名), ...]`）⇒
> **单源边的组是单元素** ⇒ 与原「触发源」**逐字等价** ⇒ ⇒ **本节的触发源定义逐字保留**
> ⇒ 多源口径的**唯一权威** = `specs/b7f4-multisource-join/contracts/superstep-multisource-contract.md` §3.1。

### 3.2 判定规则（**逐字**）

```
节点 N 被触发 ⟺ ∃ 边触发源 s ∈ sources(N) : version(s) > seen(N)[s]
```

* `sources(N)` = **所有指向 N 的边**的**源**节点（静态边 ∪ 动态边 · **同处一个空间** ⇒ 叠加）。
* `seen(N)` = `SchedulerState` 里 N 的**已消费版本**记录（`节点名 → {触发源 → 版本}` · 裁定 16）。
* **无「有值」合取项**：边触发源**没有**「值」概念 ⇒ 判定式**只有**版本比较
  （源节点的执行版本本身即「发生过执行」的信号）。
* **消费时点**：N 被**准备执行**时，消费其**全部**触发源的当前版本（⇒ 同一版本**不重复触发**）。
* **未触发节点的执行次数 == 0**：没有入边 ⇒ `sources(N)` 为空 ⇒ 永不触发。

> ⚠️ **2026-11-13 · B7F4 回溯修订 R-3 / R-5（拆分而不删）** —— **上式逐字保留**，
> 并**追加**「**组**」口径（**单源组逐字退化为上式** ⇒ **既有行为零变化**）：
>
> ```
> 节点 N 被触发 ⟺ ∃ 组 g ∈ groups(N) : ∀ s ∈ g : version(s) > seen(N)[s]
> ```
>
> * **组内全 · 组间任一**（**AND / 屏障** · **上游同款**）⇒ ⇒ **多源口径**的
>   **唯一权威** = `specs/b7f4-multisource-join/contracts/superstep-multisource-contract.md` §3.2；
> * **记账范围（R-5）**：N 被**准备执行**时 ⇒ **只消费「已满足的组」的源** ⇒
>   **逐源各记一条** `seen[(kind, ident)] = version(ident)` ⇒ **未满足的组不记账**
>   ⇒ 屏障**后来齐了仍能再次触发**（**上游同款**）⇒ ⇒ **单源口径的记账逐字不变**
>   （未满足 ⇒ `version ≤ seen` ⇒ 版本只增不减 ⇒ `version == seen` ⇒ **同值记账**
>   ⇒ **可观察行为零变化**）⇒ ⇒ **既有断言一条不删**。

### 3.3 边触发

| 规则 | 内容 |
|---|---|
| 边 `(P → N)` | P **执行成功**后，其**执行版本** +1 ⇒ N 在**下一轮**被触发（research **D-09** · 与上游 Branch→PUSH **语义等价**） |
| **入口边** `(__start__ → N)` | 入口哨兵的版本**恒为 1** ⇒ N 在**第 1 轮**被触发（**且仅一次**）⇒ 与上游 `add_edge(START, "a")` **同款** |
| 边与边同时触发 | N **只执行一次**（一个节点一轮内至多一次） |

## 4. 一个 super-step 的**七个阶段**（**顺序固定** · FR-001 · ⚠️ **2026-11-13 · B12F1 回溯修订 T-10**）

> ⚠️ **B12F1 的回溯修订（T-10 · 拆分而不删）**：阶段 ③ 由「按**节点表顺序串行**执行」

### 5.3 结果对象的字段语义（**`SuperStepResult`**）

### 5.4 原子性（FR-032）

| 规则 | 内容 |
|---|---|
| 触发场景 | 节点抛异常 · 节点返回 schema 外的 key · 归约器抛错 · 覆盖型多写冲突 |
| 效果 | 本轮产生的**全部**待写入 **MUST NOT** 被合并 ⇒ 通道的正式值 MUST 保持**本轮开始前**的样子 |
| 禁止 | MUST NOT 留下「一部分通道已更新、一部分没更新」的中间态 |
| **快照** | 合并阶段 MUST 在**首次写入之前**对**本轮将被写入的通道**取快照（值 / 有无值） |
| **回滚** | 任一环节出错 ⇒ MUST 用快照**逐通道回滚**（`clear()` + `update([快照值])` · **MUST NOT** 套归约器 ⇒ 逐字还原）⇒ 该通道值 MUST 与轮初**逐字相等** · 回滚顺序 MUST 与合并顺序一致（按**通道映射顺序**）· ⚠️ **快照为「无值」时的分支**（**2026-11-11 分析轮第 6 次补齐** —— 原文只写「`clear()` + `update([快照值])`」⇒ 未覆盖「轮初本就无值」的通道）：快照**无值** ⇒ **只** `clear()`（**MUST NOT** 调 `update([...])` —— 无值快照**不是**一个可写回的值）；快照**有值** ⇒ `clear()` + `update([快照值])` |
| **版本同退** | 本轮出错 ⇒ 通道的**值**回滚 **且** **写入版本不推进**（FR-002 ⚠️）⇒ 无「值回滚、版本前进」的不一致 · 无**幽灵触发** |
| **豁免** | 回滚路径对覆盖型 / 归约型通道的 `clear()` **不计入** §5.2 的「步末清空」判据（§5.2 只约束**步末**） |
| **合并顺序** | 通道的合并 MUST 按**通道映射的顺序**进行 ⇒ 合并与回滚**可复现**（MUST NOT 依赖字典哈希序） |
| **回滚面** | 四类错误中**只有「归约器抛错」需要真正回滚**：「节点抛异常」发生在**执行阶段** · 「未知 key」与「覆盖型多写」在**合并前**被拦下（§5.1）⇒ 三类**天然**满足整轮原子 |
