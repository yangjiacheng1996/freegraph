## 0. TL;DR — 五句话

1. **剥离可行，且路径唯一**：LangGraph 的图运行时（state / node / edge）**零账号、零出站**就能跑（已实跑，`BLOCKED: []`）；但 `langchain-core` **硬依赖 `langsmith` 包**，所以 freegraph 内核必须**完全不碰 `langchain-core`**，运行时依赖压到「**零**」——基础安装不装任何第三方包（Q3 + 宪法修订记录 v1.2.0 · 2026-11-05）。
2. **LangSmith 的付费墙锁的不是「可观测」，而是「托管 + 自治」**：Developer 档（$0）实得 **31 个勾选项**（29 个产品功能 + 2 个支持渠道），Tracing / Evals / Datasets / Annotation Queue / Prompt Hub / **Studio** 全在免费档；被锁的只有 5 类——Deployment 托管扩缩、Engine、Tuned Evaluators、Insights、Bulk export（Plus 也锁）+ Unlimited agents。（Q1 / Q2）
3. **真正该被消灭的是「免费但需账号」这一层**：免费档也强制 LangSmith 账号 + API key，连**本地开发的 Studio UI 都要过云**（浏览器 → `smith.langchain.com` → 反连本地 `baseUrl`）；「自托管」也不等于零账号——standalone server 仍需 `LANGGRAPH_CLOUD_LICENSE_KEY` 且要向 `beacon.langchain.com` 出网。（Q2）
4. **差异化叙事只能落在三条硬承诺上**：**零账号 / 零出站 / 零 license key**。对标「功能更多」没有说服力（那些功能官方本来就免费），对标「免费那一半且不需要账号」才成立。（Q1 §3.3 / Q2 §5）
5. **可视化走路线 B**：OTel 兼容协议 + 内嵌轻量 UI（62–101 人日），不做路线 A（自研整套 Studio，245–415 人日）；MVP 只做三件套——图视图 / trace 时间线 / 状态快照与回放。**没有任何现成 OSS 提供「交互式图运行时 IDE」**，这是 freegraph 的独占位置。（Q6；**Q9 精化**：精确说是「没有 OSS 提供**图视图**」——chat/time-travel 已有 MIT 的 Agent Chat UI）

## 1. 术语锚点：先统一语言（Q4 §3.4）

> 这是全项目**唯一权威**的术语对照表；其他报告引用它，不得各写各的。

**官方三层分类**（`harness/docs/oss/python/concepts/products.md:9-40`）：

| 层 | 官方术语 | 对标产品 | 我的定位 |
|---|---|---|---|
| **Runtime** | LangGraph | Pregel runtime / Graph API | **freegraph = 这一层** |
| **Framework** | LangChain | Abstractions / Integrations | **freechain = 这一层**（后续独立项目） |
| **Harness** | Deep Agents | Predefined tools / Prompts / Subagents | **不做** |

官方原话：「LangChain is built on top of LangGraph, you don't need to know LangGraph to use LangChain.」

**自造表述 → 官方术语（我以后只用右列）**：

| 自造表述 | 官方术语 | 处置 |
|---|---|---|
| 「三大基础功能」 | **Graph API: State Schema + Nodes + Edges**（另含 Command / interrupt / Send / durability） | 弃用 |
| 「六大概念」 | **LangChain v1: Model / Tools / Messages / Structured output(+middleware)** | 弃用（v1 已断裂） |
| 「tool 循环智能体」 | **Agent（`create_agent`）/"the basic agent loop"** | 弃用 |

**「六大概念」为什么断裂**（v1 迁移结果）：model / message / tool / embeddings 留在 `langchain`；**chain / retriever / indexing / hub 迁到 `langchain-classic`**；**output parser 被 `ToolStrategy` / `ProviderStrategy` 取代**；prompt 从独立模板类变成 agent 参数 + middleware。

**另一条关键源码事实**：v1 的 `create_agent` 内部就是构造一个 `StateGraph` 再 `compile()`（`langchain/agents/factory.py`）→ LangChain v1 ＝ **把 agent Graph 继续封装**。freegraph / freechain 的分工，恰好就是把这两层重新拆开。

## 2. 竞品与付费墙：LangSmith 到底卖什么（Q1 + Q2）

### 2.1 它不是「一个功能」，是一条产品线（15 个功能块 / 3 组）

| 组 | 功能块 |
|---|---|
| **A. Agent Improvement** | Observability/Tracing、Monitoring/Dashboards、Insights、Evaluation（online+offline）、Datasets、Annotation Queue、Prompt Hub & Playground |
| **B. Agent Infrastructure** | Studio、Deployment（Agent Server）、LLM Gateway |
| **C. Autonomy / Managed** | Engine、Fleet、Sandboxes、Context Hub、Agent Registry、Marketplace（模板库）、Managed Deep Agents |

**它的数据模型地基是四层**（这一层我直接抄）：run（最小工作单元，官方自己类比 **OTel span**）→ trace（run 树）→ thread（`thread_id` 串联的多轮会话）→ trajectory（thread 的扁平投影）。单 trace 上限 25,000 runs。

> **我的判断**：官方把 run 类比成 OTel span，意味着「用 OTel 而不是自造格式」不是我拍脑袋，是官方路径。Q6 的路线 B 由此坐实。

### 2.2 付费墙的精确形状（DOM 级解析定价页 74 行勾选矩阵）

**Developer 档（$0）实得 31 项 = 29 个产品功能 + 2 个支持渠道**：

| 分区 | ✅ 免费档就有 | ❌ / N/A（付费墙） |
|---|---|---|
| Observability & Evaluation | Tracing、Monitoring、Online+offline evals、Dataset collection、**Annotation queue**、**Prompt Hub and Playground** | Insights、Bulk data export、Unlimited agents、Tuned Evaluators |
| Deployment | **LangSmith Studio**、MCP 暴露、实时流式、Agent Authorization(beta) | 1-Click Deploy、Dedicated 扩缩、Scale-to-Zero、Assistants API、30+ endpoints、Cron、鉴权；**整行 N/A** |
| Fleet | 模板、remote MCP、API 触发、LangChain models | 模板共享克隆、Unlimited agents |
| Sandboxes | **全部 7 项** | — |
| LLM Gateway | **全部 8 项** | — |
| Engine | — | **全部 6 项；整行 N/A** |
| Hosting / Security | Support Portal、Community Forum | Platform hosting、SSO、RBAC、SLA…（Enterprise 全套） |

**一句话结论（这张表的价值全在这里）**：

> **用户付费买的是「可运营性」（托管 + 扩缩 + 治理）与「自治性」（Engine 自动提 PR 修复），不是「可观测性」，也不是「调试工具」。**
>
> 可观测 + 调试工具在免费档就给够 → 它们承担的是**获客与生态锁定**（LangChain 家族免费，LangSmith 是唯一变现口）；
> Fleet / Sandboxes / Gateway 即使免费档开放，也**靠成本（LSU）锁**而不是靠档位锁。

**对我项目的直接含义**：freegraph 复刻的那一块，**正好是官方定价里的免费那一半** → 所以差异化叙事不能是「功能更多」，只能是「零账号 + 零出站 + 可离线」。

### 2.3 档位 / 计量 / 限流速查（as-of 2026-11-01，以官方定价页为准）

| 档位 | 价格 | 关键额度 |
|---|---|---|
| **Developer** | **$0 / seat / 月** | 1 seat；**5,000 base traces/月**（仅无付款方式时）；Fleet 7 LSU；Sandboxes 8 LSU + 限 10 个 |
| **Plus** | **$39 / seat / 月** | 无限 seat；10,000 base traces/月；1 个免费 Serverless(Small) deployment；Fleet 37 LSU |
| **Enterprise** | 定制（年付预付） | Cloud / Hybrid / **Self-Hosted**；Custom SSO / RBAC / SLA / Bulk export |
| Startup Build / Scale | 申请制 | 席位折扣 / **$10,000 credits 可用 1 年** |

**三种计量并存**：① **base trace**（一次操作的全部 run，14 天保留）② **extended trace**（180 天，单独计费）③ **LSU**（LangChain Standard Units，**1 LSU = $1**，2026 年的统一抽象单位，Deployment / Engine / Fleet / Sandboxes / Gateway 共用）。

**限流也是「免费」的一部分**：Developer 无付款方式 = 50,000 trace events/hr + 500MB/hr；Developer 有付款方式 = 250,000 + 2.5GB；Plus/Startup = 500,000 + 5.0GB。另有 **per-project / per-user 月度上限**（触限后新 trace 直接丢弃）。通用端点限流 5000/min，trace 上限 25,000 runs。

> **我的判断**：这个限流体系是**稀缺性设计**，本地存储没有对应约束 → 这是可以主动宣传的差异点，freegraph 不该引入任何配额 / seat / LSU 概念。

### 2.4 「免费但需账号」——最该被消灭的一层（Q2 §3.6）

五处具体表现：

1. **Studio 强制账号**：官方前置写明需要 LangSmith account + API key；`langgraph dev` 的 banner 打印 `🎨 Studio UI: https://smith.langchain.com/studio/?baseUrl=http://127.0.0.1:2024` → **本地调试 UI 也要过云**（Studio 本身在 Developer 档免费）。
2. **API key 存在即自动开 tracing**：`langgraph_api/config/__init__.py:675-677` 明写「if langsmith api key is set, enable tracing unless explicitly disabled」。→ **反面教材**：freegraph 要反过来，**环境变量存在也不改变任何行为**。
3. **自托管 ≠ 零账号**：standalone server 仍需 `LANGSMITH_API_KEY` + `LANGGRAPH_CLOUD_LICENSE_KEY`，且要向 `beacon.langchain.com` 出网做 license 校验与用量上报（`langgraph_api/metadata.py:75`）。
4. **Sandboxes 默认 restricted egress**：非 Enterprise 组织连白名单外的目的地都被拦。
5. **Agent Registry 自托管不可用**（Cloud-only）→ 自托管场景没有官方替代品。

> **我的判断**：第 1 条是「可复制缺口」的核心 —— LangGraph OSS 的 `get_graph()` + `draw_mermaid()` 是纯本地能力，而 LangSmith Studio 的图视图 + 状态调试 + time-travel 必须经云端账号。**要「能调试」就得先「能运行」，所以本地 Agent Server 是必答题，Studio 本身反而是次要的。**

### 3.1 实跑事实（全部可复现）

### 3.2 依赖树：`langsmith` 的唯一入口是 `langchain-core`

```
langchain 1.4.1 ─┬─ langchain-core 1.6.3 ─── langsmith 0.12.6  ★硬依赖
                 └─ langgraph 1.2.11 ─┬─ langchain-core ───── langsmith ★
                                        ├─ langgraph-checkpoint → …
                                        ├─ langgraph-prebuilt  → …
                                        └─ langgraph-sdk       → …
```

`langchain-core 1.6.3` 的 `Requires-Dist` 含 **`langsmith<1.0.0,>=0.3.45`（非 extras）** → **「依赖树无 langsmith」⟺「依赖树无 langchain-core」**，是同一条红线，不能只挡一层。

**唯一可行路径：freegraph 零第三方运行时依赖**（**必装依赖 = 无**；`pydantic` 走可选 extra）。
代价：自己实现 `RunnableConfig` 语义与图结构导出（参照 `langchain_core/runnables/graph.py` 约 300 行量级，**独立重写而非复制**）。

> 补充正面信号：`langsmith` **0.14.x 新版已不再依赖 `langchain-core`**（requires_dist 只剩 anyio / httpx2 / orjson / pydantic / requests 等）→ LangSmith SDK 正在被抽成独立通用 SDK。「用 LangSmith SDK 但不装 LangChain」是可行的，但本项目出于红线仍不用。

### 3.5 `harness/demo/target.py` 逐项裁定（验收契约，只读）

`target.py` 共 151 行，拆出 **18 个 API 元素**：**7 项必须同名同签名**（`StateGraph`/`START`/`END`、`StateGraph(schema)`、`add_node`、`add_edge`、`add_conditional_edges`、`compile()`、`invoke`），**11 项可自由设计但须行为等价或原样承载**，**0 项要求触及 LangSmith 或 Agent Server**。

三个必须写进迁移说明的隐性风险：

1. **PNG 依赖公网**：第 144 行 `display(Image(agent.get_graph(xray=True).draw_mermaid_png()))` 位于第 149 行 `invoke()` **之前** → 离线必抛异常 → **脚本到不了验收点**。对策：`draw_mermaid()` 纯本地必成功；`draw_mermaid_png()` 做**可选插件、默认关闭**，离线返回占位图或抛可捕获异常，并给出 mermaid-cli 本地渲染的替代路径。
2. **`get_graph(xray=True)` 的 `xray` 参数**必须保留（无子图时无副作用，但签名要兼容）。
3. **`invoke()` 必须返回完整状态 dict**（实测 `['llm_calls','messages']`），不是仅新增消息。

> 注意一个反直觉点：脚本自带的 `langchain.*` 导入是**脚本自身**的要求，不构成 freegraph 的依赖要求；freegraph 只需**能承载**这些对象（鸭子类型），**不做类型转换**。

## 4. LangSmith 对 LangChain 的影响：三层分档（Q4）

| 层 | 判定 | 证据 |
|---|---|---|
| **① 运行时强依赖** | 包级 **🔴 是**（`langchain-core` → `langsmith` 硬依赖）；运行时 **❌ 否**（默认 `tracing_is_enabled()` = `False`，`langchain_core` 对 `langsmith.run_helpers` 是延迟导入，注释明写为了省 ~132ms）；代码级 import 仅 `langchain` 1 处 + `langgraph` 4 处，**全在可选路径** | PyPI 元数据 / 实测 / 源码扫描 |
| **② 可选集成** | tracing 上报、局部 tracing（`ls.tracing_context`）、`@traceable`、OTel 导出、Studio、RemoteGraph —— 均需账号 | `local-server.md:47-55` 等 |
| **③ 仅商业引导** | 文档前置要求 key、模板 `.env`、CLI banner 指向云、官方推荐配 Engine、`langgraph up` 提示 license、README 里「Pair it with LangSmith」 | 各处原文 |

> **我的结论**：LangSmith 是**旁路的商业层**，不是 LangChain 的运行时依赖。「包在依赖树里」与「用得上」是两回事 —— 这正是本项目必须精确到「不装 / 不依赖」的原因，而不是「不设置环境变量」就够了。
>
> **正面证据**：只要不设 `LANGSMITH_TRACING`，LangChain/LangGraph 完全静默 → **剥离后的行为与「不设 env 的 LangChain」完全一致**，这为「剥离是可行的」提供了直接依据。

## 5. DeepAgents 的位置：既是坐标也是反面教材（Q5）

**位置**：Harness 层（最上层）。**不自带运行时** —— 源码 `deepagents/graph.py:1008` 直接 `return create_agent(...)`，隔离 venv 实测 `create_deep_agent()` 返回值 `isinstance(..., CompiledStateGraph) == True`，图节点里能看到 `PatchToolCallsMiddleware.before_agent` 等 middleware 编译成的真实节点。**它的全部能力都是通过 LangChain 的 middleware 机制插进同一个 LangGraph 图。**

**对 LangSmith 的耦合强度（三层）**：

| 层面 | 判定 | 细节 |
|---|---|---|
| 包级 | 🔴 **硬依赖** | `deepagents 0.7.32` 的 `Requires-Dist` 含 **`langsmith>=0.14.12`（非 extras）** —— 比 `langchain` 本身更耦合（`langchain` 只是间接） |
| 代码级 | 🔴 **硬依赖** | `middleware/subagents.py:29`、`async_subagents.py:44`、`rubric.py:53` **三处顶层 import `langsmith.run_helpers`**；`import deepagents` 即加载 **174 个 langsmith 模块**。这三处是**核心能力**不是可选插件 → 绕不开 |
| 运行时 | 🟢 **默认零** | 清空全部 env 后 `create_deep_agent` + `invoke` 成功，`BLOCKED: []`；Deep Agents Code 甚至有 `DEEPAGENTS_CODE_LANGSMITH_TRACING=false` 与 `--no-tracing` 显式关闭开关 |

**凭据层是好消息**：模型走 `provider:model` 字符串 + `init_chat_model` 解析，**不经 LangSmith 中转**；Web 搜索用第三方 Tavily；凭据分层为「`DEEPAGENTS_CODE_` 前缀变量 > 应用内 `/auth` 存储 > 通用环境变量」。

**真正的 SaaS 耦合只有 3 处**（都是可选后端）：① `ContextHubBackend`（`from langsmith import Client`）② `LangSmithSandbox`（需 `langsmith[sandbox]` extra）③ Managed Deep Agents（整个托管运行时在 LangSmith 上）。

> **我的教训（也是设计准则）**：**Harness 层一旦开始用 LangGraph 特有能力（`DeltaChannel`、`BaseStore`、`Checkpointer`、`Send`、tracing context），就会被迫拖入 `langchain-core` 与 `langsmith`。**
> → 所以 freegraph 要提供 DeepAgents 需要的**图级扩展点的最小替代**：`context` 通道、checkpointer 接口、store 接口、subgraph 支持、`current_span()` 协议；**但绝不提供** `DeltaChannel` / `BaseUser` 这类专有内部件。

## 6. 可视化与可诊断性：路线 B（Q6）

### 6.1 目标必须先拆开

LangSmith 的「可视化」其实是**两个产品**：**Studio**（本地 agent IDE，9 项能力）与 **Observability UI**（trace 浏览器 + 评测平台，12 项能力）。

| 组 | 低成本可覆盖 | 中成本 | 高成本/不做 |
|---|---|---|---|
| Studio（9） | 图结构可视化（🟢 LangGraph OSS 已有）、time-travel（🟢 OSS 已有，已实跑） | 运行交互、assistants/threads、prompt 迭代、长期记忆、Playground | 数据集实验 🔴、1-Click Deploy ❌ |
| Observability（12） | trace 记录、thread、trajectory、feedback/tags/metadata | trace 浏览、monitoring 看板、retention | Insights 🔴、Evals 🔴、Datasets 🔴、Annotation Queue 🔴、Prompt Hub 🔴 |

> **诚实的答案**：LangSmith 全栈 ≈ 21 项，freegraph 现实覆盖 **8–10 项（38–48%）**，但**高价值低成本项覆盖 8/8（100%）**。
> → **在「图运行时可诊断性」这个垂直维度可以做到「不亚于」；在「全生命周期 AI 工程平台」维度不可能，也不该追求。**
> → 目标改写为：**「不亚于 LangSmith Studio 的本地图运行时可诊断性，且零账号、零出站；评测与数据集能力通过 OTel 后端可选接入。」**

### 6.2 现成 OSS 覆盖评估

| 方案 | 许可证 | 覆盖 | 关键限制 |
|---|---|---|---|
| **OTel**（协议层） | Apache-2.0 | 事实标准，**提供数据模型但不是 UI** | 只解决格式 |
| **OTel GenAI semconv** | Apache-2.0 | `gen_ai.*` 属性命名 | 规范已迁至独立仓库 `open-telemetry/semantic-conventions-genai`，仍在演进 |
| **Langfuse**（36,859★） | MIT 主体 + `ee/` 另行许可 | 覆盖 O1–O12 大部分，有 agent graph 视图 | 自托管需 **4 个存储服务**（PG + Redis + ClickHouse + Blob），官方建议 t3.xlarge；EE 功能需 license key |
| **Phoenix**（12,096★） | 🔴 **Elastic-2.0** | O1/O3/O5/O8/O9/O10，OTel + OpenInference 原生 | **ELv2 禁止托管 → 只能连不能嵌** |
| **OpenLIT**（2,900★） | Apache-2.0 | O1/O5/O6/O8，另有 Guardrails / Rule Engine | 文档站 404，只能依赖官方仓库 README；部署最轻 |

**三条关键结论**：

1. **没有任何一个现成 OSS 提供「LangSmith Studio 那种交互式图运行时 IDE」** —— Langfuse / Phoenix 的 agent graph 只是**从 trace 还原的只读调用图**（不能改 prompt、不能跑图、不能 time-travel）。**这就是 freegraph 的独占位置。**
   > **【Q9 精化，2026-11-03】** 精确表述应为「**没有 OSS 提供交互式图视图（node/edge IDE）**」：OSS 侧另有 **MIT 的 Agent Chat UI**（Next.js；本地可跑、**连本地 server 不需要 LangSmith key**；支持 **time-travel / state forking**），但它是 chat-first、**无图视图**。→ 独占位置**收窄**为「图视图 + 状态检查器」，**v1 不必引入前端技术栈**（能力层优先）。同时实测确认：**`langgraph dev` 起的是 Agent Server 而非 Studio**；可视化代码（mermaid 渲染）归属 **`langchain-core`** 而非 `langgraph` 包。详见 [Q9](../reports/Q9-Studio与本地server及可视化代码边界.md)。
2. **trace 数据层已被 OTel 生态解决** —— 三个后端全是 OTel 原生，freegraph 只要产出 OTel span 就能全接上，零转换成本。
3. **Phoenix 是法律地雷**，绝不内嵌。

### 6.3 路线对比（工作量）

| 维度 | 路线 A（自研整套） | **路线 B（OTel + 轻量 UI）** |
|---|---|---|
| 工作量 | **245–415 人日**（1–2 人年） | **62–101 人日** |
| 调试维度达成度 | 95% | 85–90%（接 OTel 后端综合 ~85%） |
| 评测/数据集 | 90% | 0%（明确不做，可后接） |
| 与「零依赖内核」一致性 | ❌ 前端栈庞大 | ✅ UI 是可选子包 |
| 与「零出站」一致性 | ⚠️ 需保证 | ✅ 天然满足（OTLP 需显式开启） |
| 生态兼容 | 差（自造格式） | ✅ OTel 事实标准 |
| 结论 | ❌ | ✅ **选它** |

**v1 可视化三件套**：① 图视图（mermaid，零出站）② trace 时间线 / 详情（本地存储）③ 状态快照 + checkpoint 历史 + 回放入口。

**MVP 存储三件套**：`FileTraceStore`（JSONL，零依赖，默认）+ `SqliteTraceStore`（可查询）+ **OTLP 导出（可选插件，默认关闭）**。

**后端推荐顺序**：**OpenLIT**（Apache-2.0、无功能门、一条 `docker compose`）> Langfuse（重）> Phoenix（只外部连接）。

## 7. 许可证与商标：可以复刻 API，不能复刻品牌（Q7）

### 7.1 许可证事实

**好消息：LangChain 家族 OSS 侧几乎全是 MIT**（`langgraph` / `langchain` / `langchain-core` / `langchain-classic` / `langchain-protocol` / `langsmith` SDK / 所有 provider 包 / `deepagents`）→ **未发现任何 AGPL / SSPL / BUSL 传染性条款**，商用友好度**高**。

**唯一的非 MIT 陷阱**：

| 组件 | 许可证 | 后果 |
|---|---|---|
| **`langgraph-api`** | 🔴 **Elastic-2.0** | 禁止「provide the software to third parties as a hosted or managed service」→ **不能进依赖树，不能被托管版内嵌** |
| **`langgraph-runtime-inmem`** | 🔴 **Elastic-2.0** | 同上 |
| LangSmith SaaS 平台 | 🔴 专有（Platform License，付费订阅） | 不可用 |
| `langsmith` **SDK** | 🟢 **MIT** | 付费的是平台，不是 SDK → **「开源 SDK + 付费平台」正是 LangChain 的商业模式核心，也是本项目存在空间的来源** |

> **最关键的洞察**：**LangSmith 的付费墙不是靠许可证锁住的，是靠「服务端是专有的」锁住的。**
> → 本项目只想做「本地图运行时」的话，几乎不碰许可证问题；
> → 但只要想提供「托管的 Agent Server」，就直接撞上 ELv2 → **必须自己写一份 Agent Server**（这也是 Q6 强调自己做本地 server 的法律动因）。
> → 附带发现：`langgraph-api` wheel 内置的 license 校验其实是 **noop**（`plus_features_enabled()` 恒 True）→ **付费墙目前主要在文档/服务层，不是代码层强制**。

### 7.2 版权 vs 商标（两件独立的事）

| 维度 | 能做 | 不能做 |
|---|---|---|
| **版权**（MIT） | 同名实现 `StateGraph` / `add_node` / `add_edge` / `compile` / `START` / `END`；复制源码片段（保留版权声明）；复制 mermaid **语法**；参考 Pregel **算法**；参考 run/trace/thread **数据模型** | —— |
| **商标** | —— | 产品名里用 Lang/LangChain/LangSmith/LangGraph；复制 Studio 前端与视觉设计；复制 logo / 配色 / 图标；照抄官方 "Approved copy" 文案 |

**官方品牌指南**（`www.langchain.com/brand-assets`）把 **langgraph / deepagents 与 langchain 并列为受保护的 "Open Source Framework Logos"**，并给出 Do's & Don'ts（不拉伸、不加效果、不 off-brand 配色、不用 Community logo 代替官方 logo）。

**必须做的四件事**：① README 顶部声明「非官方 / independent implementation」② 不用任何 logo / 品牌色 ③ 提第三方用「兼容（compatible with）/ 受启发于（inspired by）/ 类似（similar to）」+ 免责 ④ 维护一张「API 兼容矩阵」，逐条标注行为等价 / 部分等价 / 不支持。

> **我的判断**：**MIT 解决「能不能抄代码」，商标解决「能不能叫这个名字」，两者独立。**
> 做法：**API 层全面兼容（同名同签名）+ 品牌层完全独立 + 许可证层选 MIT/Apache-2.0 + 零 `langchain*` 依赖**（后一条同时满足剥离要求）。
> 许可证选择上我倾向 **Apache-2.0**（显式专利授权 + §6 商标不授权 + NOTICE 机制），当前仓库 `LICENSE` 是 MIT（Copyright (c) 2026 杨家成）——若维持 MIT，也要在 README 单独写明不使用任何 LangChain 商标。

## 8. 内核最小契约 C1–C26（Q8）

> 这是 **freechain 的设计输入**，也是 freegraph 对上（freechain）/ 对下（用户脚本）的承诺清单。**必须整份冻结，不得擅自增删。**

### 8.1 图运行时从外界真正需要的，只有 6 类输入

① 状态 schema（含归约器）② 节点函数 ③ 边 / 路由函数 ④ 执行配置 ⑤ 外部能力注入点（context / checkpointer / store / tracer）⑥ 可选执行控制（interrupt / Command）。

**模型抽象、消息类型、工具装饰器、provider 抽象、agent 装配 —— 全部不在图运行时的契约面内。**

### 8.2 图层到底需不需要 LangChain？**不需要**

`langgraph/` 全目录对 `langchain_core` 的 **135 处引用**，符号级分布：

| 符号 | 次数 | 性质 | 我的处置 |
|---|---|---|---|
| `runnables.RunnableConfig` | 26 | 配置传递 | 🔴 换成自有 `RunConfig` |
| `runnables.Runnable` / `RunnableBindingBase` | 8 | 协议 | 🔴 换成自有 `Node` / `CompiledGraph` 协议 |
| `runnables.graph.Graph` / `Node` / `Edge` | 5 | 图结构类型 | 🔴 换成自有 `Graph`（**唯一必须重写的类型**） |
| `tracers.*` / `callbacks.*` | 6 + 6 | 可观测挂钩 | 🟢 用 OTel 替代 |
| `messages.*` / `tools.*` / `language_models.*` | 6 / 5 / 4 | 消息、工具、模型 | 🟢 **不需要**（鸭子类型） |

**结论：图层不需要 `langchain`，也不需要 `langchain-core`；只需替换 4 个「接缝」类型。**（这 4 个接缝 + `Command`/`Interrupt` = freegraph 必须自备的 5 个接缝类型，其余全是通用协议。）

### 8.3 关键语义细节（最容易实现错的地方）

| 契约 | 要求 | 依据 |
|---|---|---|
| **C4 稀疏状态** | 节点入参是**普通 `dict`**，且**只含当前有值的 key**（`read_channels(skip_empty=True)`）；实测 `NODE_INPUT_KEYS: ['messages']` | 这是 `state.get('llm_calls', 0)` 能工作的根本原因 —— **不实现就会返回 `None` 而非 `0`，静默破坏 `target.py`** |
| **C8 条件边读 fresh 状态** | 路由函数必须看到「当前值 + 本节点本次写入」 | 否则 `should_continue` 读到旧 `messages`，**tool 循环失效** |
| **C2 归约器提取** | `Annotated[T, reducer]`，reducer 必须**恰好 2 个位置参数**，否则抛错 | `state.py:1905-1922` |
| **C3 默认归约** | 无 reducer → **覆盖**（`LastValue`，丢左值留右值） | `last_value.py:20-52` |
| **C6 合并语义** | 逐 key 应用 reducer；未知 key 报错 | `binop.py:123-153` |
| **C7 路由双形态** | `path_map` 传 list → 返回值即节点名；传 dict → 返回值是 **key**，目标是 **value** | 实测 `PATHMAP_OUT` |
| **C11 执行** | `invoke(input) -> dict`，**返回完整状态** | 实测 `['llm_calls','messages']` |
| **C16 `Command`** | `goto` + `update` 可同时；`resume` 从**节点起点**重跑（不是从 interrupt 点继续） | 实测 `COMMAND_OUT` / `RESUME_OUT` |
| **C17 `interrupt`** | 抛可识别异常；run 结果含 `__interrupt__`（元素带 `.value` / `.id`） | 实测 `INTERRUPT_OUT` |

### 8.4 通用 vs LangChain 特有（判别结果）

**通用协议（freechain 可直接采用，无需适配层）**：`Annotated[T, reducer]` 二元归约器机制、OpenAI 风格 `tool_calls` 结构 `{"name","args","id","type"}`、`invoke(input) -> message` 的模型契约、`tool.invoke(args)` 的工具契约、路由函数返回节点名或 `END`、`Command` / `interrupt` 的语义。

**LangChain 特有（需 freechain 适配）**：`AnyMessage` / `BaseMessage`、`add_messages` 归约器、`BaseTool` / `@tool`、`RunnableConfig` 的 `configurable` 约定、`langgraph_sdk.BaseUser`、`DeltaChannel`。

> **这是「把 LangChain 与 LangSmith 一起替换掉」在技术上可行的关键证据。**

## 10. 我的判断（读完全部报告后最想记住的几件事）

1. **这个项目的机会窗口不在「功能」，在「耦合」。** LangChain 家族已经把可观测、调试、评测都做完了，而且**免费**。它们唯一的变现口是「托管 + 自治 + 治理」。freegraph 的机会是把**免费那一半**做成**不需要账号、不需要出网、不需要 license** 的东西 —— 这是替代关系，不是竞争关系。
2. **「免费但需账号」是被低估的付费墙。** 所有人看到「$0 档」就以为免费了，其实 Observability 层整个绑死在账号上，Studio 连本地开发都要过云。**消灭这一层，本身就是产品。**
3. **剥离的技术成本被高估了。** Q8 的结论很干净：图执行语义（channels / 调度 / 归约器 / checkpoint）根本不依赖 `langchain_core`，135 处引用集中在 4 个接缝。**真正难的不是脱钩，是脱钩后的语义等价**（稀疏状态、fresh 读、超步并发写）—— 这也是最该写回归测试的地方。
4. **可视化是唯一有独占性的地方。** OTel 生态把 trace 数据层彻底解决了，但**没有任何 OSS 提供「能改 prompt、能跑图、能 time-travel 的交互式图 IDE」**。这块自研不亏（路线 B 62–101 人日），而评测/数据集/标注队列自研就是灾难（路线 A 245–415 人日）。**不讨好这件事是范围管理的第一课。**
5. **ELv2 是最有约束力的一条外部事实。** 它直接否掉了「把 LangGraph 的 Agent Server 拿来托管」这条最省事的路 → 我们必须自己写一个 → 这不是技术偏好，是法律必然。
6. **术语纪律不是形式主义。** 官方已经有 Runtime / Framework / Harness 三层分类；继续用自造的「三大基础功能 / 六大概念」会让人误以为 freegraph 要复刻 LangChain 全家桶。**说清楚「我只做 Runtime」，比多写一万行代码更能防止范围膨胀。**
7. **「不设 env」不等于「没外呼」。** Q3 实测：一旦 `LANGSMITH_TRACING=true`，`langchain-core` 会真的去 `api.smith.langchain.com` 上报。**零出站必须有 socket guard 级别的证据**，不能靠自觉。

## 11. 取证方法备忘（下次调研直接照抄）

| 方法 | 要点 | 效果 |
|---|---|---|
| **DOM 级解析动态页** | 定价页是 Webflow 渲染，勾选矩阵是 SVG（`Check.svg` / `is-minus`）→ Markdown 文本化会**丢失勾选状态**。做法：抓原始 HTML → **平衡 `<div>` 扫描器**逐行解析 `.p-pricing-grid-item`（74 行）+ `.pricing-element-wrapper` 单元格 → 判定：含 `Check.svg` → ✅ / class 含 `is-minus` → ❌ / 否则取文本 | **纠正了初稿 5 处误判**：Insights、Annotation Queue、Prompt Hub、Bulk data export、Studio |
| **socket guard 夹具** | 阻断所有非 localhost 的 `socket.connect`，断言拦截列表为空 | 证明「零出站」不是靠自觉；已证明 `BLOCKED: []` 与「设 key 后确实外呼」 |
| **实跑取证优先于文档** | 文档与代码冲突时**以代码为准**（例：`local-server.md` 正文说 standalone 可自托管，但 `cli.py:368-369` 的 banner 是硬编码的；`draw_mermaid_png` 的真实行为与文档描述不同） | 避免把文档简化当事实 |
| **依赖树展开** | `importlib.metadata` 递归展开 `Requires-Dist` + PyPI JSON API 交叉 | 定位 `langchain-core` → `langsmith` 的硬依赖 |
| **wheel 解包** | `langgraph-api` / `langgraph-cli` / `deepagents` 解包看真实 import 与许可证 | 发现 license 校验是 noop、发现 DeepAgents 三处顶层 `import langsmith`、发现 Langfuse 的 `ee/` 子目录另有许可 |
| **抓取注意** | `docs.langchain.com` 支持 URL 后加 `.md` 直接拿 Markdown 源文；本机代理 `127.0.0.1:10808` 出网 | 补齐了 16 个原本缺失的官方页 |

**遗留的「非信息缺口」**（属官方未公开或需专业判断，不是抓取失败）：LangSmith Sandbox 每沙箱配额、Startup 计划折扣百分比、商标侵权的司法认定、Phoenix/OpenLIT 的最低配置表。
