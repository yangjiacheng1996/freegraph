## 1. 起因：PyPI 名称被永久占用

`opengraph` 与 `openchain` 在 PyPI 上**均已被他人占用**，且 PyPI 名称**不可转让、不可复用**（删除后也不回收）：

| 名称 | 占用者 | 实测证据（2026-11-03） |
|---|---|---|
| `opengraph` | Erik Rivera — *A module to parse the Open Graph Protocol* 0.5 | `GET https://pypi.org/pypi/opengraph/json` → 200 |
| `openchain` | *Openchain Library* 0.1.0rc3 | `GET https://pypi.org/pypi/openchain/json` → 200 |

而本项目的交付物 B24F1 就是「打包分发」，验收契约又把 import 路径写死为 `from opengraph.graph import StateGraph, START, END`（`harness/demo/target.py:103`）——**这个名字发不出去**。

### 1.1 候选名的筛选口径

对 120+ 个候选名做实测（PyPI JSON API `GET /pypi/<name>/json` + npm registry `GET registry.npmjs.org/<name>` + GitHub 主页探测）：

- **硬约束**：PyPI 名称**全局唯一、不可复用** → 发行名必须干净；
- **软约束**：GitHub 组织名（个人账号下建仓不受影响）、npm 名称（生态兼容性）、含义与可读性；
- **否决项**：与既有项目的正面撞车（如 `openflow`、`openstate`、`graphcore`、`flowgraph`、`zerograph`、`litgraph`、`chainkit`、`ochain` 等均已被占）。

- 验证：`pip install freechain` → 解析出 3 个包（`freechain` / `freegraph` / `typing-extensions`），
  运行期无 `langsmith` / `langchain`
- **两个 PyPI 名称均已被本项目锁定**，不再存在被他人抢注的风险

> **⚠️ 上述元数据是 v0.0.1 的**历史事实**，不予改写**——但**当前状态已变**：
> 依《项目宪法》修订记录 **v1.2.0**（2026-11-05），freegraph 的
> **`requires-python` 抬至 `>=3.11`**、**`typing-extensions` 已从基础安装剥离**
> （基础安装**零**第三方运行时依赖）。下一次发布（**v0.0.3**）的元数据为
> **`Requires-Dist` 无 / `Requires-Python: >=3.11`**。
> 姊妹项目 `freechain` 若仍声明 `freegraph>=0.0.1`，其解析出的依赖链将随之变化
> （不再有 `typing-extensions`）——**该调整归 freechain 仓库，本仓库不代改**。

**为什么选 "free"**：本项目的四条对外承诺是「零账号 / 零出站 / 零依赖 / 零 license key」——`free` 一词同时覆盖「零锁定」与「免费」两层含义，比中性的功能描述词（`zerograph` / `litgraph` / `flowgraph` 那一类）更有立场感；两个名字对称、可读、可注册。

**为什么不采用「发行名与导入名解耦」**（评审时的备选建议）：解耦后 `pip install X` 与 `import opengraph` 不同名，且 `import opengraph` 会与既有 PyPI 包**同名撞车**（同时安装时 import 解析冲突），治标不治本；整体更名后 **发行名 = 导入名 = `freegraph`**，语义干净。

**已知的两处注意点**：
1. `Free Graph` 是图论旧术语（Harary 时代 "undirected graph" 的旧译）——README 首句需把语义钉死为 *"free of accounts, free of egress, free of license keys"*；
2. GitHub 上 `freegraph` / `freechain` 分别是 2013 年的空用户账号与 2026-03 的空组织，无法用作独立 org 主页（个人账号下建仓不受影响）。

## 4. 验收契约的连续性论证

**原则 III 的实质要求**：固定脚本是 LangGraph Quickstart "Full code example" 的**机械替换**版——把其中的 `langgraph` 字样替换为**本项目包名**，其余一字未改。

| 环节 | 更名前 | 更名后 | 是否等价 |
|---|---|---|---|
| 脚本来源 | LangGraph Quickstart | 同左 | ✅ |
| 替换规则 | `langgraph` → `opengraph` | `langgraph` → `freegraph` | ✅ 同一条规则，只换替换目标 |
| 脚本自带导入 | `langchain.*` | 同左 | ✅ 脚本自身的要求，不构成项目依赖 |
| 验收判据 | 7 项同名同签名 + 11 项行为等价 | 同左 | ✅ |
| 契约清单 | C1–C26 | 同左 | ✅ |

**结论**：本次更名属于**平移**（parallel move），不构成原则 III 所说的「验收契约的弱化」。宪法已按 Governance 记录为 **v0.0.1（PRE-1.0 修订）**：原则 I–X 的**实质要求均未改变**，仅原则 III 的具体 API 名与原则 V 门禁 4 的方法措辞变化。

> **注**：原则 V 门禁 4 的措辞修正（socket 夹具「拦截」→「只观测不阻断 + 按发起方归因」）来自评审 1 的 **C3**，与更名一并纳入 v0.0.1。理由：freegraph 是**函数胶水 / 工作流框架**，承诺「自己不会偷偷联网」而非「你的程序不许联网」；拦截式守卫会阻断用户节点的正常出网。
