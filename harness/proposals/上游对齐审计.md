### 2. ★★★ 头条发现：**触发模型不同款**（B7F1 · ① 类最高优先）

freegraph 让**订阅集兼任触发源**（通道触发源 `("c", key)`），上游**只**按**边**触发
（`branch:to:<node>` 通道 · `graph/state.py:1531-1532`）。

**实测**（同一拓扑：节点 `a` 写通道 `log`；节点 `b` **订阅** `log` 但**无任何入边**）：

```
上游     ran = ['a']            log = ['a']        ⇒ b 从未执行
freegraph ran = ['a', 'b']      log = ['a','b']    ⇒ b 被执行
          ⇒ 随后 GraphRecursionError: recursion limit exceeded (25 步)
```

⇒ **两个可观察后果**：
1. **同一张图，freegraph 会多跑上游不跑的节点**（触发面更大 ⇒ 状态可能不同）；
2. **节点写自己订阅的通道 ⇒ 自触发循环**（上游不会）⇒ freegraph 更容易撞上递归上限。

> **连带解释**：freegraph 的 `recursion_limit` 缺省 **25**，而上游**有效缺省 = 10007**
> （`langgraph/_internal/_config.py:32` · `DEFAULT_RECURSION_LIMIT = int(getenv(..., "10007"))`；
> 实测 `ensure_config()["recursion_limit"] == 10007`）⇒ **上游几乎撞不到上限，freegraph 经常撞到**。
> ⚠️ 既有 parity 表「缺省 25 逐字一致」的结论**是错的**。

### 4. 一句话结论

> **freegraph 目前不是「上游的等价实现」，而是「受上游启发的一套自研语义」。**
> 与上游的差异集中在 **触发模型（头条）· 通道 API · 错误信号（严 vs 静默）· 配置字段集** 四处；
> 其余（触发判定公式 · 合并形态 · `Command` 语义 · 中断语义 · 并发调度）**已经同款或接近同款**。
> ⇒ **回改的性价比很高**：改 4 处地基（触发模型 · 通道 API · 错误信号 · 配置字段集），
> 就能把大部分 ① 类差异一次性消掉，**并让差分测试真正可跑**。

| **C. 触发模型照抄 + 「更严」条款**改写为**上游同款** | 同 A | 同 A |

> **推荐 B**：① **触发模型**是**行为分叉**（多跑节点 / 自触发循环）⇒ 必须改；② 「更严」条款是**失败信号**的分叉（不影响成功路径的可观察状态）⇒ 保留成本低、收益高（可诊断性）；③ 差分夹具本就要**只比对确定性投影**（否则上游的竞态项会让 CI 偶发红）⇒ 「更严」的失败信号**天然落在投影之外** ⇒ **B 与差分门禁天然共存**。
> ⇒ **只需发起者对 B 点头一次**，其余全部按上游源码执行。
