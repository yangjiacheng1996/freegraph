# 项目owner的吐槽
我觉得本项目再这么推进下去可能会僵死。
本来项目的目标是无账号无主动出网无依赖。就是一个上游langgraph的免费版本。
或者说难听一点，就是langgraph的“破解版”。
从设计到代码实现，可以照抄langgraph都没问题，只要能做到“无账号无主动出网无依赖”的项目目标即可。有吃不准的设计，你直接读langgraph源码就行。
并且破解版能够基本兼容下游langchain。
但是本项目自从采用speckit后，智能体+大模型开始自由发挥，导致feature之间越来越“无法对齐”，开发难度陡增。
本来就是一个照抄的工作，被你搞的越来越繁琐，偏离主路线越来越远，需要我人工决策的地方越来越多，我疲于奔命，狂做选择题。
你是否能够力挽狂澜，将本项目向上游靠拢？从最初的立项书（harness/proposals/立项书.md）到feature提示词（harness/features）再到speckit相关的spec（specs/）再到源码和测试，都尽量贴合上游，降低人工决策，降低项目风险。
如果没有langgraph，本项目重头开发一个“图框架”的成功率极低，正是langgraph的出现给了我灵感，也给了我坚信freegraph一定成功的底气，而目前的成果越来越让我心慌，矛盾点越来越多了，底气没了。

## 摘要

**问题**：项目从立项至今，**规格链（散文）的膨胀速度远超代码**，且**大量语义是 agent 自行发明的** —— 这些发明随后都要发起者逐条签字，于是「选择题」从 0 涨到每个 feature 10 题以上，而**与上游的行为一致性反而在下降**。

**本提案的立场**（发起者 2026-11-12 明确表述）：

> 「本来项目的目标是**无账号、无主动出网、无依赖**，就是一个上游 LangGraph 的**免费版本**；从设计到代码实现，**可以照抄 langgraph 都没问题**，只要能做到『无账号无主动出网无依赖』的项目目标即可。**有吃不准的设计，直接读 langgraph 源码就行。** 并且『破解版』应当能够**基本兼容下游 langchain**。」

**因此本提案只做三件事**：

1. **把决策来源倒转回上游**（§2）—— 上游源码是唯一权威；照抄上游的**不需要**发起者签字。
2. **把「必须自研」的范围收窄到 4 类**（§2.2）—— 其余全部照抄；自研区才是唯一需要发起者过目的地带。
3. **把文档与流程瘦身**（§3）—— spec 只写「与上游的差异 + 自研点」，不复述上游语义；人工决策从**逐题**降为**每 feature ≤ 1 次批量确认**（通常 **0** 次）。

**预期结果**：散文 : 代码的比例从当前的 **9.7 : 1** 回到 **≤ 1 : 1**；与上游的**行为等价面**从当前的约 17% 代码覆盖，提升到**可差分验证**的覆盖；发起者的决策负担从「每 feature 10 题」降到「**每里程碑 1 次批量确认**」。

## 1. 为什么现在要改路线（诊断）

### 1.1 数据（仓库现状 · 可复核）

| 项 | 数值 | 参照 |
|---|---|---|
| `specs/**` 散文 | **34,484 行** Markdown | —— |
| `src/freegraph/**` 代码 | **3,540 行** Python | —— |
| `tests/**` 代码 | **18,538 行** Python | —— |
| **散文 : 代码** | **9.7 : 1** | ⚠️ **比例倒挂** |
| 上游内核规模 | **20,277 行** Python | `langgraph 1.2.11` 的 `pregel/` + `graph/` + `channels/` + `types.py` + `errors.py` |
| freegraph 代码 / 上游 | **≈ 17%** | ⚠️ 代码量小、散文量大 ⇒ **规格在描述一个还没被实现的世界** |
| B12F1 单个 feature 的裁定 | **25** 条（其中 **13** 条 agent 自拍） | —— |
| B12F1 消耗的发起者决策 | **18** 题（三轮澄清） | ⚠️ 决策负担已超出「个人项目」的合理区间 |
| B12F1 与上游的**已知分叉** | **7** 条（parity `X-1…X-7`） | ⚠️ 分叉项**都**需要额外判据 ⇒ 都**要**发起者签字 |

### 1.2 根因：不是细节问题，是**决策来源**错了

现行流程（**已被 speckit 流程放大**）：

```
agent 读需求 → agent 设计语义 → agent 写裁定 → 发起者逐条签字 → 实现
                        ▲
                        └── 每个环节都**没有**「上游已经有现成答案」这一步
```

而这个项目**本来的形态**应该是：

```
读上游源码 → 照抄 → （只有自研处）→ 一次性批量确认 → 实现
```

**上游已经解决过**的问题，我们重新发明了一遍，再请你签字 —— 举 B12F1 的实例：

| 我们发明的 | 上游的现成答案 | 代价 |
|---|---|---|
| 「首个异常按**节点表顺序**取」（裁定 5 · parity `X-1`） | 上游从 `done` 集合取（**竞态**） | 多一条 SC + 多一条裁定 + 多一次签字 |
| 「失败**不取消**其余任务」（裁定 17 · parity `X-2`） | 上游失败即取消（`_runner.py:676-681`） | 同上 |
| 「并发度**不限**」（裁定 2 · parity `X-4`） | 上游 `max_concurrency` 缺省 `min(32, cpu+4)` | 同上 |
| 「中断集合落**调度状态**」（裁定 8 · parity `X-3`） | 上游合并成一个 `GraphInterrupt` 携带元组 | 同上 |
| 「`executed` **含**被中断的节点」（裁定 22） | 上游任务清单**确实**含（**实测**） | 多一条裁定 |
| 「多会话隔离**只登记**」（裁定 23 · `D-4`/`D-5`） | 上游**原生支持**（编译产物持规格、每次运行新建实例） | 多 **2 条**下游承接 + 多 **2 份**提示词改动 + 一个**已知限制**要写进文档 |

⇒ **6 条分叉，0 条必要**；其中 4 条只需**照抄**即可消除，1 条（多会话隔离）需要**改实现**（属既有 B5F1/B7F1 的形态问题），1 条（并发度缺省）只是一行参数。

### 1.3 关键澄清：**《立项书》的口径本来就是对的**，漂移发生在**执行层**

这不是要改方向，是要**回到**已签署的方向：

| 《立项书》的既有条款 | 出处 | 实际执行 |
|---|---|---|
| 「以与 LangGraph Graph API **同名同签名**的接口提供…」 | 摘要 | 部分对齐 |
| **S5 语义等价 · 三层证据**：① 契约级回归 ② **差分测试**（**同一份图规格同时跑 `langgraph` 与 `freegraph`，比对输出状态与事件序列**）③ 属性 / 参数化测试 | §4.2 | ①②③ **均未按「差分」实施** ⇒ 改用了**逐条裁定 + 逐条签字** |
| **S6 API 兼容**：固定脚本使用的 **18** 个 API 元素 = 7 同名同签名 + 10 行为等价 | §4.2 | 同上 |
| **S1/S2/S3** 零依赖 / 零环境变量 / 零出站 | §4.2 | ✅ 已达成 |

⇒ **差分测试（同一份规格双跑）本就是立项书写明的等价证据手段**，它天然地会把「与上游不同款」的地方**自动暴露出来**；我们没有把它做成**门禁**，而是改成了**逐题裁定** —— 这就是全部漂移的机制。

## 2. 主路线：一条规则 —— **上游优先**

### 2.1 判定顺序（每个设计点按此顺序走，**不得跳步**）

| 步 | 判据 | 结果 |
|---|---|---|
| **①** | **上游 LangGraph 有对应实现？** | **照抄**（含其**已知缺陷**与**非确定性**）⇒ **MUST NOT** 自研替代方案 ⇒ **不需要**发起者签字 |
| **②** | 上游**没有**（本项目的增量能力） | **自研** ⇒ 需证明「不违反『零账号 / 零主动出网 / 零依赖』」⇒ 登记为**自研点** ⇒ **一次性批量**确认 |
| **③** | 上游有，但**照抄会违反**项目目标（引入依赖 / 出站 / 账号） | **自研等价物**（**行为对齐**、**形态自研**）⇒ 登记为**自研点** ⇒ **一次性批量**确认 |

> **默认动作 = 照抄**。任何「我认为上游这样不好」的想法，**不构成偏离上游的理由**；
> 偏离必须以上表的 ② / ③ 为唯一依据，且**必须**指向**项目的三条目标**（无账号 / 无主动出网 / 无依赖）。

### 2.2 「必须自研区」的边界（**只有 4 类** —— 其余全部照抄）

| # | 自研区 | 为什么不能照抄 | 必须做到什么 |
|---|---|---|---|
| **S-1** | **配置载体**（上游 `RunnableConfig`） | 上游的配置类型在 `langchain_core` ⇒ 照抄即**引入依赖** ⇒ 破 S1 | freegraph 自有 `RunConfig`；**字段名与语义** MUST 与上游**对齐**（`configurable` / `metadata` / `tags` / `max_concurrency` / `thread_id` / `checkpoint_ns`）⇒ 下游 langchain 迁移成本最低 |
| **S-2** | **回调 / 追踪桥**（上游 `BaseCallbackManager`） | 同上（在 `langchain_core`） | freegraph 自有 `TraceSink`；**事件名与入参形状** MUST 对齐上游（`on_chain_start` / `on_chain_end` / `on_chain_error` / `on_chain_stream` 的 kwargs 形状）⇒ **兼容下游 langchain 的关键** |
| **S-3** | **本地 trace 存储 / 查询 / Studio 三件套** | **上游没有**（上游是 LangSmith SaaS） | 纯自研 ⇒ 这是 freegraph 相对上游的**增量价值**，不与上游冲突 |
| **S-4** | **PNG 渲染后端** | 上游走 `mermaid.ink`（**出站**）⇒ 破 S3 | v1 占位 PNG（纯本地）；真渲染属 v2（立项书 D14） |

> **其余全部照抄**（含：`StateGraph` / `START` / `END` / `add_node` / `add_edge` / `add_conditional_edges` /
> `compile` / `invoke` / `stream`（五模式）/ `Command` / `Send` / `interrupt` / `Interrupt` /
> `GraphInterrupt` / `StateSnapshot` / `PregelTask` / 通道语义（`LastValue` / `BinaryOperatorAggregate` /
> `EphemeralValue` / `Topic`）/ 归约器解析 / `get_graph` / `draw_mermaid` / `checkpointer` 协议 /
> `recursion_limit` / 并发调度 / 触发判定 / 版本号模型 / `update_state` / time-travel 语义）。

### 2.3 「照抄」的三条纪律

| # | 纪律 | 理由 |
|---|---|---|
| **①** | **连缺陷一起抄**（例：上游「首个异常是竞态」） | 「破解版」的**价值**就是行为一致 ⇒ 上游的怪癖也是**契约**；自研一套「更合理」的语义 ⇒ **兼容性破功**，且**要**发起者签字 |
| **②** | 上游的**非确定性**（竞态 / 依赖调度）MUST 在文档里**如实标注一句**（「上游同款的非确定性」）⇒ **不**做成选择题、**不**当成 bug 去「修」 | 照抄的**代价**必须**如实记录**，而不是被悄悄抹平 |
| **③** | 照抄**必须**留下**可核对的锚点**：**上游版本 + `路径:行号`**（仓库既有纪律 · 宪法原则 VIII） | 「照抄」若无锚点 ⇒ 无法复核 ⇒ 变成「据说照抄了」 |

## 3. 流程改造：把选择题从「逐题」变成「一次」

| 维度 | 现状 | **主路线** |
|---|---|---|
| **决策来源** | agent 拍板 → 发起者追认 | **上游源码** → 照抄；只有**自研点**需发起者过目 |
| **spec 的内容** | 复述上游已有语义 + 逐条裁定（24 条/feature） | **只写**：① 与上游的**差异清单** ② **自研点**（含上游锚点）③ 本 feature 的**验收判据**（引用上游契约，不复述）⇒ 目标 **150–250 行/feature** |
| **裁定表** | 24 条（13 条 agent 自拍 + 发起者追认） | **只留自研点**（0–3 条/feature）⇒ **取消**「spec 阶段拍板 ⇒ 发起者追认」这一仪式 |
| **发起者决策** | 逐题（10 题/feature） | **每 feature ≤ 1 次批量确认**（通常 **0** 次：无自研点时不打扰） |
| **plan / tasks** | 逐条复述 spec | **只写**「照抄清单」（上游锚点）+ **自研点的实现任务** |
| **等价证据** | 契约级回归（2 条）+ 逐条判据 | **差分夹具为主**（同一份规格双跑 `langgraph` 与 `freegraph` ⇒ 比对输出状态 + 事件序列）—— **立项书 S5 ② 已在册**，本路线只是把它**升格为主证据** |
| **文档总量** | 随 feature **线性膨胀**（34,484 行） | 随**自研点**增长（照抄部分**不写**）⇒ 散文 : 代码回到 **≤ 1 : 1** |

### 3.1 什么时候才找你（**收窄到一类**）

**只有**「自研点」需要发起者过目，且**按 feature 一次性给全**：

```
本 feature 的自研点（共 N 条）：
 ① <一句话> —— 上游没有 / 照抄会破项目目标（零依赖 | 零出站 | 零账号）
    建议：<方案> —— 理由：<一行>
    备选：<方案> —— 代价：<一行>
```

> **N = 0 ⇒ 不问**（纯照抄 ⇒ 直接实现）。**N ≥ 1 ⇒ 一次问完**（不再逐题）。

### 3.2 立即停止的四件事（**止损**）

| # | 停止 | 理由 |
|---|---|---|
| **①** | 停止「**发明**上游已有的语义」 | 已造成 6 条不必要的分叉（§1.2）⇒ 每条分叉 = 1 条裁定 + 1–2 条 SC + 1 次签字 + 长期维护成本 |
| **②** | 停止「**spec 阶段 agent 拍板 ⇒ 发起者追认**」的仪式 | 追认的是「agent 的发明」⇒ **零价值**；照抄上游的部分**不需要**追认 |
| **③** | 停止「**复述上游语义**」的文档写法 | 34,484 行散文的**主要来源**；上游源码 + `路径:行号` 就是**更精确**的说明书 |
| **④** | 停止「**一个 feature 问 5–10 题**」 | 决策负担已超出个人项目的承受区间 ⇒ 本路线把每 feature 压到 **≤ 1 次**（通常 0 次） |

## 9. 结论与审批

**结论**：

1. 项目的目标（《立项书》摘要 + 摘要节的三条对外承诺）**从未改变**，**不需要改**；需要改的是**执行方式**。
2. 当前的僵死**不是 speckit 的错**，而是「**决策来源**从『上游源码』漂移成了『agent 发明 + 发起者追认』」⇒ 修的是**决策来源**，不是工具。
3. 本提案把「照抄」从**口号**变成**可核对的纪律**（上游锚点 + 差分夹具 + 只删不加）⇒ **可审计**、**可回退**。
4. 代价：**P0–P3 ≈ 4.5 天**；收益：后续 21 个 feature **每个少 1–3 天** + 发起者决策**从每 feature 10 题降到 ≤ 1 次**（通常 0 次）+ 项目风险**从「自研」降为「移植」**。
