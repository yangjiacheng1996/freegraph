## 提示词正文

### 1. 目标

让**调度内核**能表达并正确执行「**多源汇合边**」—— 即一条边的**源是多个节点**、
目标是**一个**节点，且目标 MUST 等到「**所有**源都跑过」才被触发（**AND / 屏障**语义）。

上游 `langgraph` 的 `StateGraph.add_edge([a, b], c)` 早已支持该形态；freegraph 的
`GraphSpec.edges` 是 `dict[str, tuple[str, ...]]`（**源只能是单个节点名**）⇒ **不可表达**
⇒ 本 feature 补齐这个**能力缺口**。

### 2. 背景与上下文

- **上游机制**（`langgraph 1.2.11` · `langgraph/graph/state.py:1560-1575`）：
  `add_edge([a, b], c)` 会为这条边建一条**专用的屏障通道** `join:a+b:c`
  （类型 `NamedBarrierValue(str, {"a", "b"})` · `langgraph/channels/named_barrier_value.py:13-30`）⇒
  **每个源**各写入**自己的名字**⇒ 屏障通道**收齐全部名字后**才变为可用 ⇒ 目标节点 `c`
  订阅该通道 ⇒ ⇒ **`c` 在 `a`、`b` 都跑完之后才被触发**。
  **实测基线**（上游 · `langgraph 1.2.11`）：`add_edge([a,b], c)` ⇒ 结果状态
  `{'msgs': ['a', 'b', 'c']}`（`c` 最后执行）。
- **freegraph 现状**：`GraphSpec.edges` 的键类型是 `str` ⇒ **单源**；`GraphSpec.__post_init__`
  的校验（V-2）逐一检查「源的键必须在节点表里」⇒ **多源键直接被拒**。
  ⇒ 本 feature 是**能力缺口**，不是「偏离」⇒ **必须与上游同款**。
- **触发层现状**（B7F1）：`_is_triggered` 的判定式**逐字**是
  「∃ 触发源 s ∈ sources(N) : version(s) > seen(N)[s]」⇒ **「任一」语义**。
  ⇒ 屏障需要的是「**所有**源都已越过各自的 `seen`」⇒ **「全」语义**。
  ⇒ **这两处是本 feature MUST 破的 B7F1 冻结面**（**发起者已于 2026-11-12 明确同意**）。
- **破冻结面的范围（**经发起者同意**，2026-11-12）**：
  - **B7F1 契约 §3.2** 的判定式（MUST 改写为「**单源：∃**；**多源：∀**」）；
  - **B7F1 契约 §1 / §3.1 / §4** 里 `edges` 的**键类型**（`str` ⇒ `str | tuple[str, ...]`）；
  - **B7F1 契约 §5** 的「边触发源的版本口径」（多源 ⇒ 逐源各记一条 `seen`）；
  - **B7F1 契约 §7** 的不变量 **I-12**（并发下执行顺序不确定 ⇒ 屏障的**触发**顺序亦然）；
  - **B7F1 的冻结断言**（`tests/runtime/` 的图规格与触发判定用例）⇒ 逐条**拆分**为
    「单源口径」与「多源口径」两族 ⇒ **既有断言一条不删**。
  - ⚠️ **MUST NOT** 破的：B7F1 的**通道冻结面**（`Channel` 的四个操作 · B5F1）·
    **L1 的 20 个符号面** · **门面的 7 个符号面** · **B5F2 的稀疏读** · **B9F1 的 `Command`**。
- **实现路线（本 feature MUST 走这条 · 代价最小 · 语义等价）**：
  **在触发层实现，不新增通道类型** —— 多源边的语义 = 「**所有**源的版本 > 各自的 `seen`」。
  ⇒ 与上游的屏障通道**可观察行为等价**（上游「收齐全部名字」≡ freegraph「所有源都跑过」）。
  ⇒ ⇒ **不新增** `NamedBarrierValue` 同款通道 ⇒ **不破** B5F1 的通道冻结面 ⇒ **零新增**导出符号。
- **与 B12F1（并发执行器）的关系**：屏障在串行下**同样成立**（`c` 仍等 `a`、`b`）⇒
  **逻辑上不依赖并发**；但「两个源真的在同一轮跑」的**价值**只有在并发下才显现
  ⇒ ⇒ 前置依赖含 **B12F1**（**顺序**：B12F1 → B7F4）。
- **与 B9F1（`Command.goto`）的关系**：动态边**恒为单源**（`goto` 指向一个节点名）⇒
  本 feature MUST NOT 改变动态边的形态 ⇒ **零改动**。

### 3. 用户场景

**P1 — 两个节点汇合到一个下游**
作为用户，我的图里有 `a`、`b` 两个并行分支，它们都完成后才能进入 `c`（例如
「两路检索都回来再汇总」）。我希望上游代码里的 `add_edge(["a", "b"], "c")`
**在 freegraph 里原样可用**。

- **独立验收**：`c` 的执行时刻在 `a`、`b` **之后**；且 `a` 或 `b` **任一**未跑时 `c` **不跑**。

**P2 — 只有一个源跑完时下游不触发**
作为用户，我希望「屏障没齐」时下游**静默等待**（而不是提前跑、或直接报错）。

- **独立验收**：只让 `a` 可达时，`c` 的执行计数 == **0**；图**正常收敛**（不抛错）。

**P3 — 与上游同款（差分可判定）**
作为维护者，我希望屏障语义与上游 `add_edge([a,b], c)` **逐字同款**，且有**自动化装置**证明。

- **独立验收**：`tests/differential/` 的**差分探针场景组**新增屏障场景且全绿。

### 4. 功能需求

- **FR-001**（`edges` 的源 MUST 支持多源）：`GraphSpec.edges` 的**键类型** MUST 由 `str`
  放宽为 **`str | tuple[str, ...]`** ⇒ 键为元组时表示「**这些源**共同汇合到目标」。
  ⚠️ **破 B7F1 冻结面**（**发起者 2026-11-12 同意**）⇒ MUST **回溯修订** B7F1 的契约与冻结断言。
- **FR-002**（多源的每个源 MUST 都在节点表里）：多源边的**每个**源 MUST 存在于节点表 ⇒
  否则 MUST **显式失败**（内置 `ValueError` · 与 B7F1 的 **V-2** 同族）⇒
  **点名**缺失的源名 ⇒ **零新增**错误类型。
- **FR-003**（屏障的触发判定 MUST 是「全」语义）：多源边的目标 MUST 仅在
  「**所有**源都已越过各自的 `seen`」时被触发 ⇒ MUST NOT 因「**某一个**源已跑」而提前触发。
  ⚠️ 判定式 MUST 逐字写成：**单源 ⇒ ∃ 触发源 s : version(s) > seen(s)**；
  **多源 ⇒ ∀ 源 s : version(s) > seen(s)** ⇒ ⇒ **回溯修订 B7F1 契约 §3.2**。
- **FR-004**（多源的 `seen` MUST 逐源各记一条）：多源边 MUST 为**每个**源各记一条
  「已消费版本」⇒ ⇒ **回溯修订 B7F1 契约 §5** ⇒ ⇒ 「**屏障只触发一次**」的承诺 MUST 保持
  （与 B7F1 的 SC-007「一轮内至多触发一次」同族 ⇒ **多源下 MUST 仍只触发一次**）。
- **FR-005**（**上游同款** · 屏障语义）：屏障 MUST 与上游 `add_edge([a,b], c)` **可观察等价**
  ⇒ 目标节点在**所有**源跑完后执行；**上游实测基线** = `{'msgs': ['a','b','c']}`。
  ⇒ ⇒ MUST 在 `tests/differential/parity_probe.py` 落**屏障场景**并与上游对跑。
- **FR-006**（**不新增通道类型** · 不破通道冻结面）：本 feature MUST **NOT** 新增任何
  通道类型 ⇒ MUST **NOT** 破 B5F1 的 `Channel` 冻结面 ⇒ ⇒ 屏障语义 MUST **完全**由
  **触发层**实现 ⇒ ⇒ **`freegraph.runtime.__all__` 的 20 个符号 MUST 零改动**。
- **FR-007**（动态边 MUST 不受影响）：`Command.goto` 产生的动态边**恒为单源** ⇒
  本 feature MUST **NOT** 改变其形态与语义 ⇒ **B9F1 零改动**。
- **FR-008**（`Command` / 稀疏读 MUST 不受影响）：本 feature MUST **NOT** 改变
  `Command.update` 的合并路径、**不改变**节点的入参口径（`read_channels(子映射)`）⇒
  **B9F1 / B5F2 零改动**。
- **FR-009**（**层纪律 · ARCH-1**）：本 feature 的代码 MUST 落在 **L2**
  （`src/freegraph/runtime/`）⇒ MUST 只向下依赖 **L1**（`freegraph.contracts`）⇒
  MUST **NOT** import 门面（L3）/ L4 / L5。
- **FR-010**（依赖隔离 · 零出站 · 零环境变量）：内核路径 `src/freegraph/**` MUST **NOT** import
  `langchain` / `langchain-core` / `langchain-*` / `langgraph*` / `langsmith`；MUST **NOT** 读取
  环境变量；MUST **零出站**、零文件 I/O。
- **FR-011**（**零新增门禁编号**）：既有门禁编号 **G1–G30** MUST 保持**连续无跳号**、总数 == **30**；
  本 feature MUST **NOT** 新增门禁编号 ⇒ 屏障的正确性由**差分探针**与**既有门禁**覆盖。
- **FR-012**（**破冻结面 MUST 登记 + 追认**）：本 feature MUST 落一条**阻断合入**的
  **发起者追认**任务（追认文字 MUST 落在 `harness/verification/B7F4/manual-verification.md` 内）
  ⇒ MUST 落**偏离登记项**（被破的冻结面 · 根因 · 判据未被放宽的论证 · 承接方 · 落点）
  ⇒ MUST **NOT** 以此放宽或稀释任何门禁判据。
- **FR-013**（**回溯修订的清单 MUST 逐条落全**）：MUST 回溯修订：
  ① B7F1 契约 §1（`edges` 键类型）· §3.1（触发源枚举）· §3.2（触发判定式）·
  §4（阶段①的顺序）· §5（版本口径 / `seen`）· §7 的 **I-12**；
  ② B7F1 的 `spec.md`（FR-002 / FR-013 / Edge Cases）与 `data-model.md`（V-2）；
  ③ B7F1 的冻结断言（**既有断言一条不删** ⇒ **拆分**为「单源」与「多源」两族）；
  ④ **已落地 feature 的执行记录**（B7F1 的 `tasks.md` / `research.md`）⇒ **只加注记 · 不改历史**。
- **FR-014**（**上游行号纪律**）：本 feature 引用的上游行为与源码 MUST 标注

- **FR-015**（人工验证记录）：`harness/verification/B7F4/manual-verification.md` MUST 存在且
  **五段式**小节齐全（验证环境 / 验证步骤 / 实际输出 / 结论 / 遗留问题）。
- **FR-016**（**不越界**）：本 feature MUST **NOT** 实现：上游的 `defer=True` 节点专用屏障
  （`NamedBarrierValueAfterFinish` · 上游 `graph/state.py:1567-1570`）· **跨 checkpoint** 的
  屏障状态持久化（归 **B14F1**）· **条件边**的路由判定（归 **B8F1**）· **构建器**侧的
  `add_edge` 接线（归 **B6F1**）⇒ ⇒ 本 feature 只交付 **L2 运行时**的可表达与可执行。

### 5. 成功标准

- **SC-001**：多源边 `("a", "b") -> "c"` ⇒ `c` 的执行**严格晚于** `a` 与 `b` ⇒
  且 `a`、`b` 的执行顺序**互不约束**（并发下二者可并行）。
- **SC-002**：只让**部分**源可达 ⇒ `c` 的执行计数 == **0** ⇒ 图**正常收敛**（**不抛错**）。
- **SC-003**：屏障**只触发一次** ⇒ `c` 在**同一轮**内至多被触发 **1** 次
  （与 B7F1 的 SC-007 同族）。
- **SC-004**：**与上游同款（差分可判定）** ⇒ 屏障场景在 `tests/differential/` 里
  **逐字一致**（节点序列 + 最终状态）。
- **SC-005**：**既有判据零削弱** ⇒ B7F1 的既有触发判定用例**一条不删** ⇒
  「单源口径」的断言数 == **改前**的断言数（拆分后**只增不减**）。

### 6. 验收判据（逐条可判定）

| # | 判据 | 判定方式 |
|---|---|---|
| A1 | 多源边可表达 | 构造 `edges={("a", "b"): ("c",)}` ⇒ **构造成功**（不抛错） |
| A2 | 屏障语义正确 | `a`、`b` 都跑 ⇒ `c` 执行且**在二者之后**；只 `a` 可达 ⇒ `c` **不执行** |
| A3 | 与上游同款 | 差分探针的**屏障场景**与上游 **逐字一致**（上游基线 `{'msgs': ['a','b','c']}`） |
| A4 | 既有断言零削弱 | B7F1 的触发判定用例**全绿**且**未删改**（拆分后只增不减） |
| A5 | 冻结面追认 | `manual-verification.md` 含**发起者追认**文字 + 偏离登记项 |

### 7. 关键实体与契约

| 实体 | 语义 | 对应契约 |
|---|---|---|
| 多源边 | `edges` 的键为 `tuple[str, ...]` ⇒ **AND / 屏障**语义 | B7F1 契约 §1 / §3.2（**本 feature 破**） |
| 触发源 | **边**触发源（静态边 ∪ 动态边）· 每个源各一条 | B7F1 契约 §3.1 / §5 |
| 屏障判定 | 单源 ⇒ ∃；多源 ⇒ ∀ | B7F1 契约 §3.2（**本 feature 破**） |

> **契约影响面**：本 feature **只**动 B7F1 的**触发层**口径 ⇒ **C4**（稀疏读）·
> **C5 / C6**（节点函数签名 / 返回值合并）· **C8**（条件边 fresh 读）· **C17**（中断）
> **语义零影响** ⇒ 契约 C1–C27 **零修订**。

### 8. 边界（本 feature 明确不做）

- **不**实现上游的 `defer=True` 节点专用屏障（`NamedBarrierValueAfterFinish`）⇒ 登记为
  「**已知不支持**」（上游 `graph/state.py:1567-1570`）。
- **不**实现跨 checkpoint 的屏障状态持久化（归 **B14F1**）。
- **不**实现条件边路由（归 **B8F1**）。
- **不**接线构建器侧的 `add_edge([a, b], c)`（归 **B6F1**）⇒ 本 feature 只交付
  **L2 运行时**可表达 ⇒ **构建器接线时直接透传**即可。
- **不**新增通道类型（**不破** B5F1 的通道冻结面）。
- **不**引入 async（v2 范围）。

### 9. 红线与质量门禁

- **依赖门禁（阻断，红线）**：无 `langsmith` / `langchain*` / `langgraph*`。
- **零出站 / 零环境变量**。
- **ARCH-1**：L2 只依赖 L1。
- **契约门禁**：屏障 MUST NOT 破坏 C4 / C5 / C6 / C8 / C17。
- **人工门禁**：`harness/verification/B7F4/manual-verification.md`（含**追认**文字）。
- **差分门禁（阻断）**：`tests/differential/` 的**差分探针场景组** MUST 全绿

- **证据门禁**：屏障语义与 LangGraph 的对应须标注**版本 + 源码行号**

- **追认门禁（阻断 · 破冻结面的代价）**：B7F1 冻结面的破 MUST 有**发起者追认**文字
  （见 FR-012）。
