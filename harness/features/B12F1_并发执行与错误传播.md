## 提示词正文

### 1. 目标

让调度内核能**真正执行节点函数**，并处理三件在真实使用中立刻会遇到的事：
① **同一 super-step 内的多节点并发执行**；② **节点抛异常时的错误传播**；
③ **多个节点同时中断时的 `GraphInterrupt` 合并**。本 feature 的判定是：
**并行节点不被串行化**、**首个异常被正确抛出**。

⚠️ **2026-11-12 · 上游对齐（本次修订的第一性目标）**：
**上游 `langgraph 1.2.11` 是唯一权威**（见 `harness/proposals/主路线.md` 的
「上游优先」三步判定）⇒ 本 feature MUST 以「**与上游行为面逐条同款**」为**缺省口径**；
**只在失败信号上**允许 freegraph **更严**，且 MUST **如实标注「比上游更严」**。
⇒ 凡本提示词未显式标注「刻意分叉」者，一律 MUST 照抄上游。

### 2. 背景与上下文

- 节点函数是**用户代码**：可能慢、可能抛异常、可能主动中断。运行时的职责是
  **如实反映**这些行为，而不是吞掉或改写。
- **并发是语义问题不是性能问题**：同一 super-step 内多个节点被触发时，它们的
  **写入必须按归约器合并**（B7F1 的合并路径）；若被串行化执行，「并行」退化为
  「顺序」——这在语义上会改变可观察行为（例如执行顺序影响写入顺序）。
- **`GraphInterrupt` 合并**：多个节点同时中断时，MUST 收集为**一组**中断信息（而不是
  只保留第一个），否则 HITL 场景会丢失待审批项。
- **错误传播**：第一个异常 MUST 正确抛出给调用方；MUST NOT 被静默吞掉或包装成
  语义不明的错误。
- **承接条款（B7F1 → B12F1 · M1 · 调度契约的跨 feature 接口）**：B7F1 已交付**调度内核**
  并**冻结**了跨 feature 的接口口径 ⇒ **本 feature MUST** 照它写：
  - **并发与顺序的切换点**：B7F1 的**同轮执行顺序** = **节点名序**（**上游同款** ·
    **2026-11-12 P2-c 已落地**：上游 `langgraph/pregel/_algo.py:482` 的
    `sorted(triggered_nodes)`）⇒ **本 feature 引入并发**时，MUST NOT 让
    「同一通道的待写入序列」失去确定性 ⇒ 非交换归约器的合并顺序 MUST 仍然**可复现**
    （不得依赖完成时刻的竞态）；
  - **合并路径口径**：写入 MUST 走 B7F1 的**批量**合并路径（每通道**一次**
    `Channel.update(values)` ⇒ 归约型按序归约）⇒ **本 feature MUST
    NOT** 另写一条并发合并路径；
  - **原子性口径**：B7F1 已冻结「一轮 super-step MUST 是**原子**的」（本轮任何环节出错 ⇒ 本轮
    产生的**全部**待写入不合并 ⇒ 通道的正式值 MUST 保持**本轮开始前**的样子）⇒ **本 feature
    MUST** 在并发下**保持**该性质（MUST NOT 出现「一部分通道已更新」的中间态）
    ⇒ ⚠️ **上游无回滚**（`langgraph/pregel/_algo.py:315-323`）⇒ freegraph 在此**比上游更严**
    ⇒ **MUST 标注**；
  - **异常传播口径**：B7F1 已冻结「节点抛出的异常 MUST **原样**向上传播」（不包装 · 不吞掉）
    ⇒ **本 feature** 的并发实现 MUST 保留「**第一个**异常**原样**抛出」的语义
    （不得包装成语义不明的错误）；
  - **节点入参口径**（裁定 26）：入参 MUST 等于 `read_channels(子映射)` 的结果，子映射 MUST
    按「**通道映射的顺序**」构造 ⇒ **本 feature MUST NOT** 改写 key 顺序；
  - **多会话隔离**（**已由 2026-11-12 P2-b 落地**）：每次运行从规格**新建**通道实例
    ⇒ 同一份图规格**可并发跑多次** ⇒ **初版的「已知限制 X-6」已作废**。
  该口径由 B7F1 的 `specs/b7f1-superstep-loop/spec.md`（FR-005 / FR-008 / FR-013 / FR-015 /
  FR-032 / 裁定 26）落成 · 契约见
  `specs/b7f1-superstep-loop/contracts/superstep-contract.md` §4 / §5.1 / §5.4。
- **承接条款（B9F1 → B12F1 · M1 · `Command` 的并发语义）**：B9F1 已交付 `Command` 原语的
  **运行期语义**（`goto` / `update` / `Command.PARENT`）并**冻结**了跨 feature 的接口口径
  ⇒ **本 feature MUST** 照它写：
  - **跳转语义口径**：B9F1 已把 `Command.goto` 落在 B7F1 的**边触发源**空间（`("e", 源节点名)`）
    ⇒ 同一 super-step 内多个节点并发执行时，**每个节点各自的 `goto` 目标 MUST NOT** 互相吞并
    （多目标合并口径由**本 feature** 拍板 · freegraph v1 的并发合并顺序另议）；
  - **合并路径口径**：`Command.update` MUST 继续走 B7F1 的**批量**合并路径（每通道**一次**
    `Channel.update(values)` ⇒ 归约型按序归约）⇒ **本 feature MUST NOT** 为 `Command`
    另写一条并发合并路径（否则「未知 key 只对 `dict` 报错」这类分叉迟早出现）。
  - **命令列表的并发维度（补充 · 2026-11-11）**：B9F1 已把节点返回值放宽出「**命令列表**」
    （`list[Command | StateDict]` · 一次返回多条命令 · 按**列表顺序**依次生效）⇒ **本 feature MUST**
    一并拍板「**多节点 × 多命令**」的归并顺序（MUST NOT 让完成时刻的竞态决定写入顺序 ⇒ 须可复现）
    ⇒ 详见 B9F1 的 `specs/b9f1-command-primitive/spec.md`（**裁定 15** · **裁定 21**）与 `plan.md`（**R-7**）。
  该口径由 B9F1 的 `specs/b9f1-command-primitive/spec.md`（FR-002 / FR-004 / FR-008 / 裁定 1 /
  裁定 3 / 裁定 4）落成。

### 3. 用户场景

**P1 — 多个节点在同一轮各自执行**
作为用户，我从 `START` 分叉到两个节点时，我希望它们**都被执行**（而不是只执行一个，
或排队执行）。

- **独立验收**：两个节点各自的副作用计数 == 1；且能观察到二者**并行**（非串行）。

**P2 — 节点抛异常时用户能拿到原始异常**
作为用户，我的节点里有个 bug 抛了 `ValueError`，我希望 freegraph 把它**原样**抛给我，
而不是包成 `RuntimeError` 或吞掉。

- **独立验收**：捕获到的异常类型与消息与节点内抛出的一致。

**P3 — 多个中断被完整收集**
作为实现者，两个节点同时请求人工审批时，我希望拿到**两个**中断，而不是一个。

- **独立验收**：中断集合长度 == 2，且各自的 `value` 正确。

**P4 — 与上游行为一致（差分可判定）**
作为维护者，我希望 freegraph 的并发 / 取消 / 中断语义与上游**逐条同款**，且**有自动化装置
证明**，而不是靠人工比对源码。

- **独立验收**：`tests/differential/` 的**差分探针场景组**全绿（见 §6 的 A4）。

### 4. 功能需求

- **FR-001**：系统 MUST 在同一 super-step 内**并发执行**所有被触发的节点任务。
  ⚠️ **并发度缺省 = `min(32, cpu+4)`**（**上游同款** · langchain-core
  `runnables/config.py:660-674`）⇒ 实际并发度 = `min(本轮任务数, 缺省上限)`；
  **显式** `max_concurrency=N` ⇒ 实际并发度 = `min(本轮任务数, N)`。
  ⚠️ 并发 MUST 用**线程**实现（标准库线程池）⇒ MUST NOT 引入 async / 事件循环抽象（v2 范围）。
  ⚠️ **零节点的一轮** MUST NOT 创建任何线程。
- **FR-002**：并发任务的**写入收集** MUST 保持「待写入 → 轮末统一合并」的语义
  （并发不得导致通道正式值被提前改写）。
- **FR-003**：系统 MUST 传播节点抛出的异常：首个异常 MUST 以**原始类型与消息**抛给
  调用方；MUST NOT 静默吞掉。
  ⚠️ **「首个」的判定 MUST 是确定性的**（**节点名序** · 上游同款排序口径）⇒
  MUST NOT 依赖「谁先跑完」（完成时刻的竞态）⇒ ⚠️ **比上游更严（上游自身不确定）**。
  ⚠️ **失败时 MUST 取消「排队未启动」的同轮任务**（**上游同款**）；运行中的任务 MUST
  **不中断**、但 MUST **被等待** ⇒ ⇒ 「本轮跑过哪些节点」**可复现**。
  ⚠️ **其余并发失败**：MUST NOT 被**静默**丢弃 ⇒ 以**附注**（标准库异常附注机制）记录在
  抛出的那个异常上 ⇒ 该附注 MUST NOT 改变异常的**类型 / 消息 / 对象 identity**
  ⇒ ⚠️ **比上游更严（上游丢弃其余异常）**；但**已取消任务**的异常 MUST NOT 收集。
- **FR-004**：系统 MUST 收集**全部** `GraphInterrupt`（而非只取第一个）⇒ 并
  **合并抛出**一个 `GraphInterrupt`，其载荷 = **元组**（**上游同款** ·
  `pregel/_runner.py:690`）⇒ ⚠️ **比上游多承载一层** ⇒ **B10F1 MUST 同步改接线**。
- **FR-005**：系统 MUST 在存在未处理异常时**停止后续 super-step**（不带着坏状态继续跑）。
  ⚠️ **同轮其它节点的写入**（含被中断节点之外的）MUST **照常合并**（上游同款）。
- **FR-006**：并发执行 MUST NOT 改变通道写入的**合并语义**（与串行执行结果一致）。
- **FR-007**：系统 MUST NOT import `langchain` / `langchain-core`；MUST NOT 读环境变量；
  MUST NOT 阻塞式依赖任何外部服务。
- **FR-008**：本 feature 不引入 async（v2 范围）——并发用**线程**实现即可，
  MUST NOT 为 async 预留会破坏 v1 简洁性的抽象。
- **FR-009（顺序口径 · 上游同款）**：同一通道上多个写入的**合并顺序** MUST 由
  「**节点名序**」决定（**上游同款** · `pregel/_algo.py:482`）⇒ MUST NOT 依赖完成时刻的竞态、
  MUST NOT 依赖字典哈希序；**非交换归约器**的合并结果 MUST **可复现**。
  ⚠️ `executed` 的**成员** MUST 记「本轮**被启动过**的节点」（**含**被中断的节点 ·
  上游同款）；**顺序** MUST 为**节点名序**。
- **FR-010（原子性 · 比上游更严）**：一轮内**任何**环节出错 ⇒ 该轮产生的**全部**待写入
  MUST **不**被合并 ⇒ 通道的正式值 MUST 保持**本轮开始前**的样子 ⇒ MUST **NOT** 出现
  「一部分通道已更新、一部分没更新」的中间态 ⇒ ⚠️ **上游无回滚** ⇒ **比上游更严** · **须标注**。
  ⚠️ **调度状态同样纳入本条**：该轮**任何**节点的「执行版本」与「跳转目标」MUST **不**落回。
- **FR-011（可观测面零新增）**：本 feature MUST **NOT** 新增 `freegraph.runtime.__all__`
  的符号（**仍为 20**）⇒ 并发执行器 MUST 作为**内部实现**存在（`runtime/` 目录下的非导出模块）。
- **FR-012（旋钮）**：两个调度入口 MUST 提供一个 **keyword-only** 的
  `max_concurrency: int | None = None`（**上游同名同义**）⇒ `max_concurrency=1` ⇒ **串行基线**
  ⇒ 「并发与串行结果一致」MUST **可判定**；非法取值 MUST **显式失败**
  （类型不符 ⇒ 内置 `TypeError`；`< 1` ⇒ 内置 `ValueError`；两者均 MUST 点名该参数）。
- **FR-013（差分装置 · 新增）**：本 feature MUST 交付**一组**「上游 ↔ freegraph 同场景对跑」
  的**差分探针场景**（落 `tests/differential/parity_probe.py` · 判词三态：
  `SAME` / `STRICTER` / `DIFF`）⇒ 覆盖：① **并发重叠** ② **首个异常的对象 identity 与消息**
  ③ **取消语义**（排队未启动者被取消 · 运行中者被等待）④ **中断合并成一个异常且载荷为元组**
  ⑤ **中断节点的写入被丢弃 / 其它节点照常合并** ⑥ **并发 == 串行（`max_concurrency=1`）**
  ⇒ ⇒ 这些场景 MUST 在 CI（**装了上游差分组的作业**）里**真跑** ⇒ ⇒
  **任何 feature 让地基与上游分叉 ⇒ 差分用例立刻红**（不再依赖人工回改轮次发现）。

### 5. 成功标准

- **SC-001**：同一 super-step 内 2 个节点并发执行，两者副作用计数均为 1，
  且**不呈串行特征**（可判定：两节点重叠执行时间窗 > 0，或用屏障类夹具证明）。
- **SC-002**：节点抛出的异常类型与消息**逐字**传到调用方（**对象 identity 相同**）。
- **SC-003**：2 个节点同时中断 → **合并成一个** `GraphInterrupt`，其载荷是**长度 == 2** 的**元组**。
- **SC-004**：并发执行与串行执行（同一规格 · `max_concurrency=1`）产生的**最终状态一致**。
- **SC-005**：存在异常时，后续 super-step **不执行**（可由执行计数判定）；
  且「**排队未启动**」的同轮任务**被取消**。
- **SC-006**：**差分探针场景组全绿**（FR-013 的 6 类场景）。

### 6. 验收判据（= 立项书 §5.2 B12F1 小目标，逐条可判定）

> 小目标原文：并行节点不串行化；首个异常正确抛出

| # | 判据 | 判定方式 |
|---|---|---|
| A1 | 并行节点不串行化 | 并发夹具（屏障/重叠时间窗）判定二者重叠执行 |
| A2 | 首个异常正确抛出 | 断言捕获到的异常类型与消息 == 节点内抛出的（**identity 相同**） |
| A3 | 存在异常时**后续 super-step 不执行** | 断言下游节点的执行计数 == 0（不带着坏状态继续跑） |
| A4 | **与上游同款（差分可判定）** | `tests/differential/` 的**差分探针场景组**全绿（上游 `langgraph 1.2.11`） |

### 7. 关键实体与契约

| 实体 | 语义 | 对应契约 |
|---|---|---|
| 节点任务执行 | 调用用户节点函数、收集其返回值 | C5 / C6 |
| 并发任务组 | 同一 super-step 内被触发的节点任务集合 | C6 |
| `GraphInterrupt` 合并 | **一个**异常 · 载荷 = **元组**（元素含 `.value` / `.id`） | **C17** |

> **口径提醒**：C17 要求中断结果含 `__interrupt__` 键，元素含 `.value` / `.id`；
> **结果键的落点**在 B10F1，本 feature 只负责「多个中断被完整收集并合并成一个异常」
> 这一运行时语义 ⇒ ⚠️ **B10F1 的接线 MUST 随之改**（元素类型 = 上游同款的**元组**）。

### 8. 边界（本 feature 明确不做）

- 不实现 `interrupt()` 的产生与恢复闭环（属 B10F1）——本 feature 只处理「若节点抛出
  `GraphInterrupt` 则收集并合并」。
- 不实现 async 全套（v2 范围，未排 feature）。
- 不实现 `Send` 的动态 fan-out（属 B11F1）。
- 不实现 `recursion_limit`（属 B13F1）。
- 不实现 checkpoint（属 B14F1）。
- 不实现节点级重试 / 超时（不在 v1 范围）。
- ⚠️ **不实现「多源汇合边」（AND / 屏障语义）** —— 上游 `add_edge([a,b], c)` 可表达
  （`langgraph/graph/state.py:1560-1575` 的 `NamedBarrierValue`），freegraph 的
  `GraphSpec.edges` 是**单源** ⇒ **能力缺口** ⇒ **本 feature MUST NOT 顺手做**
  （会破 B7F1 的 `edges` 冻结面）⇒ **承接方待定（建议独立 feature）**。

### 9. 红线与质量门禁

- **依赖门禁（阻断，红线）**：无 `langsmith` / `langchain*` / `langgraph*`。
- **零出站 / 零环境变量**。
- **ARCH-1**：L2 只依赖 L1。
- **契约门禁**：并发 MUST NOT 破坏 C4 / C6 / C8 语义。
- **人工门禁**：`harness/verification/<feature>/manual-verification.md`。
- **证据门禁**：并发语义与 LangGraph 的对应须标注**版本 + 源码行号**
  （`langgraph/pregel/_runner.py:660-700` · `langgraph/pregel/_algo.py:482` ·
  `langchain_core/runnables/config.py:660-674`）。
- ★ **差分门禁（新增 · 阻断）**：`tests/differential/` 的**差分探针场景组** MUST 全绿
  ⇒ ⇒ 它是「**地基与上游同款**」的**常驻门禁**（CI 的 Linux 全量档装了上游差分组 ⇒ 真跑；
  其它档 **skip**（非失败）· 沿用 B5F2 的「缺席即 skip」纪律）。

### 10. 交付物与后续

- **交付物**：节点执行器、并发执行与写入收集、错误传播、`GraphInterrupt` 合并、
  **差分探针场景组**、单元测试 + 人工验证记录。
- **后续解锁**：**B10F1**（`interrupt` + `resume` · ⚠️ **接线须适配「元组载荷」**）→
  **B7F3**（`invoke` 对外 API，依赖 B12F1 的错误传播）。
- **风险提示**：并发一旦引入，**测试的不确定性**会上升。spec 阶段应要求
  「并发与串行结果一致」这一**确定性判据**，而不是靠「跑 100 次都没错」。
