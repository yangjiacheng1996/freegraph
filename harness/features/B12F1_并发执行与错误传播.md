## 提示词正文

### 1. 目标

让调度内核能**真正执行节点函数**，并处理三件在真实使用中立刻会遇到的事：
① **同一 super-step 内的多节点并发执行**；② **节点抛异常时的错误传播**；
③ **多个节点同时中断时的 `GraphInterrupt` 合并**。本 feature 的判定是：
**并行节点不被串行化**、**首个异常被正确抛出**。

### 2. 背景与上下文

- 节点函数是**用户代码**：可能慢、可能抛异常、可能主动中断。运行时的职责是
  **如实反映**这些行为，而不是吞掉或改写。
- **并发是语义问题不是性能问题**：同一 super-step 内多个节点被触发时，它们的
  **写入必须按归约器合并**（B7F1 的合并路径）；若被串行化执行，「并行」退化为
  「顺序」——这在语义上会改变可观察行为（例如执行顺序影响写入顺序）。
- **`GraphInterrupt` 合并**：多个节点同时中断时，MUST 收集为**一组**中断信息（而不是
  只保留第一个），否则 HITL 场景会丢失待审批项。
- **错误传播**：第一个异常 MUST 正确抛出给调用方；MUST NOT 被静默吞掉或包装成
  语义不明的错误。

### 3. 用户场景

**P1 — 多个节点在同一轮各自执行**
作为用户，我从 `START` 分叉到两个节点时，希望它们**都被执行**（而不是只执行一个，
或排队执行）。

- **独立验收**：两个节点各自的副作用计数 == 1；且能观察到二者**并行**（非串行）。

**P2 — 节点抛异常时用户能拿到原始异常**
作为用户，我的节点里有个 bug 抛了 `ValueError`，我希望 freegraph 把它**原样**抛给我，
而不是包成 `RuntimeError` 或吞掉。

- **独立验收**：捕获到的异常类型与消息与节点内抛出的一致。

**P3 — 多个中断被完整收集**
作为实现者，两个节点同时请求人工审批时，我希望拿到**两个**中断，而不是一个。

- **独立验收**：中断集合长度 == 2，且各自的 `value` 正确。

### 4. 功能需求

- **FR-001**：系统 MUST 在同一 super-step 内**并发执行**所有被触发的节点任务。
- **FR-002**：并发任务的**写入收集** MUST 保持「待写入 → 轮末统一合并」的语义
  （并发不得导致通道正式值被提前改写）。
- **FR-003**：系统 MUST 传播节点抛出的异常：首个异常 MUST 以**原始类型与消息**抛给
  调用方；MUST NOT 静默吞掉。
- **FR-004**：系统 MUST 收集**全部** `GraphInterrupt`（而非只取第一个），并以可判定的
  结构返回。
- **FR-005**：系统 MUST 在存在未处理异常时**停止后续 super-step**（不带着坏状态继续跑）。
- **FR-006**：并发执行 MUST NOT 改变通道写入的**合并语义**（与串行执行结果一致）。
- **FR-007**：系统 MUST NOT import `langchain` / `langchain-core`；MUST NOT 读环境变量；
  MUST NOT 阻塞式依赖任何外部服务。
- **FR-008**：本 feature 不引入 async（v2 范围）——并发用**线程**实现即可，
  MUST NOT 为 async 预留会破坏 v1 简洁性的抽象。

### 5. 成功标准

- **SC-001**：同一 super-step 内 2 个节点并发执行，两者副作用计数均为 1，
  且**不呈串行特征**（可判定：两节点重叠执行时间窗 > 0，或用屏障类夹具证明）。
- **SC-002**：节点抛出的异常类型与消息**逐字**传到调用方。
- **SC-003**：2 个节点同时中断 → 中断集合长度 == 2。
- **SC-004**：并发执行与串行执行（同一规格）产生的**最终状态一致**。
- **SC-005**：存在异常时，后续 super-step **不执行**（可由执行计数判定）。

### 6. 验收判据（= 立项书 §5.2 B12F1 小目标，逐条可判定）

> 小目标原文：并行节点不串行化；首个异常正确抛出

| # | 判据 | 判定方式 |
|---|---|---|
| A1 | 并行节点不串行化 | 并发夹具（屏障/重叠时间窗）判定二者重叠执行 |
| A2 | 首个异常正确抛出 | 断言捕获到的异常类型与消息 == 节点内抛出的 |
| A3 | 存在异常时**后续 super-step 不执行** | 断言下游节点的执行计数 == 0（不带着坏状态继续跑） |

### 7. 关键实体与契约

| 实体 | 语义 | 对应契约 |
|---|---|---|
| 节点任务执行 | 调用用户节点函数、收集其返回值 | C5 / C6 |
| 并发任务组 | 同一 super-step 内被触发的节点任务集合 | C6 |
| `GraphInterrupt` 收集 | 一组中断（每项含 `.value` / `.id`） | **C17** |

> **口径提醒**：C17 要求中断结果含 `__interrupt__` 键，元素含 `.value` / `.id`；
> **结果键的落点**在 B10F1，本 feature 只负责「多个中断被完整收集」这一运行时语义。

### 8. 边界（本 feature 明确不做）

- 不实现 `interrupt()` 的产生与恢复闭环（属 B10F1）——本 feature 只处理「若节点抛出
  `GraphInterrupt` 则收集」。
- 不实现 async 全套（v2 范围，未排 feature）。
- 不实现 `Send` 的动态 fan-out（属 B11F1）。
- 不实现 `recursion_limit`（属 B13F1）。
- 不实现 checkpoint（属 B14F1）。
- 不实现节点级重试 / 超时（不在 v1 范围）。

### 9. 红线与质量门禁

- **依赖门禁（阻断，红线）**：无 `langsmith` / `langchain*` / `langgraph*`。
- **零出站 / 零环境变量**。
- **ARCH-1**：L2 只依赖 L1。
- **契约门禁**：并发 MUST NOT 破坏 C4 / C6 / C8 语义。
- **人工门禁**：`harness/verification/<feature>/manual-verification.md`。
- **证据门禁**：并发语义与 LangGraph 的对应须标注源码行号
  （`langgraph/pregel/_runner.py` 941 行：节点执行、并发、错误处理）。

### 10. 交付物与后续

- **交付物**：节点执行器、并发执行与写入收集、错误传播、`GraphInterrupt` 收集、
  单元测试 + 人工验证记录。
- **后续解锁**：**B10F1**（`interrupt` + `resume`）→ **B7F3**（`invoke` 对外 API，
  依赖 B12F1 的错误传播）。
- **风险提示**：并发一旦引入，**测试的不确定性**会上升。spec 阶段应要求
  「并发与串行结果一致」这一**确定性判据**，而不是靠「跑 100 次都没错」。
