## 提示词正文

### 1. 目标

交付**本地 trace 存储**的第一段：一个**零依赖**的 **JSONL 文件后端**——把运行中产生的
span 落盘成一行一条的 JSON 记录。本 Phase 的判定是：**trace 落盘，零出站**。

### 2. 背景与上下文

- **v1 可视化三件套**（宪法原则 IV / 立项书 §5.6）：① 图视图（mermaid，纯本地零出站）
  ② **trace 时间线 / 详情（本地存储）** ③ 状态快照 + checkpoint 历史 + 回放入口。
  本 Phase 是第 ② 件的**存储底座**。
- **零依赖是硬约束**：基础安装**零**第三方依赖——因此后端 MUST 只用**标准库**
  （`json` + `os` / `pathlib`），**MUST NOT** 引入 SQLite 绑定等第三方依赖
  （SQLite 后端在 **F20P2**，用标准库 `sqlite3`——它属于标准库，不是第三方依赖）。
- **零出站**：本地存储不得触发任何网络行为。
- **形态待锁定**：`harness/demo/README.md` 列出「本地 trace 目录的**参数名**」是
  **未锁定的形态**，随 M3 各 Phase 一同锁定。本 Phase 正是锁定它的时点。
- ✅ **缺口 1 已关闭（D11 批准 2026-11-05）**：**「本地 trace 存储与查询」已增补为
  契约条目 C27**（请求 / 返回结构、JSON 可序列化，见 Q8 §3.4.1 / 立项书 §5.3.1）。

### 3. 用户场景

**P1 — 运行轨迹留在本机**
作为用户，我跑完一次图后，希望在**本地目录**里能看到这次运行的完整 span 记录，
以便事后排查（不依赖任何云服务、不需要账号）。

- **独立验收**：注入 trace 存储后运行一次，目录中生成 JSONL 文件且含 span 记录。

**P2 — 记录可被人与机器读取**
作为用户，我希望记录是**每行一条 JSON**（可直接 `jq` 过滤、可用文本编辑器查看）。

- **独立验收**：每行可被 `json.loads` 解析为 dict。

**P3 — 不启用时不留痕迹**
作为用户，我不启用 trace 存储时，希望**不产生任何文件**。

- **独立验收**：未启用时目标目录不存在 / 无新增文件。

### 4. 功能需求

- **FR-001**：系统 MUST 提供**本地 trace 存储后端**，默认实现为 **JSONL 文件后端**
  （零第三方依赖，只用标准库）。
- **FR-002**：每条 span 记录 MUST 序列化为**一行一个 JSON 对象**（JSONL），
  可被 `json.loads` 独立解析。
- **FR-003**：记录内容 MUST 至少包含：`Span` 的全部字段（`name` / `attributes` /
  `parent` / `start_time` / `end_time` / `context`）+ 关联键
  （`thread_id` / `run_id` / 节点名，⚠️ 关联键字段约定见 §7）。
- **FR-004**：存储 MUST **零出站**；MUST NOT 访问任何外部服务。
- **FR-005**：未启用存储时，MUST **不创建任何文件、不产生任何副作用**。
- **FR-006**：系统 MUST 提供**存储目录/路径的注入形态**（参数名 MUST 在本 Phase
  锁定，见 §7 与 §10）。
- **FR-007**：写入失败（如目录不可写）时，MUST **不使运行失败**——可诊断能力不得
  阻断核心执行（宪法原则 IV：可视化层 MUST NOT 阻断执行）。失败 MUST 可被感知
  （如记录诊断信息或回调）。
- **FR-008**：系统 MUST NOT import `langchain` / `langchain-core`；MUST NOT 读环境变量。

### 5. 成功标准

- **SC-001**：启用后每次运行生成 JSONL 文件，**每行可被 `json.loads` 解析**。
- **SC-002**：记录中包含 span 的全部字段 + 关联键（逐字段断言）。
- **SC-003**：未启用时**零文件产生**（目录快照比对）。
- **SC-004**：写入路径不可写时，运行**仍然成功**（核心执行不被阻断）。
- **SC-005**：零出站（socket 监测夹具「框架出站 = 0」）。

### 6. 验收判据（= 立项书 §5.2 F20P1 小目标，逐条可判定）

> 小目标原文：trace 落盘，零出站

| # | 判据 | 判定方式 |
|---|---|---|
| A1 | trace 落盘 | 启用后目录中生成 JSONL，含 span 记录 |
| A2 | 零出站 | socket 夹具断言「框架出站 = 0」 |
| A3 | 每行可独立解析 + 含关联键 | 逐行 `json.loads` 成功；记录含 `thread_id` / `run_id` / 节点名 / `checkpoint_id`（C23 字段约定） |

### 7. 关键实体与契约

| 实体 | 语义 | 对应契约 |
|---|---|---|
| trace 记录 | span 的 JSONL 序列化 | **✅ C27**（缺口 1 已关闭，2026-11-05 · D11） |
| 关联键 | `thread_id` / `run_id` / 节点名 / `checkpoint_id` | **✅ C23 字段约定**（缺口 2 已关闭，同日） |

> ✅ **口径（已冻结 · D11 批准 2026-11-05）**：立项书 §5.8.3 的**缺口 1** 已关闭——
> **C27 = 本地 trace 存储与查询**已冻结：① 写入接收自有 `Span` 的序列化记录并落本地存储
> （**零出站**）；② 查询按 **`run_id` / `thread_id` / 时间范围 / 节点名**检索（**四者可组合**）；
> ③ **请求与返回结构 MUST JSON 可序列化**；④ 存储与查询同一协议、后端可替换；
> ⑤ 表结构 / 文件格式属**内部实现细节**（对外只暴露查询 API）。
> → **本 Phase 的义务**：记录内容 MUST 含 `Span` 全部字段 + 关联键
> （`thread_id` / `run_id` / 节点名 / `checkpoint_id`），并逐字段对齐 C27。
> **注意**：本 Phase 只负责**写入**（记录里必须带上 `run_id`，否则后续无法按运行检索）；
> **查询侧**（含 `run_id` 过滤器）属 F20P2。

### 8. 边界（本 Phase 明确不做）

- 不实现 **查询 API** 与 **SQLite 后端**（属 F20P2）——本 Phase 只写不读
  （可写一个最小「读回自己写的文件」的校验用于测试）。
- 不实现 OTLP 导出（属 F21P1）。
- 不实现前端 / UI（v2 / F26）。
- 不实现 trace 的**保留期 / 清理策略**（v1 不做；若纳入须写明默认行为）。
- 不实现评测 / 数据集（永不做）。

### 9. 红线与质量门禁

- **依赖门禁（阻断，红线）**：零第三方依赖（只用标准库）。
- **零出站 / 零环境变量**。
- **可视化不阻断执行**（宪法原则 IV）：写入失败 MUST NOT 使运行失败。
- **ARCH-1 / ARCH-3**：L5 只依赖 L1；跨层只经由协议 + 纯数据。
- **人工门禁**：`harness/features/<feature>/manual-verification.md`。
- **证据门禁**：JSONL 记录结构的字段清单须与 §7 的契约状态一致标注。

### 10. 交付物与后续

- **交付物**：JSONL 文件后端（写入路径注入形态 + 记录结构）、记录结构说明、
  单元测试 + 人工验证记录。
- **形态锁定（本 Phase 必办）**：锁定「本地 trace 目录/路径的注入形态与参数名」，
  并更新 `harness/demo/README.md` 的「待锁定形态」清单（该项从待锁定清单移除）。
- **后续解锁**：**F20P2**（Trace 查询 API + SQLite 后端）→ **F21P1**（OTLP 导出）。
- **风险提示**：写入失败「不阻断运行」的取舍要写清楚——静默吞掉错误会让用户以为
  trace 已记录。spec 阶段须决定**失败如何被感知**（诊断输出 / 回调 / 计数），
  并把它写成可判定条目。
