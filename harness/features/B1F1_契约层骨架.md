## 提示词正文

### 1. 目标

建立 freegraph 的**唯一数据与类型契约层**：交付一个可独立安装、可被外部单独消费的
`freegraph.contracts` 包，其中定义状态字典、命令原语、状态快照、运行配置四类核心类型，
以及一套完整的异常体系。本 feature **不交付任何运行时行为**——它交付的是「此后全部代码
都必须引用的类型地基」，并且这块地基**不依赖任何内部模块**。

### 2. 背景与上下文

- freegraph 采「6 层单向依赖 + 1 个契约层」架构（L1 契约层 → L2 运行时 → L3 图定义 →
  L4 持久化 / L5 可观测）。**契约层是全部工作的前置**：运行时层的 `StateDict`、图定义层的
  `CompiledGraph`、持久化层的 `StateSnapshot`、可观测层的 `Span` 关联键全部引用本层类型。
- 跨仓库姊妹项目 **freechain**（LangChain 替代层）将基于本层契约构建。本层必须能被
  **单独消费**——freechain 不得为了用状态类型而被迫依赖 freegraph 的运行时实现。
- 宪法原则 II（内核纯净）要求内核不 import `langchain` / `langchain-core`。
  本层的类型定义**不得**复用 `RunnableConfig`（它是 `langchain-core` 类型，复用即把
  `langsmith` 拖回来）；运行配置必须自有。

### 3. 用户场景

**P1 — 上层开发者能引用稳定的状态与运行配置类型**
作为 freechain 的开发者，我希望能 `from freegraph.contracts import StateDict, RunConfig`
直接定义节点函数签名，并在类型检查器中得到补全，以便我不必猜测 freegraph 的状态形状。

- **独立验收**：在只安装 freegraph 基础包的环境中执行该 import 成功，且不触发任何
  内部模块加载。

**P2 — 运行时实现者能在不依赖内部层的前提下定义异常语义**
作为内核实现者，我希望所有跨层失败的异常都有统一基类与稳定名字（`InvalidUpdateError` /
`GraphRecursionError` / `GraphInterrupt`），以便上层能只捕获基类就兜住全部内核错误。

- **独立验收**：断言这三个异常都继承自同一基类，且基类也继承自 `Exception`。

**P3 — 契约层可被单独安装与消费**
作为 freechain 的打包者，我希望能只依赖 freegraph 的契约层（不触发运行时/持久化/可观测
任何代码），以便契约变更能被单独审计与冻结。

- **独立验收**：静态断言契约层模块的 import 图中不存在任何对 freegraph 内部模块
  （`freegraph.runtime` / `freegraph.graph` / `freegraph.persistence` /
  `freegraph.observability` 等）的引用。

### 4. 功能需求

- **FR-001**：系统 MUST 提供 `freegraph.contracts` 包，`import freegraph.contracts`
  成功且不产生任何运行时副作用（不读环境变量、不发起网络请求、不加载内部层）。
- **FR-002**：系统 MUST 定义 `StateDict` —— 表示图状态的**稀疏字典**（只包含当前有值的
  key）；类型上 MUST 与 `dict[str, Any]` 兼容，MUST NOT 自造并行状态类型体系。
- **FR-003**：系统 MUST 定义 `Command` —— 命令原语，承载 `goto` / `update` / `resume`
  三个语义位，并提供 `Command.PARENT` 常量（表示「向父图跳转」）。
- **FR-004**：系统 MUST 定义 `StateSnapshot` —— 状态快照，字段为 `values` / `next` /
  `config` / `metadata` / `created_at` / `tasks` / `interrupts`。
- **FR-005**：系统 MUST 定义 `RunConfig` —— 每次运行的配置载体，字段为 `thread_id` /
  `context` / `metadata` / `tags`。MUST NOT 复用 `langchain_core.runnables.RunnableConfig`。
- **FR-006**：系统 MUST 提供统一异常体系：基类 + `InvalidUpdateError`（节点返回了状态
  schema 中不存在的 key）+ `GraphRecursionError`（递归超限）+ `GraphInterrupt`（节点主动
  中断）。
- **FR-007**：契约层 MUST **零**第三方运行时依赖——基础安装的依赖闭包 MUST 为**空集**；
  MUST NOT 引入任何第三方运行时依赖。**最低 Python 版本为 3.11**（3.11 起 `Self` /
  `NotRequired` / `Required` / `TypeVarTuple` / `Unpack` / `LiteralString` /
  `dataclass_transform` 均在标准库内，故无需 `typing-extensions` 兜底；
  见《项目宪法》修订记录 v1.2.0）。
- **FR-008**：契约层 MUST NOT import 任何 freegraph 内部模块（ARCH-2 断言）。
- **FR-009**：本层导出的全部类型 MUST 具备完整类型注解，且包 MUST 随发行产物发布
  `py.typed`（PEP 561）。
- **FR-010**：本 feature 新建的**每一个源文件 MUST 携带署名头**（宪法原则 X）：
  `# Copyright (c) 2026 杨家成 · MIT License · https://github.com/yangjiacheng1996/freegraph`
  （模块 docstring 仍 MUST 是首个语句）。**理由**：MIT 允许文件被单独复制，
  署名必须随文件流动——这是「个人作品集」定位下**署名头的兑现机制**。
- **FR-011**：**顶层包 MUST 保持惰性**——`freegraph/__init__.py` MUST 只暴露
  `__version__` 等元信息，MUST NOT 导入 `freegraph.contracts` / `freegraph.graph` /
  运行时 / 持久化 / 可观测任何子模块；`import freegraph` MUST NOT 连带加载内部层
  （**D1 决议的附加约束**：否则契约层「可独立消费」的收益失效，freechain 无法只取
  契约而不拖进运行时）。

### 5. 成功标准

- **SC-001**：在**隔离环境**（只安装 freegraph 基础包）执行 `import freegraph.contracts`
  成功，耗时与普通 import 同量级。
- **SC-002**：递归展开 freegraph 自身声明的依赖后，**基础安装（不含任何 extras 变体）**的
  依赖闭包为**空集**（零第三方运行时依赖），无 `langsmith` / `langchain*` / `langgraph*`。
  （**extras 变体的闭包另按宪法依赖白名单校验**——extras 由 B3F1 引入，本 feature 尚无 extras。）
- **SC-003**：CI 的 AST 扫描断言：契约层模块的 import 图中**零**条指向 freegraph 内部
  模块的边（违反即 CI 失败）。
- **SC-004**：`StateDict` / `Command` / `StateSnapshot` / `RunConfig` 四个类型的字段与
  注解 100% 覆盖，可由 `typing.get_type_hints` 解析。
- **SC-005**：异常体系满足「三子异常同基类、基类继承 `Exception`」的结构约束，
  且基类可被单独 `except` 捕获。
- **SC-006**：**顶层包惰性**——`import freegraph` 后 `sys.modules` 中**不含**
  `freegraph.contracts` / `freegraph.graph` / `freegraph.runtime` /
  `freegraph.persistence` / `freegraph.observability`；`import freegraph.contracts`
  后 `sys.modules` 中**不含任何内部层模块**（**契约层自身的子模块如
  `freegraph.contracts.types` / `.errors` 不受此限**）。

### 6. 验收判据（= 立项书 §5.2 B1F1 小目标，逐条可判定）

> 小目标原文：`import freegraph.contracts` 成功；**依赖零（闭包为空集）**；
> **C1/C11/C16/C22 类型冻结**；契约层不 import 任何内部模块

| # | 判据 | 判定方式 |
|---|---|---|
| A1 | `import freegraph.contracts` 成功 | 隔离 venv 中执行，退出码 0 |
| A2 | 依赖**零**（闭包为空集） | 递归展开 `importlib.metadata.requires('freegraph')` 后核对 |
| A3 | **C1 / C11 / C16 / C22 类型冻结** | 四个类型定义落盘并通过类型注解完整性断言（SC-004）；冻结记录写入 feature 验收记录 |
| A4 | 契约层不 import 任何内部模块 | CI AST 断言（SC-003） |
| A5 | **顶层包惰性（D1 决议附加约束 · ARCH-2 可判定项）** | `import freegraph` 与 `import freegraph.contracts` 后的 `sys.modules` 检查（SC-006） |

### 7. 关键实体与契约

| 实体 | 语义 | 对应契约 |
|---|---|---|
| `StateDict` | 稀疏状态字典 | C1 / C4 / C6 |
| `Command` | 命令原语（`goto` / `update` / `resume`） | C16 / C17 |
| `StateSnapshot` | 状态快照 | C19 |
| `RunConfig` | 运行配置 | C22 |

- **C1（状态 schema）**：schema 本身由用户以 `TypedDict` 表达；本层的 `StateDict` 只是
  「运行时传给节点的稀疏字典」的类型名，**MUST NOT** 要求用户继承任何 freegraph 基类。
- **C11（执行）**：`invoke(input, config=None) -> dict`，返回**完整状态**。本 feature 只
  冻结「返回类型是 `StateDict`」这一点。
- **C16（命令原语）**：`Command(goto=..., update=..., resume=...)` 三个语义位
  **至少填一个**——三者全为 `None` 时构造即抛 `FreegraphError`；三者可任意组合。
- **C22（运行配置）**：`thread_id` / `context` / `metadata` / `tags` 四个字段。
  `context` 是**独立通道**，不塞进 `configurable`（C21）。

### 8. 边界（本 feature 明确不做）

- 不实现任何运行时行为：无调度、无 channel、无状态读写。
- 不定义节点函数协议与 4 类协议（`Node` / `Checkpointer` / `TraceSink` / `Store`）——
  属 **B2F1**。
  > **后续更名注记（2026-11-06 · B2F1 澄清 Q1）**：上文的 `Node` 指**节点函数协议**，
  > 其名在 B2F1 已定为 **`NodeFunc`**（`Node` 一词此后**唯一**指图结构节点元素）。
  > 注：`Store` 协议（**C20**）虽**仍冻结**，但 **v1 无实现**（B17 已砍，2026-11-05）——
  > 契约层保留它是为了 freechain 的设计输入不被破坏。
- 不定义公开 API 门面 `freegraph/graph.py` —— 属 **B2F2**。
- 不搭建 `pyproject.toml` / extras / CI 门禁 —— 属 **B3F1**（本 feature 可复用仓库既有
  `pyproject.toml`，但不得改依赖白名单）。
- 不实现 `Send` / `interrupt` 的具体运行时语义（只在本层预留类型位，属 B2F1 协议范畴）。
- **不新增第二个发行包**（**D1 已拍板，2026-11-04**：契约层 = 主发行包内的子模块
  `freegraph/contracts/`，不拆独立发行包）——本 feature 交付的是**子模块**，
  不是新包；`pyproject.toml` 保持**单一发行包 `freegraph` + extras**。
  将来若重开 D1（触发信号：freechain 需单独依赖契约 / 出现非可选的重量级依赖 /
  出现第 3 个消费契约层的包），拆分成本 = 移动目录 + 加 shim 包，**零契约变更**。

### 9. 红线与质量门禁

- **依赖门禁（阻断，红线）**：freegraph 自身依赖闭包无 `langsmith` / `langchain*` /
  `langgraph*`；本层**只允许标准库**（`typing-extensions` 已剥离）。
- **零出站**：freegraph 自身不发起任何出站；**内核不读任何环境变量**
  （`LANGSMITH_*` / `LANGCHAIN_*` / `LANGGRAPH_CLOUD_LICENSE_KEY` 一律不读）。
- **ARCH-2**：契约层可独立安装、单独 import 无副作用；**且顶层包 MUST 保持惰性**
  （`freegraph/__init__.py` 只暴露元信息，`import freegraph` MUST NOT 加载任何
  子模块——**D1 决议的附加约束**，见 FR-010 / SC-006 / A5）。
- **人工门禁**：本 feature 结束须有 `harness/verification/<feature>/manual-verification.md`
  人工验证记录（环境 / 步骤 / 实际输出 / 结论 / 遗留问题）。
- **证据门禁**：新增事实性结论须带来源标记（`harness/proposals/立项书.md` 章节号 或
  `harness/reports/Q8-…md` 章节号）。
