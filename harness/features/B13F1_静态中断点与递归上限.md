## 提示词正文

### 1. 目标

交付两项**运行期安全阀**：
① **静态中断点**——允许在指定节点**之前**或**之后**人为挂起（用于调试与人工介入）；
② **`recursion_limit`**——当图陷入循环时**明确抛异常**而不是无限跑下去。
本 feature 的判定是：**递归超限抛明确异常**。

### 2. 背景与上下文

- **静态中断点**（`interrupt_before` / `interrupt_after`）与 B10F1 的**动态中断**
  （节点内调 `interrupt()`）互补：动态中断由节点自己决定何时挂起；静态中断点由
  **图的定义方**在指定节点前后挂起，用于「跑到这里停一下看看状态」。
- **`recursion_limit` 是安全阀**：LangGraph 的图可以自环（`add_edge("loop", "loop")`），
  没有上限时会一直跑到内存耗尽。freegraph MUST 提供明确上限与明确异常。
- **载体形态**：`recursion_limit` 的**载体**（放在普通 dict 的 config 里，还是放在
  `RunConfig` 里）此前是**未锁定**的形态——`harness/demo/graph_core.py` 用
  `invoke(input, {"recursion_limit": 3})` 的 **dict 形态**调用，并把该项列为**软断言**
  （「以 dict 形态传 `recursion_limit` 未触发超限——载体待 B13F1 锁定」）。
  → **本 feature 的首要任务之一就是把这个形态锁定**，锁定后该项断言升级为硬断言。
- **M1 收口**：本 feature 完成后，M1（运行时内核）全部 9 个 feature 就绪。

### 3. 用户场景

**P1 — 在指定节点前挂起**
作为用户，我能把图配成「跑到 `review` 节点之前先停一下」，从而检查到达该节点时的状态。

- **独立验收**：执行结果含 `__interrupt__`（或等价的明确挂起信号），且该节点**尚未执行**。

**P2 — 在指定节点后挂起**
作为用户，我也能在 `review` 执行完之后挂起，从而检查它的产出。

- **独立验收**：`review` 的副作用计数 == 1，且执行结果为挂起态。

**P3 — 死循环被明确拦住**
作为用户，我的图有个自环 bug，我希望它在有限步内**抛出明确异常**（而不是把机器跑挂）。

- **独立验收**：`invoke` 抛出可识别的异常，异常消息指明「递归超限」。

### 4. 功能需求

- **FR-001**：系统 MUST 支持**静态中断点**：在指定节点执行前 / 执行后挂起。
- **FR-002**：静态中断点的配置 MUST 通过**图定义侧**提供（构建器侧参数或
  `RunConfig`），并在 spec 中写死具体承载位置。
- **FR-003**：静态中断 MUST 与动态中断（`interrupt()`）**共用同一套挂起/恢复机制**
  （结果结构一致、可被 `Command(resume=...)` 恢复）。
- **FR-004**：系统 MUST 提供 `recursion_limit`（默认上限 MUST 有明确取值并写入 spec）。
- **FR-005**：超限时 MUST 抛出**明确的、可识别的异常**（复用契约层的
  `GraphRecursionError`），消息 MUST 指明超限事实。
- **FR-006**：**载体形态 MUST 锁定**：MUST 支持普通 dict 形态
  `invoke(input, {"recursion_limit": 3})`（与 `harness/demo/graph_core.py` 一致）；
  若同时支持 `RunConfig` 形态，MUST 写明二者优先级。
- **FR-007**：`recursion_limit` MUST 计数**super-step 轮次**（不是节点调用次数），
  语义 MUST 在 spec 中写死。
- **FR-008**：系统 MUST NOT import `langchain` / `langchain-core`；MUST NOT 读环境变量。

### 5. 成功标准

- **SC-001**：`interrupt_before` 用例：目标节点**未执行**，执行结果为挂起态。
- **SC-002**：`interrupt_after` 用例：目标节点**已执行**（副作用计数 == 1），执行结果
  为挂起态。
- **SC-003**：`recursion_limit=3` 的自环图在有限步内抛出 `GraphRecursionError`
  （可由异常类型判定），且异常消息含「超限」语义。
- **SC-004**：未设置 `recursion_limit` 时使用**文档化的默认值**（可由测试断言）。
- **SC-005**：`harness/demo/graph_core.py` 的 `recursion_limit` 软断言在形态锁定后
  **升级为硬断言**并通过。

### 6. 验收判据（= 立项书 §5.2 B13F1 小目标，逐条可判定）

> 小目标原文：递归超限抛明确异常

| # | 判据 | 判定方式 |
|---|---|---|
| A1 | 递归超限抛明确异常 | 自环图 + `recursion_limit=3` → 抛出 `GraphRecursionError`（或 spec 指定的等价异常） |
| A2 | 静态中断点可用 | `interrupt_before` / `interrupt_after` 两条用例 |
| A3 | 载体形态锁定 | `harness/demo/graph_core.py` 的对应软断言升级为硬断言并通过 |

### 7. 关键实体与契约

| 实体 | 语义 | 对应契约 |
|---|---|---|
| `GraphRecursionError` | 递归超限异常（B1F1 已定义于契约层） | B13F1 |
| 静态中断点配置 | 节点前/后挂起 | 与 C17 共用挂起机制 |
| `recursion_limit` | super-step 轮次上限 | 载体由本 feature 锁定（dict 形态） |

### 8. 边界（本 feature 明确不做）

- 不实现持久化中断恢复（属 B14F1 / B16F1）——本 feature 是内存态。
- 不实现 `Command.PARENT` / 子图（v2）。
- 不实现 async（v2 范围）。
- 不实现节点级重试 / 超时（不在 v1 范围）。
- 不实现 `Send`（属 B11F1）——但本 feature 依赖它已就绪（M1 顺序上本 feature 在其后）。

- **零出站 / 零环境变量**。
- **ARCH-1**：L2 只依赖 L1。
- **契约门禁**：MUST NOT 破坏 C4 / C6 / C8 / C17。
- **人工门禁**：`harness/verification/<feature>/manual-verification.md`。
- **证据门禁**：若本 feature 需要新增契约条目，MUST 走 Governance 修订流程并记录。
