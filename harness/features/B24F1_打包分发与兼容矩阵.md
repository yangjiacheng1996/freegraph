## 提示词正文

### 1. 目标

交付**发行就绪**的产物：把 freegraph 打成可发布的 Python 包，产出 **API 兼容矩阵**
与**第三方归属清单**，并把「**发行产物纯度门禁**」接进发布流水线。本 feature 的判定是：
**发行包就绪；兼容矩阵与归属清单齐备；发行产物纯度门禁通过**。

### 2. 背景与上下文

- **发布门禁（Release Gate）**是**独立于 7 项质量门禁**的一条：作用于**打包结果**
  而非源码。构建产物 MUST **仅含包代码**（`src/<pkg>/`）与**必要元数据**
  （README / LICENSE / pyproject.toml / PKG-INFO）；
  **MUST NOT** 含任何仓库内容——`harness/`（调研报告 / 提示词 / 立项书 / 验收脚本）、
  `.specify/`、`.opencode/`、`node_modules/` 等属**开发辅助材料**：
  它们留在 GitHub 上供读者学习本项目全部原理，但**不得**进入发行包
  （否则会被他人 `import` 引入）。
  → 由 `harness/scripts/check_dist_purity.py` 断言，并在发布流水线中于 `uv publish`
  **之前**强制执行（断言不通过即中止发布——PyPI 上的版本一旦发布**不可删除**，
  只能 yank）。
- **API 兼容矩阵**（宪法原则 X）：允许为互操作目的使用同类 API 名称，但 **MUST**
  维护一张「行为等价 / 部分等价 / 不支持」的兼容矩阵，并注明「兼容意图为互操作，
  **不构成 affiliation**」。→ 表体已定稿于立项书 §3.2，**由本 feature 首次落库**。
- **第三方归属清单**（原则 X）：任何引入的第三方代码 MUST 进入 `THIRD_PARTY_NOTICES`，
  保留其原始版权与许可声明。
- **extras 划分**（立项书 §3.5）：基础安装**零**第三方依赖；其余全部 extras
  （`[pydantic]` / `[checkpoint]` / `[otel]` / `[png]`）。
- **发布通道**：GitHub Actions Trusted Publishing（OIDC）——无需 API token。
  `freegraph` 与 `freechain` 均已在 PyPI 占位发布 v0.0.1。

### 2.1 背景与上下文（补充 · 2026-11-11）

- **承接条款（B9F1 → B24F1 · M4 · 兼容矩阵的定稿口径）**：B9F1 **经发起者特批**更新了兼容矩阵**既有**
  `Command` / `NodeFunc` 两行的**差异说明**（「**运行期语义已落地**」·「**命令列表**形态」）⇒
  **零新增行**、**等价程度（第三列）MUST NOT 变**（`Command` = 部分等价 · `NodeFunc` = 不支持）
  ⇒ **本 feature 的定稿 MUST 保留**这两行的更新 ⇒ **MUST NOT** 按旧措辞回退。
  该口径由 B9F1 的 `specs/b9f1-command-primitive/spec.md`（**裁定 20** · **裁定 21** · FR-016）落成。
### 3. 用户场景

**P1 — 装上就能用，且只有一个小依赖**
作为用户，`pip install freegraph` 后我得到一个**不依赖任何第三方包**的包。

- **独立验收**：隔离 venv 安装后 `pip freeze` 只有两个包。

**P2 — 发行包里没有仓库杂物**
作为用户，我 `pip install freegraph` 后**不应该**在 site-packages 里看到
`harness/`、`.specify/`、调研报告这些开发材料。

- **独立验收**：纯度断言脚本通过（构建产物内容清单核对）。

**P3 — 我能查 freegraph 与 LangGraph 的兼容程度**
作为用户，我想知道 freegraph 哪些 API 与 LangGraph **行为等价**、哪些**部分等价**、
哪些**不支持**。

- **独立验收**：`COMPAT.md` 存在且覆盖 §4.3 的 18 项 + 关键契约条目。

**P4 — 发布前有一道机械拦截**
作为项目发起者，我希望发布前有一道**机械检查**：产物里混进仓库文件就**中止发布**
（而不是发布后才发现）。

- **独立验收**：故意混入一个仓库文件 → 断言失败并中止。

### 4. 功能需求

- **FR-001**：系统 MUST 产出可安装的发行包（wheel + sdist），基础依赖仅
  **零**第三方依赖，其余能力全部 extras。
- **FR-002**：发行产物 MUST **仅含** `src/freegraph/` 包代码 + 必要元数据；
  MUST NOT 含 `harness/` / `.specify/` / `.opencode/` / `specs/` / `node_modules/`
  / 测试目录。
- **FR-003**：系统 MUST 提供**纯度断言脚本**（`harness/scripts/check_dist_purity.py`
  已存在）并把它接入发布流水线，在上传**之前**执行，失败即中止。
- **FR-004**：系统 MUST 交付 **API 兼容矩阵**（`COMPAT.md`），内容为「行为等价 /
  部分等价 / 不支持」三档，覆盖 §4.3 的 **18 项**与关键契约条目，并注明
  「兼容意图为互操作，不构成 affiliation」。
- **FR-005**：系统 MUST 交付 **`THIRD_PARTY_NOTICES`**，登记全部第三方代码/资产的
  原始版权与许可声明。
- **FR-006**：系统 MUST 交付 **README**（中文为主 + 英文并行，含「独立实现、非
  LangChain Inc. 产品」声明与三条对外承诺：零账号 / 零出站 / 零 license key）。
- **FR-007**：系统 MUST 交付「**能力 → freegraph 处置**」表（立项书 §3.2 定稿表体），
  README 中可见，并随每次范围变更更新。
- **FR-008**：系统 MUST 发布 `py.typed`；MUST NOT 使用任何 LangChain 系商标 /
  logo / 品牌色 / 官方文案（原则 IX）。
- **FR-009**：系统 MUST 保持 `requires-python = ">=3.11"` 且不设上限。

### 5. 成功标准

- **SC-001**：发行包就绪——隔离环境 `pip install` 成功、`import freegraph` 成功。
- **SC-002**：纯度断言通过——产物内容清单中**无任何仓库内容**。
- **SC-003**：负向验证——故意混入仓库文件 → 断言**失败**并中止发布流程。
- **SC-004**：`COMPAT.md` 覆盖 §4.3 的 18 项（逐项可核对）与 `THIRD_PARTY_NOTICES`
  齐备。
- **SC-005**：基础安装依赖闭包为**空集**；许可证 ∈ {MIT, Apache-2.0,
  BSD-2/3, PSF}。

### 8. 边界（本 feature 明确不做）

- 不实现 `target.py` 的双跑验收与迁移说明（属 **B25F1**）。
- 不实现 CI 发布流水线的**首次真实发布**（PyPI 占位版已发布；本 feature 只把纯度
  断言接入流水线并验证负向用例）。
- 不实现 Postgres / async / 子图 / 完整 Studio UI（v2 范围）。
- 不做 LICENSE 的 MIT → Apache-2.0 切换（**D3 待拍板**；按默认建议「倾向改」，
  但**本 feature 不擅自改**——若 D3 未拍板，保持当前 MIT）。
- 不实现免费文档站（README + 仓库文档为主）。

### 9. 红线与质量门禁

- **依赖门禁（阻断，红线）**：基础依赖**为空**；无 `langsmith` /
  `langchain*` / `langgraph*`；许可证 ∈ {MIT, Apache-2.0, BSD-2/3, PSF}；
  无 Elastic-2.0 / AGPL / SSPL。
- **零出站 / 零环境变量**。
- **第三方商标禁令**：README 与文档 MUST NOT 出现 LangChain / LangSmith 商标资产
  或官方文案；MUST 声明「独立实现、非 LangChain Inc. 产品」。
- **发布门禁**：纯度断言 MUST 在上传前执行，失败即中止。
- **人工门禁**：`harness/verification/<feature>/manual-verification.md`。
- **证据门禁**：兼容矩阵每一项 MUST 可追溯到 §4.3 的裁定或实测依据。

### 10. 交付物与后续

- **交付物**：打包配置（extras 划分）、发行产物、纯度断言接入发布流水线、
  `COMPAT.md`、`THIRD_PARTY_NOTICES`、README（中英双语）、人工验证记录。
- **后续解锁**：**B25F1**（双跑验收 + 迁移说明 + 文档收口）——**MVP 最终验收**。
- **关键路径**：本 feature 位于**关键路径**上，紧接其后是 B25F1——
  两者构成到交付终点的尾链。
- **风险提示**：纯度门禁若只在**源码配置**层做（`only-include` / `exclude`），
  会在配置被改动时静默失效——**必须是独立于配置的断言脚本**（已在仓库就位，
  本 feature 的任务是把它接进流水线并做负向验证）。
