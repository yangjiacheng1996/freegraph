## 提示词正文

### 1. 目标

把 freegraph 的**全部对外协议一次性定义齐**：4 类可插拔协议（`NodeFunc` / `Checkpointer` /
`TraceSink` / `Store`）与图结构相关的数据类（`CompiledGraph` / `Graph` / `Node` / `Edge`）。
本 feature 是「接口契约冻结」的落点——**一旦本 feature 完成，后续 30 个 feature 的跨层协作
全部依赖这里的定义**，不再逐个协商。

### 2. 背景与上下文

- 架构采用「协议 + 纯数据」纪律：**协议用 `typing.Protocol` 定义、实现用数据类；
  跨层只传纯数据；状态通道只有 `dict`；可观测走回调（不注入即零开销零外呼）**。
- 图结构数据类（`Graph` / `Node` / `Edge`）是 freegraph **唯一必须"重写而非复用"的
  LangChain 特有件**：LangGraph 的 `get_graph()` 返回的是 `langchain_core.runnables.graph.Graph`
  ——复用即把 `langchain-core` → `langsmith` 拖回依赖树，直接破红线。freegraph 必须
  自有同名类型。
- ✅ **前置决策 D11 已批准（2026-11-05）**：契约清单**已增补 C27**（本地 trace 存储与
  查询的请求 / 返回结构，见 Q8 §3.4.1）+ **C23 字段约定已修订**（span 必带
  `thread_id` / `run_id` / 节点名 / `checkpoint_id`）+ **C22 / C23 标识约定已修订**
  （`thread_id` = 会话 / `run_id` = 单次运行，两通道共享）。**契约冻结的前置条件已满足**；
  修订本体见 Q8 §3.4.1 与立项书 §5.3.1，宪法原则 VII 已随之修订（宪法定版 1.0.0）。
- ✅ **前置决策 D1 已拍板（2026-11-04）**：契约层为**主发行包内的子模块**
  （`freegraph/contracts/`），**不拆独立发行包**；代码层保持零内部依赖（ARCH-2），
  将来可低成本拆分。

### 3. 用户场景

**P1 — freechain 能只靠协议实现自己的持久化后端**
作为 freechain 开发者，我希望能拿到 `Checkpointer` 协议，从而把 freegraph 产生的
checkpoint 写入**我自己的**存储（比如 freechain 自带的数据库层），而不必等 freegraph
提供某种特定后端。

- **独立验收**：实现一个只声明协议方法的假 checkpointer，能被类型检查器接受为
  `Checkpointer` 实例。

**P2 — 上层能注入自己的可观测接收端**
作为用户，我希望能传入一个实现了 `TraceSink` 协议的对象来接收 span，从而把 freegraph
的运行轨迹接到我已有的日志系统，而不需要 freegraph 引入任何 SDK。

- **独立验收**：实现一个假 sink 收集 `on_span_start` / `on_span_end` 调用，类型检查通过。

**P3 — 图结构可以被外部读取与绘制**
作为用户，我希望能拿到一个**自有类型**的图结构对象（节点 + 边），以便我自己渲染图、
生成文档配图或做结构断言，而不需要 freegraph 依赖 `langchain-core`。

- **独立验收**：图结构对象暴露 `nodes` / `edges` 两个集合，元素是本层定义的纯数据类。

### 4. 功能需求

- **FR-001**：系统 MUST 以 `typing.Protocol` 定义 `NodeFunc` 协议 —— 节点函数契约：
  `Callable[[StateDict], StateDict | Command | None]`。
- **FR-002**：系统 MUST 以 `typing.Protocol` 定义 `Checkpointer` 协议，方法集合为
  `get_tuple` / `list` / `put` / `put_writes` / `delete_thread` / `get_next_version`。
- **FR-003**：系统 MUST 以 `typing.Protocol` 定义 `TraceSink` 协议，方法集合为
  `on_span_start` / `on_span_end` / `current_span`。
- **FR-004**：系统 MUST 以 `typing.Protocol` 定义 `Store` 协议，方法集合为 `get` /
  `search` / `put` / `delete` / `list_namespaces` / `batch`（按 `(namespace, key)` 寻址）。
  > **注意**：C20 契约**仍冻结**（它是 freechain 的设计输入），但 **v1 不实现 `Store`**
  > （B17 已砍，2026-11-05——`Store` 是跨会话 / 跨图能力，与「图 = 一个进程」的定位不符）。
  > 本 feature 只**定义协议**（类型层面），**不提供任何实现**。
- **FR-005**：系统 MUST 定义 `CompiledGraph` 协议 —— 编译产物的对外能力面：
  `invoke` / `stream` / `get_graph` / `get_state` / `get_state_history` / `update_state`。
- **FR-006**：系统 MUST 定义 `Graph` / `Node` / `Edge` 三个**纯数据类**，承载图结构
  （节点名、节点别名、边起点、边终点、边类型/条件信息）。MUST NOT 复用
  `langchain_core` 的图结构类型。
- **FR-007**：全部协议 MUST 支持运行时结构化子类型检查（`runtime_checkable`），
  以便用户无需显式继承即可满足协议。
- **FR-008**：契约层 MUST NOT import 任何 freegraph 内部模块；MUST NOT import
  `langchain` / `langchain-core`。
- **FR-009**：系统 MUST 在本层落 **C27**（本地 trace 存储与查询）的契约条目——请求 /
  返回结构、**JSON 可序列化**、存储与查询同一协议且后端可替换、表结构 / 文件格式属
  内部实现细节（Q8 §3.4.1，已由 D11 冻结）。
- **FR-010**：系统 MUST 把 **C22 / C23 的字段约定**落进契约层的类型定义：`thread_id`
  （会话，由 `RunConfig` 承载）与 `run_id`（单次运行，由运行时生成，**不进** `RunConfig`
  的字段清单）的职责划分；span 必带 `thread_id` / `run_id` / 节点名 / `checkpoint_id`。

### 5. 成功标准

- **SC-001**：4 类协议 + `CompiledGraph` 协议 + 3 个图数据类全部就位，
  `import freegraph.contracts` 后可一次性取到。
- **SC-002**：契约层可被**单独消费**——单独 import 无副作用，依赖闭包仅
  **零**第三方依赖（ARCH-2 通过）。
- **SC-003**：CI 的 AST 扫描断言契约层零内部依赖、零 `langchain*` import（ARCH-2/ARCH-3）。
- **SC-004**：一个「零内部依赖」的自测 fixture 能同时实现 `Checkpointer` / `TraceSink` /
  `Store` 三个协议并通过静态类型检查（证明协议确实可被外部实现）。
- **SC-005**：D11 的三项修订结论（C27 增补 / C23 字段约定 / C22·C23 标识约定）在本
  feature 结束时**全部落地**（契约层可查到 C27 条目与两项字段约定的类型定义）。

### 7. 关键实体与契约

| 实体 | 语义 | 替代对象 | 对应契约 |
|---|---|---|---|
| `NodeFunc`（协议） | 节点函数：`f(state) -> StateDict \| Command \| None` | 通用 | C5 / C6 |
| `Checkpointer`（协议） | 快照 + 历史持久化 | 半通用 | C19 |
| `TraceSink`（协议） | span 推送接收端 | 替代 callbacks | C23 / C24 |
| `Store`（协议） | `(namespace, key)` 长期记忆 | 半通用 | C20 |
| `CompiledGraph`（协议） | 编译产物对外能力面 | 特有 | C10 / C11 / C12 / C13 |
| `Graph` / `Node` / `Edge`（数据类） | 图结构（**必须自有重写**） | 特有 | C13 / C14 / C15 / C25 |

> **口径提醒**：`Command` / `Send` / `interrupt` 三个原语的**类型**在 B1F1 已冻结；
> 本 feature 只定义「协议面」——`NodeFunc` 的返回值可以是 `Command`，`Store` 按
> `(namespace, key)` 寻址。
>
> > **命名裁定更新（2026-11-06 · spec 澄清 Q1）**：节点函数协议名由 `Node` **改为
> > `NodeFunc`**——`Node` 一词此后**唯一**指**图结构节点元素**（`Graph` / `Node` / `Edge`
> > 三个数据类），两者不再同名。本文件已按该裁定同步；`spec.md` / `plan.md` / `tasks.md`
> > 为该裁定的**规范来源**。

### 8. 边界（本 feature 明确不做）

- 不实现任何协议的方法体——只有类型，没有行为。行为分别落在
  B14F1（`MemorySaver`）、B19F1（`TraceSink` 接入）；**`Store` 无 v1 实现**（B17 已砍）。
- 不定义 `freegraph/graph.py` 公开门面 —— 属 **B2F2**。
- 不实现子图（C26）——v1 只保 `get_graph(xray=)` 签名兼容，实现属 v2。
- 不定义 `StreamMode` 的具体 mode 枚举全集（C12 的 mode 命名在 B8F2 落地）。
- 不引入 `pydantic` 等可选依赖；协议一律用标准 `typing.Protocol`。

### 9. 红线与质量门禁

- **依赖门禁（阻断，红线）**：本层零 `langsmith` / `langchain*` / `langgraph*`；
  只允许**标准库**（`typing-extensions` 已剥离）。
- **零出站 / 零环境变量**：本层不读任何环境变量、不发起网络请求。
- **ARCH-3**：跨层只经由 `Protocol` + 纯数据类（CI 静态检查）。
- **人工门禁**：人工验证记录落 `harness/verification/<feature>/manual-verification.md`。
- **证据门禁**：协议语义与 LangGraph 行为的对应关系须附来源（Q8 条号 / `langgraph`
  源码路径:行号）。
