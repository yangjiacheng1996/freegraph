## 提示词正文

### 1. 目标

实现 freegraph 的**调度内核**：super-step 循环——每轮「判定哪些节点被触发 → 准备任务
→ 执行任务 → 收集写入 → 按通道语义合并写入 → 进入下一轮」。本 feature 交付的是
**不依赖图构建器**的运行时内核：调度循环 MUST 能用手写的图规格直接驱动与验收。

### 2. 背景与上下文

- **为什么运行时层先行**：LangGraph 的图定义层 import 运行时层
  （`langgraph/graph/state.py:73-75` → `from langgraph.pregel import Pregel`），
  而运行时层**不** import 图定义层——运行时是独立性最高的一层。先做运行时可获得三个
  收益：① 调度循环可脱离 `compile()` 独立验收；② C4 稀疏状态、C8 fresh 读、super-step
  并发写等**静默破坏**型语义在早期暴露；③ 图定义层退化为薄适配器。
- **super-step 模型**：LangGraph 采用 Pregel 的 Plan → Execution → Update 三段
  （`langgraph/pregel/_algo.py` 1460 行 / `_loop.py` 1988 行）。freegraph **重写而非
  复制**，只实现 v1 必需子集（去掉 async / retry / cache / 远程图 / 子图）。
- **本 feature 是关键路径上最高风险的 feature**（立项书 §7.5 建议预留 +1 天）：
  1,480 行是全项目最大的 feature，涉及「版本号语义 + 触发判定 + 写入合并」三者的交互。
- **并发写**语义：同一 super-step 内多个节点写同一通道时，**必须按归约器语义合并**，
  而不是后写覆盖先写——这是「静默破坏」的典型来源。
- **承接条款（B5F2 → B7F1 · M1）**：B5F2 已交付稀疏状态读取与 **C4 独立回归测试**
  （断言对象 = 读取原语产出的那个 dict · 用例住在 `tests/runtime/` 下 · 挂载点
  `tests/contracts/test_contract_regressions.py` 的 `GATE-MOUNT: C4` 已翻成 `landed`）。
  **本 feature MUST 把该 C4 用例从「读取层口径」推进到「真实节点入参口径」** —— C4 的契约边界是
  **节点入参**，只在读取层断言等于把这条防线守在半个位置。
  ⚠️ **2026-11-11 追补订正**：本条逐字原为「**改为**断言真实节点收到的入参」⇒ 与 B5F2 的
  **「读取层口径并存」**相左（B5F2 **裁定 18** · Q16）⇒ **B7F1 的 spec 裁定 13** 定为
  「**并存 + 追加**」（**MUST NOT** 删除原有的读取层口径断言）⇒ 本条以 **spec 裁定 13** 为准。
  该承接条款由 B5F2 的 `specs/b5f2-sparse-state-read/spec.md`（FR-031 / 裁定 18）落成。
- **承接条款（B5F1 → B7F1 · M1 · 通道层口径交接）**：B5F1 已冻结通道层的**四个操作**
  与**四个只读属性**，其中三条口径由 **B7F1** 承接：
  ① **步末清空范围**：super-step 步末 MUST **只**对**路由型**通道调用 `clear()`
     （覆盖型 / 归约型 MUST **保留**其值 —— 否则「末值保留」与「累积保留」被抹掉
     ⇒ 与上游分叉）—— 落点：`specs/b5f1-channels/contracts/channel-contract.md` **B-2** ·
     `contracts/upstream-parity.md` **S-05** / **P-12**；
     ⚠️ **2026-11-11 追补订正**：本条以 **spec FR-014** 为准 ⇒ 步末**只清「本轮未被写入的」路由型**
     （本轮写过的路由型 MUST 保留其值到下一轮）⇒ 措辞**不得弱于** FR-014；
  ② **写入只有一条路径 + `update()` 的返回值口径**：通道的写入 MUST **只**由调度层发起
     （用户代码 MUST NOT 直接写通道对象）；`update()` 的返回值 MUST 表示
     「**本次调用是否写入了值**」（非空 ⇒ 恒真，哪怕归约后的新值与旧值**逐字相等**）
     ⇒ 触发判定 MUST 依据**写入版本**，MUST NOT 依据「值是否变化」
     —— 落点：`specs/b5f1-channels/spec.md` FR-023 ① +「澄清轮 Q5」；
  ③ **`build_channels()` 的返回类型 = 可变 `dict`**：调度层 MUST 能在通道映射之上
     **增补内部通道**（如路由型通道）⇒ 通道映射 MUST 为**可变**映射
     —— 落点：`specs/b5f1-channels/research.md` **D-14**。
- **承接条款（B5F2 → B7F1 · M1 · 稀疏读唯一实现）**：B5F2 已冻结**两个稀疏入口**
  （`read_channels` / `local_read`）**逐字相等**的契约 ⇒ 节点入参 MUST 由**同一处**
  稀疏语义产出（调度层 MUST NOT 另写一份过滤）—— 落点：
  `specs/b5f2-sparse-state-read/spec.md` FR-038 / SC-033 ·
  `contracts/read-contract.md` §4 **I-11**。
  > ⚠️ **口径备注（2026-11-11 追补）**：上面两条（B5F1 / B5F2 的口径交接）在上游原文中
  > **只指名了 feature ID、未指名里程碑** ⇒ 严格按宪法 **v1.8.0** 的**窄口径**触发条件

### 3. 用户场景

**P1 — 一个 super-step 能跑通**
作为实现者，我希望在还没有构建器的时候，能用手写的节点规格 + 边规格直接驱动一轮
super-step，从而**独立验收**调度内核。

- **独立验收**：给定手写图规格，执行一轮后状态按通道语义正确合并。

**P2 — 状态写入按归约器合并，不被后写覆盖**
作为用户，两个节点在同一轮里都给 `messages` 写消息时，我希望结果是**拼接**而不是
「只保留后一个」。

- **独立验收**：同轮双写归约通道 → 读取结果包含两条消息。

**P3 — 未被触发的节点不执行**
作为用户，一个节点的入参 channel 没有新值时，我希望它**不被调度**，从而避免空转。

- **独立验收**：一轮中只有触发条件满足的节点被执行（执行计数断言）。

### 4. 功能需求

- **FR-001**：系统 MUST 提供 super-step 循环：一个 super-step = 触发判定 → 任务准备 →
  任务执行 → 写入收集 → 写入合并。
- **FR-002**：系统 MUST 提供**触发判定**：节点在其订阅的 channel 出现新值时被触发；
  触发判定 MUST 依据**版本号**（每 channel 维护写入版本），MUST NOT 依据「值是否变化」
  （值相同但版本更新的写入仍应触发）。
- **FR-003**：系统 MUST 维护 `versions_seen` 之类的「已消费版本」记录，确保同一版本
  不会重复触发同一节点。
- **FR-004**：系统 MUST 实现**写入合并**：按通道类型执行覆盖或归约；同轮多写同通道时
  MUST 走归约路径。
- **FR-005**：系统 MUST 支持「任务写入」的隔离：任务产生的是**待写入（pending writes）**，
  在本轮结束时统一合并——MUST NOT 在任务执行期间直接改写通道正式值（C8 fresh 读的
  基础）。
- **FR-006**：系统 MUST 支持「无待执行任务即终止」的收敛判定。
- **FR-007**：系统 MUST 能被**手写图规格**驱动（MUST NOT 依赖 `StateGraph` /
  `compile()`），以便本 feature 独立验收。
- **FR-008**：系统 MUST NOT import `langchain` / `langchain-core`；MUST NOT 读环境变量；
  MUST NOT 产生任何 I/O。

### 5. 成功标准

- **SC-001**：单 super-step 可执行；执行后状态**按归约器合并**（SC-001 可判定）。
- **SC-002**：同轮双写归约通道的结果 == 两次写入的归约结果（与 `operator.add` 逐元素相等）。
- **SC-003**：未被触发的节点执行次数为 0；已触发的节点执行次数为 1（每轮内）。
- **SC-004**：手写图规格可驱动调度循环，**无需构建器**（本 feature 的独立可验收性判据）。
- **SC-005**：调度循环终止判定可判定：空任务集 → 立即收敛，**无死循环**。

### 6. 验收判据（= 立项书 §5.2 B7F1 小目标，逐条可判定）

> 小目标原文：单 super-step 可执行；状态按归约器合并；**可脱离构建器、用手写图规格
> 直接验收**

| # | 判据 | 判定方式 |
|---|---|---|
| A1 | 单 super-step 可执行 | 手写图规格跑一轮，状态变更符合预期 |
| A2 | 状态按归约器合并 | 同轮双写用例断言 == 归约结果 |
| A3 | **可脱离构建器、用手写图规格直接验收** | 测试中**不出现** `StateGraph` / `compile()`，仅用手写规格 |

### 7. 关键实体与契约

| 实体 | 语义 | 对应契约 |
|---|---|---|
| super-step | 一轮「Plan → Execution → Update」 | C5 / C6 |
| 触发判定 + 版本号 | 决定哪些节点本轮被调度 | C6 |
| 待写入（pending writes） | 任务产出、轮末统一合并 | C6 / C8 |
| 节点任务 | 「订阅哪些 channel → 读 → 写」的规格 | C5 |

> **口径提醒**：C6（节点返回值合并：逐 key 应用 reducer；**未知 key 报错**）中的
> 「未知 key 报错」依赖 `InvalidUpdateError`（B1F1 已在契约层定义）——本 feature 可先
> 抛出该异常，B7F3 负责对外暴露 `invoke` 的完整状态语义。

### 8. 边界（本 feature 明确不做）

- 不做 `invoke()` / `stream()` 的对外 API（属 B7F3 / B8F2）。
- 不做 `compile()`（属 B7F2）——本 feature 的图规格是手写的。
- 不做并发节点执行（属 B12F1）——本 feature 先单任务执行语义正确。
- 不做 `Command` 跳转（属 B9F1）、`interrupt`（属 B10F1）、`Send`（属 B11F1）。
- 不做 checkpoint 写入（属 B14F1）。
- 不做 async（v2 范围，未排 feature）。

### 9. 红线与质量门禁

- **依赖门禁（阻断，红线）**：无 `langsmith` / `langchain*` / `langgraph*`。
- **零出站 / 零环境变量**。
- **ARCH-1**：L2 只依赖 L1；MUST NOT import L3 图定义层。
- **契约门禁**：C4 回归测试常驻；本 feature 不得破坏 B5F2 建立的稀疏语义；
  **并 MUST 把该 C4 用例从「读取层口径」推进到「真实节点入参口径」**
  （B5F2 的承接条款 · 见 §2「承接条款（B5F2 → B7F1）」）。
- **人工门禁**：`harness/verification/<feature>/manual-verification.md`。
- **证据门禁**：与 LangGraph 的语义对应须标注源码行号（`_algo.py` / `_loop.py`）。

### 10. 交付物与后续

- **交付物**：super-step 调度循环、触发判定与版本号机制、写入合并、单元测试 +
  人工验证记录、**C4 回归测试推进到真实节点入参**（B5F2 承接条款 · 见 §2）。
- **后续解锁**：**B9F1**（`Command`）→ **B12F1**（并发与错误传播）→ **B7F3**
  （`invoke` 对外 API）。
- **风险提示**：本 feature 是全项目**最高风险的单个 feature**（立项书 §7.5 建议预留 +1 天）。
  建议 spec 阶段就把「同轮多写」「版本号推进」「空任务收敛」三条列为**独立验收场景**，
  不要合并成一个大用例——失败时才能定位到具体语义。
