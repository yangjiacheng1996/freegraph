## 提示词正文

### 1. 目标

完成 **v1.0 的最终验收**：让固定脚本 `harness/demo/target.py` **原样**跑通两轮——
① **fake 模型**（CI 可自动化）与 ② **真实模型**（人工验收）——并产出《人工验收记录》、
**迁移说明**与最终 **README**。本 feature 的判定是：**双跑通过；框架零出站断言通过**。

### 2. 背景与上下文

- **MVP 验收基线**：`harness/demo/target.py` 是**只读基准**——第 7–10 行硬编码
  `init_chat_model("claude-sonnet-4-6", temperature=0)`、第 50 行 `model.bind_tools(tools)`。
  **要跑 fake 且不改脚本，只能靠外部机制替换**：
  - 在 `tests/conftest.py`（或 `sitecustomize.py`）中**猴补**
    `langchain.chat_models.init_chat_model`，返回实现 `invoke()` 的 `FakeModel`；
  - 备选：import 后替换 `target.model` / `target.model_with_tools`。
  - **MUST NOT 修改 `target.py`**（由门禁 3 的「固定脚本只读基准 diff 断言」覆盖）。
- **fake 的能力要求**：fake **必须能产生 `tool_calls`**——否则验收基线退化为
  「单轮无工具」，测不到工具循环、C4（`state.get('llm_calls', 0)`）、C8（条件边
  fresh 读）这三条最易静默破坏的语义。
- **固定输出序列**：① 第 1 轮返回带 `tool_calls=[{name:'add', args:{'a':3,'b':4},
  id:'call_1'}]` 的消息；② 第 2 轮返回最终文本答案（与脚本的「Add 3 and 4.」对齐）。
- **断言点**：`messages` 长度 == 3（System + AIMessage(tool_call) + ToolMessage）、
  `llm_calls == 2`、工具结果 == **7**、`invoke()` 返回完整状态（含 `messages` 与
  `llm_calls` 两个键）。
- **框架零出站的验证方法**（只观测、不阻断）：socket 夹具只包装
  `socket.connect` / `socket.create_connection` 以**记录**目标与调用栈，**放行**所有
  连接；调用栈含 `freegraph/` 包路径 → 判「框架出站」，否则判「用户出站」；
  **只对前者断言 = 0**。人工轮允许出现「**模型厂商端点**」一条（属用户出站），
  断言「除该条外为空」。
- **验收脚本集四组全绿**（`harness/demo/`）：`acceptance.py`（编排器）→
  `graph_core.py` → `agent_loop.py` → `visualization.py`。
- **M3 的可诊断性脚本**：其依赖的四个 API 形态（`compile(tracer=)` 的载体、本地
  trace 目录参数名、`MemorySaver` 的模块路径、`update_state(...)` 的签名）已随
  M3 各 feature 锁定 → **本 feature 补齐 `diagnostics.py`**（按 `harness/demo/README.md`
  的约定：验收脚本与它所验收能力的 API 形态同时确定）。
- **承接条款（B5F2 → B25F1 · M4）**：B5F2 已交付**差分测试夹具**并**预留**「模型工厂」钩子
  （B5F2 交付时该钩子恒空 ⇒ 非空即**显式失败**；B5F2 的图规格恒为**纯本地**节点）⇒
  **本 feature MUST 提供 fake 模型工厂**并让差分夹具能跑**模型形状**的图规格 ⇒
  该口径由 B5F2 的 `specs/b5f2-sparse-state-read/spec.md`（FR-036 / 裁定 26）落成。
- **承接条款（门禁 3 / 5 的固定脚本 · B7F1 → B25F1 · M4）**：宪法质量门禁 3 的
  「`harness/demo/target.py` **原样可跑**」与门禁 5 的「**真实模型一轮**」在
  **B6F1 / B7F2 / B7F3 / B8F1 / B22F1 / B23F1** 齐备前**物理不可达成**（根因：
  **本 feature 按里程碑不交付内核运行时**）⇒ **本 feature MUST** 承接其中的
  **双跑验收**（freegraph 与 LangGraph 同跑并比对），**MUST NOT** 改动固定脚本的
  **任何一行**（`target.py` 是**只读基准**）⇒ 承接机制 = **B3F1 的裁定 22** 已把该
  承接条款写入各目标 feature 的提示词初稿。

### 3. 用户场景

**P1 — CI 自动跑通验收基线**
作为项目发起者，我希望每次提交 CI 都自动跑一遍固定脚本（用 fake 模型），
从而**回归不退化**。

- **独立验收**：CI 任务全绿；断言点（`llm_calls == 2`、工具结果 == 7、
  `messages` 长度 == 3）全部成立。

**P2 — 人工用真实模型跑一遍**
作为项目发起者，我希望在**真实模型**上再跑一遍，确认端到端真实行为（不只是 fake）。

- **独立验收**：人工验收记录含真实模型一轮的实际输出与结论。

**P3 — 能证明 freegraph 自己没有偷偷联网**
作为用户，我希望能拿到「框架出站 = 0」的可判定证据。

- **独立验收**：监测记录中「框架出站」条目数为 0；人工轮的「模型厂商端点」条目
  **写明**在记录中。

**P4 — 从 LangGraph 迁过来的人知道要改什么**
作为 LangGraph 用户，我需要一份迁移说明（哪些 API 同名、哪些要改、差异在哪）。

- **独立验收**：`harness/proposals/更名与迁移说明.md` + v1 迁移说明章节齐备。

### 4. 功能需求

- **FR-001**：系统 MUST 提供 **fake 模型注入**（猴补 `init_chat_model`），
  **MUST NOT** 修改 `harness/demo/target.py`。
- **FR-002**：fake MUST 能产生 `tool_calls`，并按固定输出序列返回（2 轮）。
- **FR-003**：CI MUST 断言固定断言点：`messages` 长度 == 3、`llm_calls == 2`、
  工具结果 == 7、返回状态含 `messages` 与 `llm_calls` 两个键。
- **FR-004**：系统 MUST 提供**零出站监测夹具**（只观测不阻断 + 按发起方归因），
  并断言「框架出站 = 0」；用户出站**记录在案但不判失败**。
- **FR-005**：系统 MUST 提供**断网等价性**验证轮（全部网络接口不可用时核心用例全绿）。
- **FR-006**：系统 MUST 补齐 **`harness/demo/diagnostics.py`**（trace / checkpoint /
  时间旅行的可诊断性验收脚本），并纳入 `acceptance.py` 编排。
- **FR-007**：验收脚本集四组 + diagnostics **必须全绿**；退出码约定
  **0 = PASS / 1 = 断言失败 / 2 = 环境未就绪**（两者必须分开）。
- **FR-008**：系统 MUST 产出《人工验收记录》：验证环境（OS / Python / 依赖 /
  环境变量清理方式）、验证步骤、实际输出、结论、遗留问题；
  并附 ① 依赖断言轮输出 ②「框架出站 = 0」监测记录 ③ 反向断言结果。
- **FR-009**：系统 MUST 交付**迁移说明**（从 LangGraph 迁到 freegraph 的差异清单）。
- **FR-010**：系统 MUST 交付最终 **README**（快速上手 + 三条对外承诺 + 能力处置表 +
  独立实现声明）。

### 5. 成功标准

- **SC-001**：**双跑通过**——fake 轮（CI）与真实模型轮（人工）均通过固定脚本。
- **SC-002**：零出站断言通过——「框架出站」计数 == 0。
- **SC-003**：四组验收脚本 + diagnostics 全绿（退出码 0）。
- **SC-004**：《人工验收记录》五要素齐备（环境 / 步骤 / 实际输出 / 结论 / 遗留问题）+
  三项附件齐备（依赖断言输出 / 出站监测 / 反向断言）。
- **SC-005**：迁移说明与 README 齐备，且 `target.py` 的 **diff 为空**（CI 断言）。

### 8. 边界（本 feature 明确不做）

- 不修改 `harness/demo/target.py`（**只读基准**）。
- 不实现真实模型之外的 provider 矩阵（属 freechain）。
- 不实现异步调用（v2 范围）。
- 不实现前端 UI（v2 / B26）。
- 不实现评测 / 数据集（永不做）。
- 不实现 Postgres / 子图 / 完整 Studio（v2 范围）。
- 不做「先把真实模型轮跑通再补 CI」——**两轮都要过**是硬要求。

### 9. 红线与质量门禁

- **依赖门禁（阻断，红线）**：freegraph 自身依赖闭包无 `langsmith` /
  `langchain*` / `langgraph*`；**反向断言**——freegraph 运行期从不 import
  `langchain` / `langchain_core`（CI 静态扫描 + 运行时 `sys.modules` 检查）。
- **零出站**：三轮验收（⓪ 依赖断言轮 / ① CI 轮 / ② 人工轮）均须在
  **清空全部 `LANGSMITH_*`** 的干净环境下进行。
- **契约门禁第 3 项**：`target.py` 的 diff 断言 + C4 / C8 回归测试常驻。
- **人工门禁**：原则 V——人工验证记录完整（含真实模型一轮）方可就特性宣布完成。
- **证据门禁**：验收记录中的事实须带来源；遗留问题须逐条列出。
- **发布门禁**：本 feature 的产物要进发行包时，仍受纯度门禁约束。
